# 銘柄

The 銘柄 tab picks one issuer and shows a common header (name, price, 時価総額, 次回決算) over five folder tabs: 概要 (指標 + the 決算速報 決算表), 株価 (candles, see `chart.md`), 業績詳細 (財務3表, `static/js/stock-financials.js`), ニュース (決算短信 list → the original text in sandboxed iframes with 幅に合わせる / 中 / 原寸 zoom), and 株主 (大量保有 + 自己株). A 決算説明資料 row in ニュース opens the reconstructed pages (KAB-350) with ニュース still selected. Spec: `docs/screen/stock.md` (KAB-178 #996, KAB-181 #1001, KAB-179 #1002, KAB-267, KAB-350 #1308, KAB-351, KAB-352, KAB-427). Code: `static/js/stock.js`, `static/js/stock-price.js`, `static/js/stock-financials.js`, `static/js/stock-deck.js`, `static/js/holders.js`, `app/api/stock.py`, `app/api/stock_decks.py`.

## Sub-features

- `stock-tab` shows `#tab-stock`. There is no `#app-nav button[data-tab="stock"]` (KAB-365); `#cur-tab` reads 銘柄 and no menu button is `.active`. With no code it sends no request; `#st-head` is `hidden`, every `.st-sub` is hidden, `#st-msg` reads 右上の「銘柄検索」から銘柄を選んでください。, hash `#stock`.
- `stock-search` is the header button `#sym-btn` (KAB-365): it opens `#sym-pop` below the header and focuses `#sym-q` (placeholder `銘柄名 or コード`), which fills `#sym-suggest` from `GET /api/stocks/search?q=` (`4桁コード 銘柄名`). Enter takes the first hit, a click takes that row; Esc, the button again, an outside click or opening the ☰ menu closes it. Picking closes it and opens the 銘柄 screen: on the 銘柄 screen it keeps the current sub tab (from a news detail or an open deck it goes to the news list), from other screens it opens 概要.
- `stock-head` loads `GET /api/stock/{code}/overview` once per code (`showStock`). `#st-title` reads `{name} {code4} / {market} / {sector33}`; `#st-quote` reads `{close} {±change} ({±pct}%) MM/DD 終値 時価総額 N億円` plus `次回決算 MM/DD` (or `未定` when `next_earnings.date` is null; nothing when `next_earnings` is null). No quote → 「株価データなし」. Then `#st-head` is shown and `#st-tabs.nav-tabs .ftab[data-sub]` gets `.on` on the current sub (folder tab: top+side border, not the filled `.fin-tabs` look).
- `stock-summary` (概要, default) fills `#st-metrics`: PER（予想） `x.x倍` / PBR（実績） `x.xx倍` / 配当利回り（予想） `x.xx%` / ROE（実績） `x.x%` / 自己資本比率 `x.x%`, `–` when the metric is null. Below, `#st-fin-tabs .ftab[data-stfin="cum"|"q"|"prog"|"rev"]` (累計 / 3か月 / 進捗率 / 修正履歴) switch `[data-stfin-wrap]` → `#st-cum-tbl` / `#st-q-tbl` / `#st-prog-tbl` / `#st-rev-tbl`, drawn by earnings.js `renderFin` / `renderProg` / `renderRev` from one `GET /api/earnings/detail/{code}` (no `disclosure_no`, latest filing). A 404 is treated as success with empty rows: 累計 / 3か月 / 進捗率 read `データなし`, 修正履歴 reads `修正履歴なし`. Any other error reads 読み込めませんでした。 in each table.
- `stock-financials` (業績詳細) is `#st-sub-financials` on `#st-tabs .ftab[data-sub="financials"]` (route `#stock/{code}/financials`). `#st-fs-tabs` 貸借対照表 / 損益計算書 / CF計算書 (`data-fs` BS / PL / CF) and `#st-fs-periods` 8期 / 20期. Each new pair calls `GET /api/stock/{code}/financials?statement=…&periods=…&consolidated=auto` once and caches it. The newest accounting-standard block is `#st-fs-tbl` (`table.sheet.fin.fs`). Older standards (API `earlier`, newest first) append into `#st-fs-earlier` as `p.sub.fs-earlier` (`{基準}の期 / {oldest label}〜{newest label} / {basis}`) plus another `table.sheet.fin.fs`. Japan GAAP and US GAAP stay in one table; a fourth header (`.fs-src.fs-std`) appears only when that one table has more than one `accounting_standard`. Empty `periods` / `rows` → `#st-fs-tbl` 「データなし」 (`empty.reason=no_material` on golden; `title` is `empty.message`); `#st-fs-legend` is hidden, `#st-fs-meta` is empty, `#st-fs-earlier` has no children (`earlier: []`). A populated `#st-fs-earlier` is `verified-unreachable` on golden 72030. Clicking 株価 from here writes `?from=stock-financials`.
- `stock-price` (株価) is `features/chart.md`.
- `stock-news` (ニュース) loads `GET /api/stock/{code}/filings` and `GET /api/stock/{code}/decks` once per code into `table#st-news` (日時 `YY/MM/DD HH:MM` / 種類 / 題名), mixed by `submitted_at` / deck `pubdate` (seconds dropped; date-only when there is no time). 種類 is `決算` for annual / semiannual / quarterly and for every deck, else `修正`, plus `訂正` when `is_amendment`. PDF titles end with `（PDF から変換）`. Deck titles are the deck `title`. Rows with documents are `tr.go[data-id]` (`x{id}` XBRL, `p{disclosure_no}` PDF). Deck rows are `tr.go[data-id="d{key}"][data-open="deck"][data-deck="{key}"]` (`key` is the decks API key, `d` + 20 hex). No filings and no decks → `#st-msg` 「ニュースがありません。」. docs/screen/stock.md's `/news` and `#st-news-kinds` are KAB-180 and not in the code.
- `stock-detail` clicks a 短信 `tr.go` → `history.pushState` to `#stock/{code}/news/{id}`, `#st-news-list` hidden, `#st-news-detail` shown: `#st-back` 「← ニュース」, `#st-zoom`, `#st-news-head` (`日時 種類 [訂正] 題名`), `#st-src`, `#st-doc`. An id that matches `NEWS_ID_RE` but is missing from the list → 「書類が見つかりません。」. An id that fails the regex (`NOPE`) is stripped and the list is shown. A deck row does not open this detail: it pushes `#stock/{code}/decks/{key}` and shows `#st-deck-detail` (`#st-deck-back` 「← ニュース」 returns to `#stock/{code}/news`). The ニュース tab stays `.on`. There is no 説明資料 tab and no deck list. Bare `#stock/{code}/decks` opens the news list.
- `stock-doc` puts one `iframe` per document into `#st-doc`, each in `.st-page` (`sandbox="allow-same-origin"`, `scrolling="no"`, title サマリー / 添付資料 / PDF から変換). `src` is the document `url` (`/api/stock/filings/{id}/documents/{seq}` or `/api/stock/pdf/{disclosure_no}`). The iframe grows to its content height. A PDF filing shows `#st-src` 「出典: {attribution}。PDF から変換した原文（画像は出ません）」.
- `stock-zoom` switches `#st-zoom .ftab[data-zoom="fit"|"mid"|"actual"]` (幅に合わせる default / 中 / 原寸) and stores it in `localStorage` `stock.zoom`. `fitStockFrame` scales an iframe wider than `#st-doc` with `transform: scale()` (fit = width, mid = max(fit, 0.75), actual = 1) and sizes `.st-page` to the scaled box. When the document fits (PC), all three look the same.
- `stock-holders` (株主) loads `GET /api/stock/{code}/holders` into `#st-holders-large` / `#st-holders-chart` / `#st-holders-treasury`. Filer names with `filer_edinet_code` call `gotoHolder` → `#holders/{edinet}`. Empty large holders → 「大量保有報告はありません。」. No buyback → 「自己株券買付状況報告書はありません。」.
- `stock-deck` (決算説明資料の中身, KAB-350) is not a folder tab and has no list. A ニュース row `pushState`s `#stock/{code}/decks/{key}?from=stock-news` and `GET /api/stock/{code}/decks/{key}` into `#st-deck-detail`: `#st-deck-back` 「← ニュース」 returns to the news list, then `#st-deck-body` (title, date, `原本の PDF` when `document.url` is set, reconstruction note, per-page title / summary / SVG charts / table). The ニュース tab stays `.on`. A 404 JSON `説明資料がありません。` becomes 「説明資料が見つかりません。」. A metric whose name contains `為替` is a non-zero-based line (KAB-351; dashed forecast segments, caption `破線・白抜きは予想・計画`). Golden has `briefing_documents=0`, so the row and the FX line are `verified-unreachable`.
- `stock-empty` `#st-msg`: 「銘柄が見つかりません。」 (overview 404; `#st-head` stays hidden), 「読み込めませんでした。」, 「ニュースがありません。」.
- `stock-route` writes `#stock/{code}/{sub}`, `#stock/{code}/news/{id}`, or `#stock/{code}/decks/{key}` (`ui.route`) via `stockRoutePath()`. Reload restores issuer, sub tab, news detail, and an open deck (ニュース stays `.on`). `#stock/{code}` opens 概要; an unknown sub falls back to `summary`. Bare `#stock/{code}/decks` and a key that fails `DECK_KEY_RE` (`^d[0-9a-f]{20}$`, e.g. `NOPE`) open ニュース. `#st-back` and `#st-deck-back` replace the hash; browser back pops the detail.

## How to get to it (user POV)

- Tap `#sym-btn`, type a name or code into `#sym-q`, then Enter or click a `#sym-suggest` row.
- Click 概要 / 株価 / 業績詳細 / ニュース / 株主 in `#st-tabs.nav-tabs`, and 累計 / 3か月 / 進捗率 / 修正履歴 in `#st-fin-tabs` (still `.fin-tabs`). 業績詳細 (`#stock/{code5}/financials`) has `#st-fs-tabs` (貸借対照表 / 損益計算書 / CF計算書) and `#st-fs-periods` (8期 / 20期), both `.fin-tabs`; each new combination calls `GET /api/stock/{code}/financials?statement=…&periods=…&consolidated=auto` once. Golden empty is `#st-fs-tbl` 「データなし」 (`empty.reason=no_material`) with `#st-fs-earlier` empty.
- On ニュース click a 短信 row, then 幅に合わせる / 中 / 原寸 in `#st-zoom`, and 「← ニュース」 or the browser back button. A 決算説明資料 row opens `#st-deck-detail` with ニュース still `.on`; 「← ニュース」 (`#st-deck-back`) returns to the news list.
- From other tabs, an issuer name (`gotoChart`) opens 株価.
- Reload with `#stock/{code}`, `#stock/{code}/{sub}`, `#stock/{code}/news/{id}`, or `#stock/{code}/decks/{key}`. `#stock/{code}/decks` opens ニュース.

## Driving it with verify-stock-analyzer

Preconditions:

- Doctor reports `ok`.
- ニュース rows need `xbrl_filings` with `xbrl_documents` rows (or `tdnet_pdf_documents` `ok` rows). A box DB copy may have none (every code then reads 「ニュースがありません。」). On a copy this run owns, `DATABASE_URL=sqlite:////abs/copy.db .venv/bin/python jobs/xbrl/xbrl_parse.py parse --from D --to D --dest <xbrl dir with that day's manifest>` fills one day (2026-10-23 from `/mnt/vps/data/xbrl` gave 34 filings / 48 documents). Never run it on a shared DB. Without data, report the document paths as `verified-unreachable`.

- **Capture.** `helpers/capture.py stock --code 72030` writes `artifacts/stock/overview.json` (keys above; golden 72030: close 3094, change +65, `next_earnings` null, per ~11.4, pbr ~1.01; 31160 `quote` null; 39120 has `next_earnings` null), `financials.json` (`GET /api/stock/{code}/financials?statement=BS&periods=8&consolidated=auto`; golden `periods: []` / `earlier: []` / `empty.reason=no_material`), `filings.json` (`{code, name, market, sector33, filings[]}`, each filing `{id, source, submitted_at, title, doc_type, period_type, is_amendment, documents[{seq, part, file_name, url}]}`), `decks.json` (`GET /api/stock/{code}/decks`, `{code, decks[]}`), and `document.html` for the first 短信 document. It prints `filings=N documents=N decks=N financials=N earlier=N` and exits 0 when filings, decks, or financials periods are empty; an unknown code exits 1 with overview 404 `銘柄がありません。`.
- **Document HTTP.** `GET /api/stock/filings/{id}/documents/{seq}` is 200 `text/html` with `Content-Security-Policy` and `ETag` `"<sha256>.s<SANITIZE_VERSION>"`, no `<script>`, and `-webkit-text-size-adjust`. ## Gotchas

- `#st-tabs` is `.nav-tabs` (folder tabs, KAB-315). `#st-fin-tabs` and `#st-zoom` stay `.fin-tabs` like 決算速報 / PTS. Select by `[data-sub]`, `[data-stfin]`, `[data-zoom]`. At 390px the `#st-tabs` labels stay on one row (`tests/nonfunctional/test_stock_nav_tabs.py`); `.on` has top+left+right border and a white bottom that meets the content, inactive tabs sit on the bottom line only.
- There is no `#st-filing` select any more; filings are the ニュース rows. There is no 説明資料 folder tab. Deck detail lives in `#st-sub-decks` and opens from a news row, or from a reload of `#stock/{code}/decks/{key}`.
- The overview is fetched once per code. Switching sub tabs does not refetch it; 概要 fetches `/api/earnings/detail` once per code (`stockFinCode`), ニュース fetches `/filings` and `/decks` once per code (decks share the 説明資料 cache).
- `resetStockFs` clears `#st-fs-tbl` and `#st-fs-meta` only. `#st-fs-earlier` from a previous issuer can remain until that code's financials GET returns (or errors, which then clear it). Do not treat that flash as a filled earlier table.
- Routing has no `hashchange` handler. Setting `location.hash` to `#stock/...` from another tab (same document) does nothing until reload. `popstate` always calls `restoreRoute`. There is no `#app-nav` 銘柄 control (KAB-365). Reload `#stock` with `ui.route` cleared for the empty search.
- The iframes are `sandbox="allow-same-origin"` without `allow-scripts`; links inside do nothing. Measuring height needs same-origin access, so do not fetch documents from another origin.
- A changed sanitizer without a `SANITIZE_VERSION` bump keeps returning 304 with the old HTML.
- `fitStockFrame` re-measures on load (and the next animation frame), zoom change, window width change, and `#st-doc` width change (`ResizeObserver`). The observer covers the PC first paint where the page scrollbar appears after the first measure and used to clip ~15px (KAB-175, fixed in #988). Height-only resize (mobile address bar) does not re-measure.
- EDINET 有報 are not listed; only TDnet XBRL and converted PDFs.
