# サプライタブ

書き方は `docs/SCREEN_SPEC.md`。マスタの検査は `app/supply_chain.py`。

## 誰のための画面か

自分。銘柄を見るときに「この素材はどの原料から来て、どの最終製品に行き着くか」と「月にどれだけ作られ、輸入され、使われているか」を辿る。いまは原油系統と、そこに合流する原料（天然ガス・天然ゴム・塩）だけ。企業と流量は対象外（下）。

## 画面と遷移

1 画面。`data-tab="supply"`。ハッシュは `#supply`、素材を選んでいれば `#supply/<素材 id>`（再読込で選択も戻る）。

- 素材の箱をタップ → その素材を選ぶ
- 詳細パネルのチップ → その素材を選び、経路が収まるよう寄る
- マップの何もないところ / 全体表示 → 選択を外す

## データ形

`config/supply_chain.json`。git で管理し、手で直す。

```json
{
  "materials": [{"id": "naphtha", "name": "ナフサ", "kind": "mid", "note": "石油化学の出発点"}],
  "flows": [["crude", "naphtha"]]
}
```

- 素材 `id` は `^[a-z][a-z0-9_]*$`。URL と flows で使うので付け替えない
- `kind` は `raw`（原料。地球から直接採るもの）/ `mid`（中間財）/ `prod`（最終製品）。`note` は任意
- `flows` は `[原料, それから作られる素材]`。ツリーでなく有向グラフで、1 つの素材が複数の原料を持てる（PET 樹脂 ← エチレングリコール・テレフタル酸、エチレン ← ナフサ・エタン）。`prod` から先へも流れてよい（自動車部品 → 自動車、重油 → カーボンブラック）
- 検査（違反は起動後の初回 API で 500、テストで落ちる）: id と name の重複なし、知らないキーなし、flows の両端が存在、自己ループ・重複・循環なし、`raw` は入力を持たない、`raw` 以外は入力を 1 本以上持つ

## サプライ

**目的。** 素材を 1 つ選び、上流の原料と下流の最終製品をひと目で掴む。

**要素。** 上から

1. 操作行: 素材名の検索（`#supply-q`、datalist で候補）、全体表示（`#supply-reset`）、線をまとめる（`#supply-merge`、既定オン）、凡例
2. マップ（`#supply-map`）: 素材を左（上流）から右（下流）へ並べた図。箱の中に素材名、塗りと枠の色が kind（原料 アンバー / 中間財 青緑 / 最終製品 緑）。線は直角に曲がる。配置は elkjs 0.9.3（`layered`、`RIGHT`、`ORTHOGONAL`、`NETWORK_SIMPLEX`）、描画は Cytoscape.js 3.30.2。どちらも unpkg から、タブを初めて開いたときだけ読む。箱の幅は素材名の文字幅で決めてから配置する。線をまとめるは ELK の `mergeEdges`（同じ素材から出る線を 1 本の幹にする）。1px 罫線で区切る（チャートと同じ扱い）
3. 詳細パネル（`#supply-panel`）: 素材名と kind、上流・下流の素材数、note、直接の原料、これから作られるもの、元をたどった原料（`raw` の祖先。自分が `raw` なら出さない）、行き着く最終製品（`prod` の子孫。子孫が無ければ出さない）。チップの並びは json の素材順
4. 月次の量（`#supply-monthly`）: 詳細パネルの下。折れ線（`#supply-chart`、lightweight-charts）と表。折れ線は生産・輸入・輸出・見掛け消費のうち、生産の単位（生産が無ければ最初の系列の単位）にそろう系列だけ。表は全系列で、指標・最新月・値・単位。最新月が速報なら月の後ろに「速報」。指標は 生産 / 出荷 / 月末在庫 / 輸入 / 輸出 / 見掛け消費。系列ごとに最新月が違う（生産は速報で翌月末、輸出入は 1〜2 か月遅れ。速報に無い素材は確報の翌々月中旬）

**操作。** 素材を選ぶと、祖先と子孫とその間の線を残し、他は薄くする。経路の線はアクセント色で太く、箱より手前に描く。検索は名前の完全一致、無ければ部分一致の最初の素材。線をまとめるの切替は配置をやり直して全体を表示する。ドラッグで移動、ホイール / ピンチで拡大。箱は動かせない。

**空とエラー。** 読み込み中はマップに「読み込み中…」。API かライブラリの読込に失敗したら「読み込めませんでした (理由)」。次にタブを開いたときに読み直す。未選択の詳細パネルは「素材を選ぶと、原料と行き先が出ます。」。月次の量は読み込み中「読み込み中…」、統計の対応が無い素材は「統計の対応がまだありません。」、失敗は「読み込めませんでした (理由)」。

**スマホと PC。** 同じ構造。900px 以上はマップの右に幅 300px の詳細パネル、未満はマップの下。マップの高さは PC が画面の残り、640px 以下は 60vh。

## API

`GET /api/supply/graph` → `{materials: [{id, name, kind, note}], flows: [[from, to]]}`。`note` が無ければ null。プロセス内で一度だけ読む（json を変えたら再起動。デプロイは再起動する）。Basic の後ろ。

`GET /api/supply/monthly/{material_id}` → `{material_id, series: [{metric, unit, sources, points: [[YYYY-MM, value, revision]]}]}`。revision は 1 速報 / 2 確報 / 3 年報。系列は 生産 → 出荷 → 月末在庫 → 輸入 → 輸出 → 見掛け消費 の順。同じ指標でも単位が違えば別の系列。`apparent`（見掛け消費）は保存せずここで計算し、`sources` は空、revision は材料の最小。素材が無ければ 404。取込は `DESIGN.md` §3「素材の月次量」

## 対象外

順に足す。

1. 企業: 素材を作る企業（`makes`）、親子会社（`owns`）、販売先（`trade`）。上場企業は `stocks` の 5 桁コードで結び、出典と確認日を持たせる。詳細パネルに「作っている企業」を出し、検索に社名・証券コードを足す。マップには描かない
2. 統計の対応が無い素材（エタン、硫酸の生産、炭素繊維、最終製品の多く）。資源・エネルギー統計（石油統計速報。原油の処理量・在庫）は未取込
3. 流量: 「直接の原料 → 素材 → 用途」のサンキー図。按分の推計値は斜線で区別する。実数が入るまでダミー値では出さない
4. 他の系統（天然ガス・金属・生物資源）と、素材が数百になったときの系統ごとの切替
5. 4,000 社の全体俯瞰
6. ダークテーマ（アプリ全体がライトのみ）
