# サプライタブ

書き方は `docs/SCREEN_SPEC.md`。素材マスタと企業マスタの検査は `app/supply/chain.py`。

## 誰のための画面か

自分。銘柄を見るときに「この素材はどの原料から来て、どの最終製品に行き着くか」と「月にどれだけ作られ、輸入され、使われているか」と「どの企業がどれだけの能力で作っているか」を辿る。いまは原油系統と、そこに合流する原料（天然ガス・天然ゴム・塩）と、鉄の系統（鉄鉱石・原料炭 → コークス → 銑鉄 → 粗鋼 → 普通鋼・特殊鋼の鋼材）と、銅の系統（銅鉱石 → 粗銅 → 電気銅 → 伸銅品・電線・銅箔 → 電子部品ほか）と、アルミの系統（ボーキサイト → アルミナ → 地金 → 板・押出品・箔 → 飲料缶・自動車ほか、二次合金地金 → ダイカスト・鋳物 → 自動車部品）と、そこへ戻るリサイクル資源（鉄スクラップ・銅スクラップ・アルミスクラップ）だけ。流量は対象外（下）。

## 画面と遷移

1 画面。`data-tab="supply"`。ハッシュは `#supply`、素材か企業を選んでいれば `#supply/<素材 id か企業 id>`（再読込で選択も戻る。id は素材と企業で重ならない）。

- 素材の箱をタップ → その素材を選ぶ
- 詳細パネルの素材チップ → その素材を選び、経路が収まるよう寄る
- 詳細パネルの企業チップ・シェアの表の行・ドーナツの区画 → その企業を選び、作っている素材が収まるよう寄る
- 企業パネルの「株価を開く」→ 銘柄タブの株価でその銘柄
- マップの何もないところ / 全体表示 → 選択を外す

## データ形

`config/supply/supply_chain.json`。git で管理し、手で直す。

```json
{
  "materials": [{"id": "naphtha", "name": "ナフサ", "kind": "mid", "note": "石油化学の出発点"}],
  "flows": [["crude", "naphtha"]],
  "returns": [["car", "steel_scrap"]]
}
```

- 素材 `id` は `^[a-z][a-z0-9_]*$`。URL と flows で使うので付け替えない
- `kind` は `raw`（原料。地球から直接採るもの）/ `mid`（中間財）/ `prod`（最終製品）/ `recycled`（リサイクル資源。使い終わった製品や加工の切りくずから回収するもの）。`note` は任意
- 素材を箱にするのは、次の 1 と 2 を満たし 3 に当たらないもの。量の多い少ないでは決めない（量が少なくても銘柄に効く素材がある。銅箔など）
  1. 流れが分かれる: 原料か行き先が既存の箱と違う。違わなければ近い箱の note に書く（銅合金の鋳物は行き先が伸銅品と同じなので伸銅品の note へ）
  2. 銘柄か統計につながる: 作る上場企業の顔ぶれが既存の箱と違うか、月次の統計が取れる
  3. 最終製品は大枠（自動車・家電・建設・電子部品など）で止める。中身（コネクタ・半導体など）は全体図に並べない（箱を開いて中を見せる形は対象外 9）
- `flows` は `[原料, それから作られる素材]`。ツリーでなく有向グラフで、1 つの素材が複数の原料を持てる（PET 樹脂 ← エチレングリコール・テレフタル酸、エチレン ← ナフサ・エタン）。`prod` から先へも流れてよい（自動車部品 → 自動車、重油 → カーボンブラック）
- `returns`（任意）は回収 `[使い終わる製品, リサイクル資源]`。リサイクル資源から作られる物は flows で書く（鉄スクラップ → 粗鋼）。回収は flows と組むと循環になる（粗鋼 → 鋼材 → 建設 → 鉄スクラップ → 粗鋼）ので、flows と別に持ち、循環の検査・配置・祖先と子孫に使わない。マップに線は引かない（配置の外を大回りする線が資源の数だけ束になる）。回収される素材の箱の印と、選んだときの紫の枠で示す
- 検査（違反は起動後の初回 API で 500、テストで落ちる）: id と name の重複なし、知らないキーなし、flows の両端が存在、自己ループ・重複・循環なし、`raw` と `recycled` は flows の入力を持たない、それ以外は入力を 1 本以上持つ。returns の両端が存在、行き先は `recycled`、出どころは `raw` / `recycled` でない、重複なし、`recycled` は回収を 1 本以上持つ

企業は `config/supply/supply_companies.json`。これも git で管理し、手で直す。数百社までは json、EDINET から全上場企業へ広げるときに DB へ移す。

```json
{
  "sources": {"meti_cap_2024": {"title": "経済産業省 主要石油化学製品生産能力調査 2024年12月末", "url": "https://…", "checked": "2026-10-14"}},
  "companies": [
    {"id": "tosoh", "name": "東ソー", "code": "40420", "status": "listed"},
    {"id": "taiyoenbi", "name": "大洋塩ビ", "status": "private", "parent_id": "tosoh"},
    {"id": "keiyo", "name": "京葉エチレン", "status": "private", "owners": [["maruzen", 55], ["sumichem", 45]], "source": "meti_cap_2024"}
  ],
  "makes": [["toyota", "car"]],
  "capacities": [{"id": "ethylene", "materials": ["ethylene"], "label": "エチレン生産能力", "unit": "千t/年",
                  "as_of": "2024-12", "source": "meti_cap_2024", "url": "https://…", "rows": [["tosoh", 493]]}],
  "trade": [["denso", "toyota", "src"]]
}
```

- 企業 `id` は素材と同じ書式で、素材の id とも重ならない。`status` は `listed`（上場。`code` は `stocks` の 5 桁で必須、表示は 4 桁）/ `private`（非上場）/ `foreign`（海外）。`note` は任意
- 親子は `parent_id` か `owners`（合弁。`[[出資者 id, %]]`、合計 100 以下）のどちらか。`owners` なら 50% を超える出資者を親とみなす。`source` は親子・出資の出典
- 上場持株会社の 100% 事業会社（ENEOS株式会社、コスモ石油、三菱ケミカル）は持株会社の id にまとめる
- `capacities` は会社別の生産能力の表。出典の表をそのまま写し、0 の行は載せない。1 つの表を複数の素材に掛けてよい（原油処理能力 → ナフサ・ガソリン・灯油・軽油・重油・アスファルト。製品ごとの能力ではないと `note` に書く）。1 つの素材に表が複数あってよい（ポリエチレン ← 低密度・高密度）
- `makes` は能力表に載る組（出典は表の出典）と、明示の `[企業, 素材(, 出典)]` の和。出典の無い組は出典未確認（issue #628 の代表例）。飲料メーカー（ペットボトルを使う側）は入れない
- `trade` は販売先 `[売り手, 買い手(, 出典)]`。有報の「主な相手先別の販売実績」（売上の 10% 以上）から入れる。いまはデンソー → トヨタ自動車だけ
- 検査: id・社名の重複なし、知らないキーなし、上場だけ `code`、`parent_id` / `owners` / makes / trade / 能力の行の参照先が存在、親の循環なし、出典の key が存在、`as_of` は `YYYY-MM`、`checked` は `YYYY-MM-DD`、能力は正の数で 1 表に同じ会社は 1 行

## サプライ

**目的。** 素材を 1 つ選び、上流の原料と下流の最終製品をひと目で掴む。

**要素。** 上から

1. 操作行: 素材名・社名・証券コードの検索（`#supply-q`、datalist で候補。上場企業の候補は「社名 4 桁コード」）、全体表示（`#supply-reset`）、線をまとめる（`#supply-merge`、既定オン）、凡例（4 つの kind と「使い終わると回収」の印）
2. マップ（`#supply-map`）: 素材を左（上流）から右（下流）へ並べた図。箱の中に素材名、塗りと枠の色が kind（原料 アンバー / 中間財 青緑 / 最終製品 緑 / リサイクル資源 紫）。線は直角に曲がる。使い終わると回収される素材（returns の出どころ）は箱の右端に紫の循環の矢印を描き、そのぶん箱を 14px 広げる。配置は elkjs 0.9.3（`layered`、`RIGHT`、`ORTHOGONAL`、`NETWORK_SIMPLEX`）、描画は Cytoscape.js 3.30.2。どちらも unpkg から、タブを初めて開いたときだけ読む。箱の幅は素材名の文字幅で決めてから配置する。線をまとめるは ELK の `mergeEdges`（同じ素材から出る線を 1 本の幹にする）。1px 罫線で区切る（チャートと同じ扱い）
3. 詳細パネル（`#supply-panel`）: 素材名と kind、上流・下流の素材数、その下にタブ「概要 / 企業 n / 輸入元 / 推移」（n は作っている企業の数。0 なら付けない。輸入元は国別の輸入がある素材だけ、取れてから出す）。選んだタブは素材を選び直しても続け、無いタブなら概要。タブの行はパネルをスクロールしても上に残る。概要は note、直接の原料、これから作られるもの、元をたどった原料（`raw` と `recycled` の祖先。自分が `raw` か `recycled` なら出さない）、行き着く最終製品（`prod` の子孫。子孫が無ければ出さない）、回収元（`recycled` だけ。回収の出どころ）、使い終わると（回収の行き先がある素材だけ）。企業は作っている企業と生産能力のシェア。輸入元は輸入元の国。推移は月次の量（5）。素材チップの並びは json の素材順
   - 作っている企業: 企業チップ（上場は 4 桁コードを添える）。出典つきを先、出典未確認を後に、どちらも json の企業順。出典未確認は点線の枠で、下に「点線は出典未確認（n 社）」
   - 輸入元の国（`#supply-countries`）: 見出し「輸入元の国」、ドーナツと凡例、下に「YYYY-MM〜YYYY-MM（最新月は速報）の輸入量 合計 単位・普通貿易統計（品別国別表）」。区切りは上位 5 か国（0.1% 未満は出さない）+ 「その他 n か国」で、色は生産能力のシェアと同じ 5 色と灰色。中央は 12 か月の輸入量の合計を 2 行で「62.9万」「t・12か月計」（1 万から「万」、100 万からは万の整数、1 億から「億」で丸める）。凡例は色・国・シェア（小数 1 桁 %）で、輸入量は区画と凡例の行に触れると出す（`title`）。表と円の両方は出さない（同じ割合を 2 回読むことになる）
   - 生産能力のシェア（能力表のある素材だけ。表ごとに 1 つ）: 見出し「<表の label>のシェア」、表の note、ドーナツ、表、出典の行、「親会社でまとめる」。ドーナツは能力の大きい順に上位 5 社を固定順の 5 色（青・橙・青緑・黄・桃）、6 位から下は「その他 n 社」の灰色 1 区画。区画の間は 2px の白。中央に合計と単位。区画に触れると社名・能力・割合（`title`）。表は全社で、色・会社・能力・シェア（小数 1 桁 %）。色は表の中の順位で振る（素材をまたいで同じ会社が同じ色とは限らない）。出典の行は「単位・YYYY年M月末・出典名（リンク）」。「親会社でまとめる」をオンにすると親をたどった一番上の会社ごとに足す（50% 超の出資者に合弁の全量を寄せる連結の考え方）。表の列名は「グループ」。オンオフはタブを開いている間すべての表で共通、再読込で戻る
4. 企業パネル（企業を選んだとき、`#supply-panel` の中身を差し替える）: 社名と区分（上場はコードを添える）、上場なら「株価を開く」、note、作っている素材（素材チップ、出典未確認は点線）、生産能力（その会社が載る能力表ごとに品目・能力・単位・表の合計に対するシェア。行を押すとその素材）、親会社（合弁なら「出資者」で比率つき）、子会社・出資先（`parent_id` で指す会社と出資先、出資先は比率つき）、販売先、仕入先、出典（親子・makes・販売先の出典の名前と確認日。無ければ「出典未確認」）。無い項目は「なし」
5. 月次の量（`#supply-monthly`。推移タブ、見出し「月次の生産・輸出入」）: 上から単位、凡例（`#supply-legend`）、折れ線と吹き出し（`#supply-chart`、lightweight-charts）、表。折れ線は既定で生産・輸入・輸出・原油処理・国内向販売・見掛け消費のうち、生産の単位（生産が無ければ最初の系列の単位）にそろう系列。表で指標の行を押すと選んだ指標だけを描き、縦軸も選んだ指標に合わせる。複数選べる。もう一度押すと外し、全部外すと既定に戻る。選んだ指標の単位が違えば単位ごとに縦軸を分ける（1 つ目は右、2 つ目は左、3 つ目からは目盛りなし）。押してもグラフは作り直さず系列だけ差し替える（作り直すと高さが一瞬 0 になり、スマホでページが上へ跳ぶ）。凡例は描いている指標の色と名前だけで、2 行ぶんの高さを取っておく。値はグラフに触れた位置の横に吹き出し（`#supply-tip`）で出す。中身は触れた月（`YYYY-MM`）と、描いている全指標のその月の値（無ければ `–`）。触れた位置がグラフの右半分なら吹き出しは左側に出す。離れると消す。指標ごとに最新月が違うので、違う月の値を並べることはしない。横線の値ラベルは出さない。横軸の目盛りは「2025年」「4月」。表は全系列で、指標・最新月・値・単位。最新月が速報なら月の前に「速報」（行ごとに月の位置がそろう）。指標は 生産 / 出荷 / 月末在庫 / 輸入 / 輸出 / 原油処理 / 国内向販売 / 見掛け消費。系列ごとに最新月が違う（生産は速報で翌月末、輸出入は 1〜2 か月遅れ。速報に無い素材は確報の翌々月中旬）。原油と石油製品は全指標が石油統計なので最新月がそろう

**操作。** 素材を選ぶと、祖先と子孫とその間の線を残し、他は薄くする。選んだ素材の回収の相手（リサイクル資源なら回収元、製品なら使い終わったときの行き先）は、経路の外でも薄くせず紫の太い枠で残す（回収をたどって広げない。たどると輪を一周して系統全部が残る）。輸入元の国はマップに置かない（詳細の輸入元タブと同じ割合を 2 か所で読むことになり、箱を置く空きも探せないことがある）。検索やチップで選んだときは、経路が収まるよう寄る（拡大は 1.2 まで）。企業を選ぶと、作っている素材を選択の枠で残し、他の素材と線をすべて薄くする。経路の線はアクセント色で太く、箱より手前に描く。検索は候補の完全一致、次に 4 桁の証券コード、無ければ部分一致の最初の素材、それも無ければ部分一致の最初の企業。線をまとめるの切替は配置をやり直して全体を表示する。ドラッグで移動（箱の上から始めても、長押ししてからでもマップが動く。動かさずに離せば箱を選ぶ）、ホイール / ピンチで拡大。箱は動かせない。ページ自体がピンチで拡大されている間（`visualViewport.scale` > 1）はマップの移動・拡大を止め、ピンチとスクロールをブラウザに渡す（マップが画面を埋めるとページを縮小できなくなるため）。

**空とエラー。** 読み込み中はマップに「読み込み中…」。API かライブラリの読込に失敗したら「読み込めませんでした (理由)」。次にタブを開いたときに読み直す。未選択の詳細パネルは「素材を選ぶと、原料と行き先が出ます。」。作っている企業が無い素材は「まだありません」。月次の量は読み込み中「読み込み中…」、統計の対応が無い素材は「統計の対応がまだありません。」、失敗は「読み込めませんでした (理由)」。

**スマホと PC。** 900px 以上はマップの右に幅 300px の詳細パネル。マップの高さは画面の残り。

900px 未満は詳細パネルを下から出すシート（`#supply-panel` の中に、つまみ `#supply-grip` と中身 `#supply-body`）にする。マップの下に置くと、選んでもスクロールしないと中身が見えないため。マップの高さは `100dvh - 186px`（最低 300px。ヘッダーと操作行のぶんを引く）で、ページがスクロールしない。凡例は項目の途中で折り返さない。

- 高さは画面の下 45% の 1 つだけ（中身はタブで分けて短いので、広げる状態は持たない。長いタブは中でスクロール）。素材か企業を選ぶと開き、選択を外すと閉じる
- 下へ 40px 以上スワイプか、つまみを押すと閉じる。スワイプはつまみからはいつでも、中身からは一番上までスクロールしているときだけ（ほかは中身のスクロール）
- 閉じても選択は残る。マップの箱を押すとまた開く
- 寄せるときは、マップのうちシートに覆われていない範囲に収める。そこが狭く経路が長いと箱が読めないので、拡大は 0.6 より引かず、そのときは選んだ素材を真ん中に置く。箱を押して選んだときは寄せず、その箱がシートの下に隠れるならマップを上へずらす

## API

`GET /api/supply/companies` → `{sources: {key: {title, url, checked}}, companies: [{id, name, code, status, parent_id, owners, note, source}], makes: [{company, material, source}], capacities: [{id, materials, label, unit, as_of, source, url, note, rows: [[company id, value]]}], trade: [{seller, buyer, source}]}`。`parent_id` は `owners` から決めた親も入る。`makes` は能力表の組を足したもの。無い値は null。プロセス内で一度だけ読む。Basic の後ろ。

`GET /api/supply/graph` → `{materials: [{id, name, kind, note}], flows: [[from, to]], returns: [[from, to]]}`。`note` が無ければ null。プロセス内で一度だけ読む（json を変えたら再起動。デプロイは再起動する）。Basic の後ろ。

`GET /api/supply/countries/{material_id}?flow=import|export`（既定 import）→ `{material_id, flow, unit, from, to, sokuho, total, countries: [{code, name, value, share}]}`。保存済みの最新月から遡る 12 か月の国別合計を多い順に。`sokuho` は最新月に速報を含むか。単位が混ざれば最新月の単位の行だけ足す。行が無ければ `countries` は空で他は null / 0。素材が無ければ 404、flow が違えば 400。

`GET /api/supply/monthly/{material_id}` → `{material_id, series: [{metric, unit, sources, points: [[YYYY-MM, value, revision]]}]}`。revision は 1 速報 / 2 確報 / 3 年報。系列は 生産 → 出荷 → 月末在庫 → 輸入 → 輸出 → 原油処理 → 国内向販売 → 見掛け消費 の順。同じ指標でも単位が違えば別の系列。同じ指標・単位を複数の出典が持てば月ごとに足し、全部の出典がそろわない月は出さない（アルミダイカスト・鋳物 = 生産動態 2560 + 2550）。`apparent`（見掛け消費）は保存せずここで計算し、`sources` は空、revision は材料の最小。貿易統計（`sources` が `trade` だけ）の系列は、0 の月が保存されないので、どれかの素材に貿易統計の行がある月を 0 で埋める（revision はその月の最小）。埋めないと 0 と未公表が区別できず、輸出がまれな素材（天然ガスなど）が 1 点だけの系列になる。素材が無ければ 404。取込は `DESIGN.md` §3「素材の月次量」

## 対象外

順に足す。

1. 企業の拡充: EDINET の有価証券報告書（主要な販売先・関係会社）から `trade` と親子を作り、全上場企業へ広げる（そのとき DB へ移す）。能力表の無い素材のシェア（自動車は各社の月次生産実績、タイヤ・家電は会社別の公開値が無い）。能力でなく生産量のシェア
2. 統計の対応が無い素材（エタン、硫酸の生産、炭素繊維、最終製品の多く）
3. 流量: 「直接の原料 → 素材 → 用途」のサンキー図。按分の推計値は斜線で区別する。実数が入るまでダミー値では出さない
4. 他の系統（天然ガス・鉄以外の金属・生物資源）と、素材が数百になったときの系統ごとの切替
5. 4,000 社の全体俯瞰
6. ダークテーマ（アプリ全体がライトのみ）
7. 輸出先の国（API は `flow=export` で返すが画面に出さない）と、国別の月次推移
8. 原料を運ぶ海運会社。会社 × 航路の輸送量は公開されず、隻数や傭船契約は機械的に最新へ更新できないので入れない
9. 素材の箱を開いて中のサプライチェーンを見せる（電子部品の中のコネクタ・リードフレーム → 半導体・プリント基板など）。タップは選択のままにし、開く操作は別に持つ
