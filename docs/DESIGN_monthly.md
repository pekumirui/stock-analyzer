# 月次タブ

参照。見た目と操作の正本。取込と unit は `DESIGN.md` §3。行名は [`DESIGN_monthly_labels.md`](DESIGN_monthly_labels.md)。書き方は `docs/SCREEN_SPEC.md`。

## 誰のための画面か

月次売上を業種グループで眺め、気になった発行体の年次表まで降りる人。

## 画面と遷移

- 月次タブは TOP から始まる。TOP は検索欄、グループチップ、発行体表
- 検索欄に名前、コード、または業種名を入れると、月次登録発行体だけが候補になる。Enter または候補クリックで表を絞り込む。会社名をクリックすると Detail へ
- チップをクリックすると検索絞り込みを外し、そのグループの行だけ残す
- Detail は戻る操作、系列切替つきの線グラフ、その発行体の横持ちの表。左の発行体一覧は置かない。年のドロップダウンは無い
- 戻ると TOP に戻り、直前のチップ選択と検索絞り込みを保つ
- 再読込は直近のタブを開く。Detail を見ていたらその発行体の Detail に戻る
- 公開面は `https://kabukpi.com/monthly` と `/monthly/{code4}`（パス）。個人ツール `/app` はハッシュ `#monthly` / `#monthly/{code}`

## データ形

`monthly_issuers` が発行体ごとの月次属性を持つ。`stocks.sector33` とは別物。

| 列 | 型 | 意味 |
|---|---|---|
| `code` | TEXT PK | `stocks.code` と同じ 5 桁。FK は付けない |
| `industry` | TEXT NOT NULL | 月次業種。既定は `その他` |
| `last_ingested_at` | datetime NULL | その code への ingest でセルが追加・変更・削除されたときに更新 |

書き込みは先に `db.get(Stock, code)`。無ければ 4xx `NOT_IN_MASTER`。既存の `monthly_tables` / `monthly_elements` / `monthly_values` は変えない。
ingest の列割り当てと暦年は `DESIGN.md` §3。

**新着。** 仮想グループ。`last_ingested_at` の JST 日付が今日を含む直近 7 日。業種グループと重複してよい。JST の日付が今日なら、行に NEW を付ける。

**系列の対応。** PDF の `element` 名を ID にはしない。一覧とグラフは次の規則で行を拾う。一覧の前年比は、セグメント・国・チャネルなしの売上高/連結売上高を優先する。セグメント・国・チャネル付き行は、セグメントなしの行が無いときだけ使う。同じ条件なら `sort_order` が先の行を使う。

| 系列 | 条件 |
|---|---|
| 全店 | 名前に `全店` または `全社` を含み `既存` を含まず、内訳が無く、unit が `yoy_index` または `yoy_pct`。スコープ無しの yoy 売上高/連結売上高/客数/客単価（既存なし・内訳なし）も全店 |
| 既存店 | 名前に `既存` を含み、内訳が無く、unit が `yoy_index` または `yoy_pct` |
| 店舗数 | 名前に `店舗数` を含み、unit が `number`。純増/新設/改装/業態転換は除く |

最新セルは、上の優先の段の中で値のある最大の `(year, month)`。無いときは空。表示の 100=フラットは保存の `yoy_index` のまま。
表の number は、表示単位がある指標だけ四捨五入（`fmtMonthlyCell`）。単位は項目名（`label.display`）。JSON と保存名は単位なし。
表示する 3 年に値が1つも無い行は表に出さない。系列セレクトは年をまたいだ行を残す。

**行名。** 保存と正規化の正本は [`DESIGN_monthly_labels.md`](DESIGN_monthly_labels.md)。分解は Python の `monthly_element_label`。year GET の各行に `label` が付く。SPA は再パースしない。画面の行キーは `label.display`。
年ごとの保存名が違っても表示名が同じなら1行。その年の値は、その年の保存 element のうち表示名が一致するものから取る。以下「表示名で畳む」と呼ぶ。和集合とゲートはクライアント側のまま。

AI による業種付けはしない。`industry` の更新は MCP と `PUT /api/v1/tables/{code}/industry`。SPA からは書かない。

## TOP

### 目的

グループを選び、その発行体の最新前年比を横並びで見る。

### 要素

`#monthly-sym` と `#monthly-suggest` をチップより上に置く。プレースホルダは「銘柄名 or コード」。候補行は 4 桁コードと正式名称。候補は月次登録発行体だけ。

`#monthly-groups` がチップ行。先頭は常に 新着。その後ろに、発行体が 1 社以上いる `industry` を日本語ロケールで並べる。件数 0 のチップは出さない。

`#monthly-tbl`（`table.sheet`）の列は左からこの順。独立したコード列は出さない。行には `data-code` を付ける。セルは縦横罫線。表は列の中身の幅（空列で画面を埋めない）。ビューポートより狭いときは中央（`margin-inline: auto`）。広いときは左から横スクロール。

| 列 | 出所 |
|---|---|
| 会社名 | code + 半角スペース + 会社名の先頭 5 文字。今日 ingest なら NEW。このセルだけ Detail へ |
| 市場 | プライムは 東証P、スタンダードは 東証S、グロースは 東証G。先頭に色付き記号 |
| 業種 | `stocks.sector33`。末尾の「業」を外し先頭 5 文字 |
| 月次業種 | `monthly_issuers.industry` |
| 全店(前年比) | 系列マップの最新セル |
| 既存店(前年比) | 系列マップの最新セル |

### 操作

入力中は `#monthly-suggest` だけ更新する。表は変えない。Enter は入力文字列を確定し、表を絞り込む。候補をクリックすると入力を正式名称にして同じ絞り込みをする。どちらも TOP に留まる。空の Enter は絞り込みを外し、チップの表に戻す。

照合は折りたたみ後に、名前の部分一致、コード 4 桁または 5 桁の前方一致、月次業種 `industry` の部分一致、`sector33` の部分一致。折りたたみは NFKC とひらがな→カタカナ。IME の compositionend でも候補を更新する。候補は最大 20 件。

チップをクリックすると検索絞り込みを外し、そのグループの行だけ残す。新着は `is_new` が真の行。業種チップは `industry` が一致する行。会社名をクリックすると Detail を開く。チップ以外の列は遷移しない。

**一時デバッグ:** 新着の右に `IR（一時）`（`data-group="__ir__"`）。`config/monthly/ir_monthly.json` の `issuers` と `html` に書いた code と、一覧 code の先頭 4 桁が一致する行だけ残す。コードは `GET /static/ir_monthly_codes.json` の `codes`（4 桁、URL は出さない）。0 件は「IR対象はありません」。月次表がまだ無い銘柄は出ない。公開 `/monthly` には出さない。

公開 TOP の既定チップは すべて。列は会社名・月次業種・全店(前年比)・既存店(前年比)。市場と `sector33` は出さない。

### 空とエラー

月次表が 1 件も無いときは「登録された月次データはありません」。系列が無いセルは空白。一覧 API が失敗したらその文を出す。表は出さない。

検索の候補が 0 件なら `#monthly-suggest` を隠す。確定した検索でヒットが 0 件なら「該当する発行体はありません」を出す。「登録された月次データはありません」は、発行体が 1 件も無いときと API 失敗のときに出す。

### スマホと PC

同じ構造。チップは折り返す。表は中身の幅で、狭いときは中央、広いときは左から横スクロール。縦横罫線。幅 1100px で二段組にしない。

## Detail

### 目的

1 発行体の系列を月次で比べ、PDF の全項目を年ごとに読む。

### 要素

`#monthly-back` が TOP へ戻る。見出しは会社名と code。

`#monthly-series` は単一の `<select>`。option は表示名を ID に、和集合の順（`monthlyRowOrder`。表示名で畳む）。optgroup は付けない。option の value はフル表示名のまま。
チャートは選んだ行をそのまま描く。既定は会社全体の 売上高(前年比)（スコープ `全店` / `全社` / 空。国・セグメント・内訳なし）。無ければ `series_kind === "all_store"`、それも無ければ先頭行。国だけの行（`海外 売上高(前年比)` など）は会社全体にしない。系列名はここに出す。チャート内には題名を描かない。

`#monthly-chart` は 1 枚の線グラフ。横軸 1〜12月に、表示する年を 1 本ずつ重ねる（年ごとのパネルや棒はやめた。年どうしを比べやすくするため）。上に年の凡例 `.monthly-legend`（新しい年が左）、その下に SVG 1 枚。

- 出す年は、選んだ行に値が 1 つでもある暦年のうち最新とその前2年（例: 2026 / 2025 / 2024）。表と同じ3年。空の月も目盛は出す。値の無い月で線は途切れる
- Y は値の幅に合わせ、0 から始めない（`monthlyLineRange`。上下に幅の 1 割の余白。値がすべて 0 以上なら下限は 0 を割らない）。前年比は 100 を必ず含める
- 色は暦年で固定し、表示順では付け替えない。`monthlyYearColor(year)` が `MONTHLY_YEAR_COLORS`（#0077b6 / #2e8b57 / #b8860b / #8e4ec6）を `year % 4` で引く。凡例の swatch も同じ色。最新の年は太く（2.5px）、一番上に重ねる。前の年は線・点・凡例を薄く（不透明度 0.4。`MONTHLY_OLD_YEAR_OPACITY`）。前年比で線が交差しても最新の年を追えるように。値の吹き出しは薄くしない
- 値は最新の年の点だけに書く（`monthly-pt-v`。3 年分は重なるため）。月スロットが 32px 未満のときだけ 9px
- 月にカーソルを当てる・タップすると、縦の補助線と `.monthly-tip` にその月の各年の値（`fmtMonthlyTick`、無い年は —）を出す
- 前年比グラフは 100 に灰色（#9aa3ad）の破線。最新年の色と紛れないよう黄色はやめた。店舗数や実数の行に 100 線は無い
- ライブラリは足さない。`static/js/monthly.js` 内の SVG
- 系列名の題は描かない。`#monthly-series` が系列名。Y軸に目盛の数字（`fmtMonthlyTick`）。左ガターに軸、下に月ラベル
- グラフと表は `#monthly-detail` の max-width 1080px 列に収める。TOP はビューポート全幅。`main` は絞らない

グラフと表を同じカードに入れない。

`#monthly-table-wrap` は横持ちの 1 枚表（下の「表」。`table.sheet.monthly-tl`）。個人 `/app` も公開 `/monthly` も同じ。暦年ごとに表を重ねる年別の表と、ゲート（節 + stub 3 列）はやめた（公開のサーバーが書く HTML だけは検索エンジン向けに暦年の表のまま。JS が横持ちに描き直す）。

- `#monthly-series` と行の和集合の順は `union_monthly_elements` / SPA の `monthlyRowOrder`。国なし → 日本 → 海外。セグメント無しが先、名前付きは新しい年から見た初出
- 各塊は 全店 → 既存 → チャネル（直営+FC → 直営 → FC）→ 売上高（実数の親→内訳、そのあと前年比の親→内訳。内訳は ドラッグ → 調剤 → 物販、領域は木の先行順）→ 客数 → 客単価 → 出店 → 退店 → 純増/新設/改装/業態転換 → 店舗数 → その他
- スコープ無しの店舗数は全店枠に入れず、既存の後へ（クスリのアオキ 合計店舗数 → `店舗数`）
- 出店/退店は指標で、セグメントにしない（ワッツ `100円ショップ 出店 店舗数` が売上高より前の塊にならない）
- 純増/新設/改装/業態転換は名前を変えず店舗数の前
- 直営はチャネルなので `焼肉 直営 店舗数` を全店の先頭に上げない。ブランド付きはセグメント（`カラオケ 全店 売上高(前年比)` は カラオケ）

### 操作

`#monthly-back` で TOP に戻る。直前のチップを保つ。グラフの指標は `#monthly-series` の切替、または表の該当行をクリックして変える。年の選択 UI は置かない。

**表（横持ち）。**
- 表示する3年を 1 枚の表にし、列は古い月→新しい月（値が 1 つも無い先頭と末尾の月は落とす）。見出しは 1 段で、各列の月の上に暦年を小さく薄く載せる（`2026年` / `8月`。横にスクロールしても年が分かる。赤帯の年の行はやめた）。1月の左は太い罫線。開いたら右端（最新月）へ横スクロール
- 行は API の木（下の「親子関係」）で描く。親子を JS で推測しない
- 前年比のセルは 100 を境に塗る（上げは `--up`、下げは `--down` の薄塗り。差 20 で最も濃い）。実数は塗らない
- 項目列は左に sticky（PC 18em、スマホ 12em。`直営+FC 既存 売上高(前年比)` が PC で 1 行）
- 同じ節に「X」（実数）と「X(前年比)」が両方あれば 1 行にまとめる（`monthlyPairYoyRows`。表示だけで DB・API は変えない）。位置と名前は実数の行。金額の下に `(前年比)` を小さく 2 行目に出す（金額の無い月は `(前年比)` だけ）。色は前年比。行をクリックすると系列は金額。数字の無いセルは塗らない
- 選んだ系列が閉じた節の下にあれば、根からその節までを開く
- 数字のセルを押すと、その行の同じ月を 2024 年以降（`MONTHLY_POPUP_MIN_YEAR`。それより前は取込済みと未取込が混ざる）の各暦年で並べたポップアップ `#monthly-pop` を出す。新しい年が上、年の色の印つき。金額と前年比をまとめた行は 年｜金額｜前年比 の 3 列、それ以外は 年｜値。前年比は表と同じ塗り。表示していない年は押したときに `GET /api/v1/tables/{code}/{year}` で取る（取得中は `…`、値が無い月は `-`）。PC もスマホも押したセルの下（入らなければ上）に、中身の幅だけの小窓で出す（見えている範囲 `visualViewport` に収める。全幅のシートにすると年の列が間延びして数字が画面の外に出た）。× ・外側のクリック・Esc で閉じる。セルを押すと行のクリックとして系列も切り替わる

### 親子関係（tree）

木は全発行体で API が返す。PDF の表どうしの親子（J.フロント: 連結 → 百貨店事業 → 大丸松坂屋百貨店 → 店計 → 大丸 / 松坂屋 → 各店）は、発行体ごとに `config/monthly/monthly_row_order.json` の `tree` と `metrics` に書く。書いていない発行体は API が自動の木を作る。行名と DB は変えない。割り当ては `app/monthly/tree.py`、year GET が各行の `tree` と表の `tree` / `tree_metrics`（自動なら `tree_auto: true`）を返す（`DESIGN.md` §5）。MCP の `monthly_get` も同じものを読むので、AI は銘柄ごとの癖を知らなくても親子を辿れる。

**節と指標を分ける。** 節は事業・会社・店・品目。同じ節を別の物差しで測った行（総額売上高と売上収益(IFRS)、売上高と入店客数）は子にしない。J.フロントの総額売上高は、IFRS 売上収益の百貨店の消化仕入を総額に、SC のテナント取引を取扱高に置き換えた数字で、IFRS とは数え方が違うだけで同じ事業（決算短信の注記）。子にすると内訳に見える。

- 節は `{name, prefix?, rows?, heading?, part?, children?}`。`rows` は保存名の完全一致、`prefix` は空白区切りの前方一致（`大丸 心斎橋店` は `大丸 心斎橋店 売上高(前年比)` に当たり、`大丸松坂屋 …` には当たらない）。完全一致が先、次に最長の prefix。どの節にも当たらない行は木の外
- `heading: true` は数字を持たない見出し（大丸・松坂屋。PDF に大丸計・松坂屋計が無い）。行を取らない。`prefix` は子の組み立てにだけ使う
- `part: true` は内数の節（うち商品売上高・うち不動産賃貸収入）。店計・法人・本社等と同じ親の下にあるが、足し合わせる関係ではない
- 子を文字列で書くと「親の prefix + 空白 + 文字列」を prefix、文字列を name にする（見出し `大丸`（prefix `大丸`）の子 `心斎橋店` → `大丸 心斎橋店`）
- `metrics` は `[{name, leaves}]`。行の葉（節の prefix を剥がした残り。剥がせなければ保存名）が `leaves` にあればその指標。並びが横持ちの指標の行の並び。どれにも無い行は metric null（横持ちでは先頭の指標に入れる）
- 内訳の 2 段目（ベルーナ プロパティ → ホテル）は `rows` で節を入れ子にする（旧 `breakdown_parent`）。行名に親事業を前置した小グループ（カネ美 `テナント事業 PPIHグループ`）は、自動の木だと事業と並ぶ兄弟になるので `tree` に書く
- 別表の同じ数字（J.フロントの 表1 百貨店事業 総額 と 表2 百貨店事業合計）は木で隠さず、`config/monthly/issuer_aliases.json` で DB を 1 行に寄せる（`docs/DESIGN_monthly_labels.md`）

**横持ちは 指標 ▸ 節の木。** 分析は「指標を 1 つ決め、その中を組織で降りる」順に見る（既存店売上高 → 客数・客単価 → 全店と店舗数 → どのブランド・店が効いているか）。焼肉の全指標を並べる見方より、既存 売上高 を焼肉 / ラーメン / … で比べる見方が先。
- 一番上の行は指標。並びは `tree_metrics`（自動の木は見る順、config は書いた順）。行の数字は根（会社全体）のその指標の行。名前は会社の行の名前。自動の木は保存名（`既存 売上高(前年比)`）、config の木は節で剥がした葉から `(前年比)` を外したもの（ＫｅｅＰｅｒ技研 `全社 売上高`。指標名 `売上高` のままだと全社の数字だと読めなかった）。金額の無い前年比だけの行は `(前年比)` を残す（神戸物産 `全国 仕入れ 全店 売上高(前年比)`。外すと金額に見えた）。会社の行が無い指標は指標名で、数字の無い行
- 指標の行を開くと、先に会社の子の指標（下の「指標どうしの親子」。直営 / FC、日本 / 海外）、次に根の子からの節の木。節（ブランド）は、その節の行がある一番浅い指標の下に出す。その指標の行（焼肉 直営+FC 全店 店舗数）があればそこで 1 回だけ出し、子の指標（焼肉 ▸ 直営 / FC）は節の行を開くと出る（既定は閉）。子の指標の下に同じブランドを並べ直さない（スマホで 焼肉 が 2 回出て、どちらが何の数字か分からなかった）。一番浅い指標にその節の行が無く、兄弟の枝（直営 / FC）にだけ行があるときは、行がある枝の下にそれぞれ出す（ハードオフ `ハードオフ 直営 店舗数` は 直営 の下、`ハードオフ FC 店舗数` は FC の下。ブックオフのように FC が無い業態は直営だけ）
- 名前は短く: 自動の木の一番上の行は会社の行の名前から `日本+海外` だけ外す（`直営+FC 全店 店舗数`）。`直営+FC` は残す（子の `直営` と見分ける）。子の指標の行は親との差だけ（`直営` / `FC` / `日本` / `海外`）各節の行にその指標の数字を出す（無ければ空欄）。その指標の行が子孫にも無い節は出さない（IFRS なら各事業だけ）。節にその指標の行が無く子の節にだけある（ワタミの既存店は 国内外食 の計が無く サブウェイ除く / サブウェイ だけ）ときは、その深さの節がそれ 1 つなら、数字の無い節の行は出さず子をその深さに並べる（空欄の行と閉じた ▸ だけが並んで読めなかった）。兄弟の節があるときは節名が子の所属を表すので残す（フレアスの施設数は メディカルケア事業 / 施設系介護サービス事業 の両方に同じ施設名がある）。見出し節の帯は残す。親は計が上
- 節の外に 1 行しか無い指標（マツキヨ `グループ 出店`）は木にせず、その行を一番上に出す。名前は自動の木なら保存名、config の木は「節名 葉」（ＫｅｅＰｅｒ技研 `直営 既存 売上高`。保存名の頭の `キーパーLABO運営事業` を一番上に出すと、同じ事業が 売上高 の木では 2 段目の節に出ていて深さが食い違い、混乱した）
- 同じ節に同じ指標が 2 行あれば（パルコの 全店 / 既存 取扱高）、2 行目から「節名 葉」で節の行の下に同じ深さで出す（葉が保存名のままなら表示名だけ）
- 見出し節は数字の無い `tl-sec` 帯。内数の節は `tl-part`（名前を薄く・細く）
- ▸ / ▾ で開閉。既定は閉じ、先頭の指標（既存店売上高）と、会社の行が無い指標（トライアル: トライアル / 西友 の別だけ）を開く。開閉のキーは指標ごと（`m:指標›節`）。木の外の行は末尾の「その他の項目」（既定は閉）
- 指標タブは無い（#434 の試作で物語が 13 タブになり読みにくかった）
- 字下げは 1 段 1.25em、スマホは 0.6em（7 段下がっても 12em の名前列で店名が 1 文字ずつ折り返さない）
- 選んだ系列が閉じた指標や節の中にあれば、指標の行からその節の親までを開く。金額と前年比の 1 行化（`monthlyPairYoyRows`）は節の中で掛ける

**自動の木。** config に `tree` の無い発行体。
- 根は `全体`（会社全体）。行名の group（ブランド・事業）を根の子の節、売上高の内訳（`label.breakdown`。ドラッグ / 調剤 …）をその行の節（根か group）の子の節にする。1 行しか無い group も節（9979 の `庄や 店舗数` は 店舗数 ▸ 庄や）。ゲート（同じ group が 2 行以上）は使わない
- `日本+海外` と `グループ` は行名の解析では group だが会社全体の数字なので根に置き、葉からも剥がす（物語 `日本+海外 直営+FC 店舗数` 932 がブランド別の合計店舗数の親）。行名全体が group の行（指標の無い行）も根
- group の中の合計の語（`企業計` / `グループ総` / `チェーン` / `総` / `全社（連結）` / `カウント` / `全業態` / `純` / `数`）は節にも葉にも残さない。それだけなら根（イオン北海道 `企業計 全店 売上高` は会社、`衣料 企業計 全店 売上高` は 衣料 の全店。35570 `全業態 既存 売上高` は会社、82000 `純 既存 売上高` は既存。33290 `数 退店` は退店）。指標の語（`増減` / `増減額` / `同規模` / `一品` / `買上点数` / `＊M&A除く` / `M&A除く`）は節から外して葉の頭に残す（LOIVE `ピラティスK 増減 店舗数` は ピラティスK の `増減 店舗数`。81630 `＊M&A除く 全店 売上高` は根の別指標）。語の一覧は `app/monthly/tree.py`
- 指標の語の無い前年比（アスモ `アスモトレーディング(前年比)`、`合計(前年比)`）は、その節（`合計` なら根）の金額の売上高の行が 1 つに決まればその指標の前年比にする。決まらなければ行名のまま。チャネル / 範囲 だけの前年比（7134 `直営 全店(前年比)`、`FC 既存(前年比)`）も同じ（#580）。同じ チャネル + 範囲 の 売上高 に寄せ、`直営+FC` はチャネル無しの 売上高（全店）に寄せる（#578）。売上高が 0 か 2 以上で決まらなければ行名のまま。実数の隣にある `増減率` 前年比（21240 `従業員数増減率(前年比)`）は、同じ名前の実数の指標へ寄せる（#578）
- 辞書に無い指標語で行名全体が group になり根にばらけた行は、既知の節・合計行へ戻す（#577 / #579）。対象は指標語が空の行だけ（`既存 売上高` / `純増 店舗数` のような辞書の指標語がある会社行は寄せない）。行名が既知の指標で始まる（71570 `保有契約年換算保険料 個人保険`）か終わる（87050 `リテール事業 預かり資産`）ならその指標の節、既知の節名で始まる（71850 `単体 営業収益`）ならその節の葉。節に入ったあとの膠着 `現物` / `信用` は 3 段目（71770 `クリック 一日平均売買代金現物`）。`連結X` の会社行は、節に `X` があるとき `X` へ寄せる（71850 `連結営業収益`）。`グループ` / `全社` / チャネル・範囲の語は節にしない
- 国の語（`日本` / `海外`）が group の前に出る行は group で節にし、国の語は葉に残す（7134 `海外 アップガレージ 店舗数` は アップガレージ の節の `海外 店舗数`。指標は 店舗数 ▸ 海外。31930 `日本 鳥貴族 店舗数` は 鳥貴族 の節の `日本 店舗数`）。group と噛み合わないときと、括弧で始まる group（43430 `日本 (曜日調整前) 既存 売上高(前年比)`、82550 `（従来基準） 全店 売上高(前年比)`）は根のまま（#590 / #591）。group の中のチャネルの語（`TCC`）は節にせず葉に残す（31930 `日本 鳥貴族 TCC 店舗数` は 鳥貴族 の節の `日本 TCC 店舗数`）
- 節にだけある指標（会社の行が無い）は、会社の `全店` / `全社` 付きの同じ指標へ寄せる（#592。30820 / 82000 の業態・ブランド `店舗数` → 会社の `全店 店舗数`）。既存だけのときは寄せない。`company_metric` で会社の行を節へ寄せたあとに掛ける
- 葉は表示名から group と内訳を剥がしたもの（`焼肉 直営 既存 売上高(前年比)` → `直営 既存 売上高(前年比)`、`全店 売上高 ドラッグ(前年比)` → `全店 売上高(前年比)`）。指標は葉から `(前年比)` を外したもの。会社の行と節の行は葉が同じなら同じ指標
- 指標語は `config/monthly/monthly_vocab.json`。`仕入高` を指標語にしたので、`出張訪問買取 仕入高` は 出張訪問買取 の節、`店舗買取 仕入高` は 店舗買取 の節に入り、根に行名のまま散らばらない（76850。#581）。辞書に無い語でも、上の既知の節・合計行への寄せが効く（#577）
- `group_metric`（`config/monthly/monthly_row_order.json`。指標 → 寄せ先の指標）で節の行の指標を寄せられる。物語のブランド別の合計店舗数は国内の数字なので `直営+FC 店舗数`（合計 932）から `日本 直営+FC 店舗数`（国内 816）へ寄せる
- `company_metric`（同じファイル。指標 → 寄せ先の指標）で会社の行の指標を寄せられる。物語の `日本 直営 店舗数` / `日本 FC 店舗数` は節と同じ `直営 店舗数` / `FC 店舗数`。柿安の `全社 売上高` は各事業の `売上高`。書かない発行体は寄せない（46800 の `日本 売上高`）
- 節はその節の行がある一番浅い指標の下に出す（根の指標から幅優先。物語の焼肉の合計店舗数は 国内 816 の下）。一番浅い指標が兄弟枝の一方（直営）だけで、もう一方（FC）にも節の行があるときは、FC の下にも出す（ハードオフの業態別店舗数）。親の指標の行がある節は従来どおり親の下に 1 回
- 指標どうしの親子（`tree_metric_parent`。指標 → 親の指標）: `直営` / `FC` の指標は `直営+FC`（無ければチャネル無印）の子、`日本` / `海外` の指標は国なしの子。`company_metric` で `日本 ` を外した指標は国内の `日本 直営+FC …` を先に探す。物語の店舗数は 合計 932 ▸ 国内 816 ▸ 直営 553 / FC 263、海外 116、ブランド別の合計。国付きの 直営 / FC は、同じ国の合計が無ければ国なしの同じチャネルの子（ハードオフ `海外 直営 店舗数` 14 は `直営 店舗数` 568 の内訳）。売上高も `直営+FC 既存 売上高 ▸ 直営 既存 売上高`
- `tree_metrics` は見る順: チャネル（無印・直営+FC → 直営 → FC）→ 国（無印・日本+海外 → 日本 → 海外）→ 既存 → 全店 → 売上高 → 客数 → 客単価 → 出店・退店・店舗数 → その他。代表は会社の行（無ければ最初の節の行）
- 節の形は表示する 3 年で決まり年で変えない。根の子は 会社の内訳 → group（新しい年の初出順。`segment_tail` は末尾）。各行の `tree.order` は 3 年を通した和集合の並び（`union_monthly_elements`）

### 空とエラー

years が空なら「データなし」。選んだ系列に値が無い年はグラフから落とす。表は残す。チャート用の 3 行が PDF に無くても、表は全行のまま。

### スマホと PC

チャートも表も同じ構造。線と値の数値は PC と同じ。スマホで変わるのは軸の字サイズ、ガター、グラフの高さ（230px。PC は 250px）、表の sticky、項目列の幅。値ラベルは月スロット幅で 9px か 11px。表は狭いときは中央、広いときは左から横スクロール。二段組にしない。

## API

`GET /api/v1/tables` は `{code, name, years}` に次を足す。
`market`, `sector33`, `industry`, `last_ingested_at`, `is_new`, `ingested_today`, `all_store_yoy`, `existing_store_yoy`。

`GET /api/v1/tables/{code}` と `GET /api/v1/tables/{code}/{year}` の形は `DESIGN.md` §5。Detail の表は years を並列 GET する。画面の空セルは `-`。

`PUT /api/v1/tables/{code}/industry` の body は `{industry}`。stocks に無い code、月次表が無い code は 4xx。

ingest はセルが1つでも変わったとき `monthly_issuers` を upsert し `last_ingested_at` を今にする。同じ値の再送と `rows=[]` と `dry_run` は触らない。industry は既にあれば触らない。無ければ `その他`。

エラー包みは既存どおり `{"error": {"code": "...", "message": "..."}}`。
