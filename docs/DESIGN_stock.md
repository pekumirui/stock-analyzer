# 銘柄タブ

原文の取込と保存は `docs/DESIGN_xbrl.md` §15（TDnet の ZIP）と §16（過去の回を IR BANK の PDF から変換）。大量保有・自己株買い・公開買付けの取込は `docs/DESIGN_edinet.md` §5〜§7。共通見た目は `docs/SCREEN_SPEC.md`。

## 誰のための画面か

1 銘柄のことを 1 か所で見たい自分。指標と業績、株価、出した書類、株主を中のタブで切り替える。決算短信は TDnet の PDF と同じ並びで読む（PDF は TDnet で約 1 か月しか読めないので、それより前の回もここで読む）。

## 画面と遷移

メニューには置かない。ヘッダー右上の `銘柄検索`（`#sym-btn`）から開く（KAB-365）。ほかのタブの銘柄名からも開く。上に共通ヘッダー、その下に中のタブ 概要 / 株価 / ニュース / 株主。ニュースの短信の行を押すと詳細。ニュースの決算説明資料の行を押すと説明資料の中身（中のタブはニュースのまま）。

| 画面 | ルート |
|---|---|
| 概要 | `#stock/{code5}/summary`（`#stock/{code5}` も概要） |
| 株価 | `#stock/{code5}/price` |
| ニュース | `#stock/{code5}/news` |
| ニュースの詳細 | `#stock/{code5}/news/{news_id}` |
| 株主 | `#stock/{code5}/holders` |
| 説明資料の中身 | `#stock/{code5}/decks/{key}`（key は開示番号から作る `d` + 16 進 20 字。中のタブは無い） |

- 開いたときは概要。銘柄を選び直しても中のタブはそのまま（ニュースの詳細か説明資料の中身にいたときはニュースの一覧へ）
- 再読込は銘柄・中のタブ・ニュースの詳細・説明資料の中身まで戻す（`ui.route` にも同じパスを残す）
- 古いルート `#stock/{code5}/decks`（key なし）はニュースの一覧を開く
- チャートタブは無い。古いルート `#chart/{code5}`（ハッシュと `ui.route`）は `#stock/{code5}/price` に置き換える
- ほかのタブの銘柄名（決算速報の決算表とチャートの題、スクリーナー、ランキング（決算後パフォーマンスと PTS）、サプライの企業パネルの「株価を開く」）は株価タブへ飛ぶ（`gotoChart(code)` は `#stock/{code5}/price` を開く）

## データ形

共通ヘッダーと概要の指標は `GET /api/stock/{code}/overview`。概要の業績の表は決算速報と同じ `GET /api/earnings/detail/{code}`（引数なし = 最新の実績開示）。株価は `GET /api/chart/{code}` と `GET /api/earnings-performance/{code}`。ニュース一覧は `GET /api/stock/{code}/filings` と `GET /api/stock/{code}/decks` を日時で混ぜる（種類チップと `GET /api/stock/{code}/news` はまだ無い）。株主は `GET /api/stock/{code}/holders`。説明資料の中身は `GET /api/stock/{code}/decks/{key}`（読み取りは `DESIGN.md` の「決算説明資料の読み取り」）。中のタブは開いたときに初めて読み、同じ銘柄のあいだは読み直さない。

指標の出どころ（`statements` は決算短信本体の開示。予想修正だけの開示は予想にだけ使う）:

| 指標 | 計算 |
|---|---|
| 株価・前日比 | `daily_prices` の最新の終値と、その前の営業日の終値との差 |
| 時価総額 | 同じ日の `daily_prices.market_cap`（百万円）。画面は億円 |
| PER（予想） | 株価 ÷ 今期の予想 EPS。予想 EPS 0 以下は出さない |
| PBR（実績） | 株価 ÷ 値のある最新の開示の `raw_json` の `BPS` |
| 配当利回り（予想） | 年間配当予想 ÷ 株価 |

今期の予想（EPS は `raw_json` の `FEPS`、年間配当は `FDivAnn`）は開示を新しい順に見て決める。決算短信本体の開示ならそこで決める（本決算は来期予想の `NxFEPS` / `NxFDivAnn`。空なら予想なし。前の四半期の予想（終わった年度）には戻らない）。予想修正だけの開示は値があるときだけ使う。
| ROE（実績） | 値のある最新の通期の開示の `raw_json` の `ROE`（会社が短信に書いた値） |
| 自己資本比率 | 値のある最新の開示の `raw_json` の `EqAR` |
| 次回の決算日 | `earnings_date_pubs` の最新の `pub_date` の行で、今日以降の `sch_date` のうち一番近い日 |

## 共通ヘッダー

**目的。** どの中のタブでも株価と次の決算日を見る。銘柄はヘッダーの銘柄検索で探す（下の「銘柄検索」）。

**要素。** 上から:

1. `#st-title`。銘柄名（太字）、4 桁コード / 市場 / 33 業種
2. `#st-quote`。株価（太字）と前日比（`+12 (+0.98%)`。上げは `--up`、下げは `--down`）、終値の日付、時価総額（`245億円`）、次回の決算日（`次回決算 11/07`。決まっていなければ `次回決算 未定`、行が無ければ出さない）
3. 中のタブ `#st-tabs`（`.nav-tabs`。`data-sub="summary|price|news|holders"`）。選択中は `.on`（上と左右の枠、下は内容と同じ白でつながる）。非選択は下線のみ。塗りつぶしの `.fin-tabs` は使わない。説明資料の中身を開いているあいだもニュースが選択のまま

**操作。** 中のタブを押すとその中身に切り替え、ルートを書き換える。

**空とエラー。** 銘柄を選んでいなければ `右上の「銘柄検索」から銘柄を選んでください。`銘柄がマスタに無ければ `銘柄が見つかりません。` 株価が無ければ `#st-quote` に `株価データなし`。API 失敗は `読み込めませんでした。`

**スマホと PC。** 同じ構造。`#st-quote` は折り返す。中のタブは 390px 幅でも 4 つを 1 行に収める。

## 銘柄検索

**目的。** どの画面からでも銘柄を探して銘柄画面へ飛ぶ。

**要素。** ヘッダーの右端に `#sym-btn`（虫めがねと `銘柄検索`。スマホは虫めがねの下に小さく文字）。押すとヘッダーの下に `#sym-pop` が開き、入力 `#sym-q`（銘柄名かコード。プレースホルダは「銘柄名 or コード」）と候補 `#sym-suggest`（`GET /api/stocks/search` の最大 20 件、`4 桁コード 銘柄名`）。fixed の幕は使わない（`docs/SCREEN_SPEC.md` の 9）。

**操作。** 押すと開いて入力にフォーカスする。もう一度押す・Esc・外のクリックで閉じる。入力すると候補を出す。候補をクリックか Enter（先頭の候補）で選ぶと閉じて銘柄画面へ。銘柄画面にいれば中のタブはそのまま（ニュースの詳細か説明資料の中身にいたらニュースの一覧へ）、ほかの画面からは概要。三本線のメニューを開くと閉じる（逆も同じ）。

## 概要

**目的。** 指標と業績の流れを一目で見る。

**要素。** 上から:

1. 指標 `#st-metrics`。PER（予想）、PBR（実績）、配当利回り（予想）、ROE（実績）、自己資本比率を横に並べる。名前は小さく上、値は下（`12.3倍` / `0.85倍` / `3.2%` / `7.1%` / `45.0%`）
2. 業績 `#st-fin`。決算速報の決算表と同じ表と切り替え（累計 / 3か月 / 進捗率 / 修正履歴。中身と書式は `docs/DESIGN_earnings.md` の「決算表」）。既定は累計

**操作。** 業績の切り替えを押すとその表に差し替える。

**空とエラー。** 算出できない指標（予想 EPS が 0 以下か無い、BPS が無い、配当予想が無い）は `–`。決算短信が 1 件も無ければ業績に `データなし`。

**スマホと PC。** 同じ構造。指標は折り返す。表は決算速報と同じく横スクロール。二段組にしない。

## 株価

**目的。** 株価と出来高を、下のバーで期間を決めて見る。指数・決算に対する動きも見る。

**要素。** チャートは共通の部品 `static/js/chart-core.js`（決算速報の `#e-chart` も同じ部品）。この画面の配線は `static/js/stock-price.js`。描画は lightweight-charts 5.2.1 を `static/vendor/` から配る（CDN は使わない）。

1. 操作の行。左から:
   - 足 `#tf`（`.fin-tabs`。日足 / 週足 / 月足 / 年足。既定は日足。選んでいる足を `.on`）
   - 移動平均 `#mas`（カンマ区切り。既定 `50,150,200`。日数で書き、週足は ÷5、月足は ÷20、年足は ÷250 の本数で引く。2 本に満たない移動平均は引かない）
   - 下段 `#chart-sub`（出来高 / 売買代金）
   - 業績の段 `#chart-fund`（なし / 営業利益 / 予想PER / 時価総額÷営業利益。既定はなし）
   - `#chart-hl` 高安値（既定オン）、`#chart-band` PERバンド、`#chart-log` 対数、`#rel` 対TOPIX のチェック
   足・下段・業績の段・高安値・PERバンド・対数は localStorage `chart.view` に残す
2. 日付・始高安終 `.chart-ohlc`（チャートの上、プロットの外。十字カーソルの足、カーソルが無いときは最後の足。`2026/10/30 始 1,899 高 1,966 安 1,899 終 1,959 +59 (+3.11%)`。上げ `--up`、下げ `--down`。足種は書かない。狭い幅は折り返す）
3. チャート `#chart`（高さ 520px。業績の段を出すと 120px 高くする）。上から次の段で、横軸は共通:
   - ローソク足と移動平均。陽線 `--up`、陰線 `--down`、中は塗る。値は調整後（分割・併合をならした値）。縦軸は見えているローソク足の高値・安値に合わせる（移動平均・PERバンドで広げない）
   - 高安値（入れたときだけ）。見えている期間の山の上に高値、谷の下に安値を `8/13 26,020` の形で出す（期間が 1 年を超えると `25/8/13`）。山・谷は、前後それぞれ k 本の中で一番高い（安い）足。k は 1 本の幅から決め、ラベルがおよそ 80px に 1 つになるようにする（最低 2 本）。見えている期間の最高値・最安値は必ず出す。ただしチャートの左右の端ではみ出すラベルは日付を外し、それでもはみ出せば出さない
   - PERバンド（入れたときだけ、ローソク足の段に重ねる）。予想EPS × n 倍の線を 3 本。n は表示できる全期間の予想PER の 10%・50%・90% 点（10 倍未満は小数 1 桁、ほかは整数に丸める）。値は凡例に出す
   - 出来高か売買代金の棒。直前 20 本の平均の 2 倍以上の足は `--accent`、ほかは `--grid` より濃い灰色
   - 業績の段（選んだときだけ）:
     - 営業利益: 四半期（Q単独）と直近 12 か月の合計の 2 本の階段線
     - 予想PER: 調整後の終値 ÷ 調整後の予想EPS（倍）。中央値に点線。予想EPS が 0 以下・無い日は線を切る
     - 時価総額÷営業利益: その日の時価総額 ÷ 直近 12 か月の営業利益（倍）。営業利益が 0 以下・無い日は線を切る
   - 対TOPIX 相対（データの最初の日=100）。対TOPIX を入れたときだけ、ローソク足の段に `--text` の太線で重ねる（段を増やすと縦に長くなりすぎるため）。縦軸は株価と別で、軸は出さない（値は凡例）。重ねている間はローソク足と移動平均を薄くする
   - 縦軸には数字だけを出し、単位は段の右上（縦軸のすぐ左）に `(万株)` `(百万円)` と 1 つ書く。軸の数字を短くしてスマホでもプロットを広く取るため。出来高は万株、売買代金と営業利益は百万円。最大（出来高・売買代金は見えている期間、営業利益は全期間）が 1 万株・100 万円に届かなければ株数・円のまま、単位も書かない
   - 段の境目をドラッグして高さを変えることはできない（間違って広げてしまうため）
   - 指でチャートに触れて横に滑らせると、十字カーソルと始高安終・凡例が指の足を追う。縦に滑らせたときは画面のスクロール
4. 期間のバー `.chart-nav`（チャートのすぐ下、高さ 44px）。全期間の終値の線と年の目盛り、いま出している期間の窓。窓の外は薄く暗くする
5. 凡例 `.chart-legend`（段ごとに左上へ重ねる。縦軸にはラベルを並べない。並べると軸が太り、グラフが狭くなる）。値は十字カーソルの足、カーソルが無いときは最後の足:
   - ローソク足の段: 移動平均の値を線の色で（`MA50 2,965.7 MA150 3,154.6 MA200 3,190`）。対TOPIX を入れていれば先頭に `対TOPIX 80.9`。PERバンドを出していれば次の行に各線の値（`PER 8.3倍 2,259 / 11倍 2,993.9 / 15倍 4,082.6`）
   - 出来高の段: `出来高 12.3万株` か `売買代金 15.2億円`
   - 業績の段: `営業利益 四半期 1.1兆円 12か月 4.2兆円` / `予想PER 11.4倍` / `時価総額÷営業利益 12.0倍`
6. イベントの重ね合わせ（決算発表日の「決」。既定オフ。`DESIGN.md` §4.3）
7. 決算発表後パフォーマンス `#perf-tbl`（`table.sheet`。%、α=対TOPIX 超過）。直近 12 回。列は発表日、+1d、α、+5d、α、+20d、α、+60d、α、現在まで、α。基準は決算後に買えた最初の値（引け後の発表は翌営業日の始値、場中は当日の終値。ストップ高引けと寄らずの日は飛ばす。`DESIGN.md` §4.3）

**業績の数字の作り方。** その日に分かっていた値だけを使う（後から出た訂正や予想で過去を書き換えない）。決算・予想修正の開示を古い順に見て、開示のたびに次の値を決め、次の開示まで同じ値を使う。引け後（`DESIGN.md` §4.3 の大引け以降。時刻が無いときも）の開示は翌営業日から、場中は当日から使う。

- 予想EPS: 概要の PER（予想）と同じ決め方（決算短信は今期予想、本決算は来期予想、予想修正だけの開示は値があるときだけ）
- 四半期の営業利益: 決算短信の Q単独（`DESIGN.md`「Q単独値の算出」）
- 直近 12 か月の営業利益: 本決算は通期。四半期は 当期累計 + 前期通期 − 前期同期累計。どれかが無ければ出さない
- 前の期を出し直した開示（訂正・遅れた再提出）は、いま出ている一番新しい期より古ければ使わない
- 予想EPS は、開示した日より後の分割・併合の係数（株価の調整と同じ `adj_factor`）を掛けて調整後の株価とそろえる
- 権利落ちが開示から 180 日以内の分割・併合は、会社が分割後の株数で予想を出し直していることがある。その係数を掛けない候補も作り、直前の予想EPS（調整後）に一番近いものを採る

**足の作り方。** 日足を一度だけ読み、週足（ISO 週）・月足（暦月）・年足（暦年）・移動平均・対TOPIX はブラウザで作る。週足・月足の足の日付は期間の最終営業日。始値は最初、終値は最後、高安は最大・最小、出来高・売買代金は合計。

**操作。**

- チャートはホイール・ドラッグ・ピンチで動かさない（スマホでは画面のスクロールになる）。選んだ期間をいつも幅いっぱいに出す。指・マウスを置いた足は上の日付行と凡例に出す
- 期間のバー: 窓の中をつまんで横に動かす、窓の左右の端をつまんで伸び縮みさせる（最短 10 営業日）、窓の外を押すとそこへ窓を動かす。動かすあいだチャートも付いてくる
- 銘柄を開いたときと足を変えたとき、日足は直近 1 年を出す（最後の足の日から 1 年前の同じ日付以降。その日が休みなら次の営業日。1 年に満たなければ全期間）。週足・月足・年足は、その足の最新を 1 本が 6px になるだけ出す（最低 20 本）。そこから先は期間のバーで動かす
- 期間のバーで広げても足は変えない（細くなるだけ）
- 画面の幅が変わっても出している期間は保つ
- 足・移動平均・下段・対数・対TOPIX を変えても読み直さない（移動平均は Enter か入力から外れたとき）。見えている期間は保つ
- 同じ銘柄を開き直しても読み直さない。10 分たったら次に開いたとき確かめる（変わっていなければ 304）

**空とエラー。** 株価が無ければ `株価データなし`。読めなければ `読み込めませんでした。` 決算が無ければ表は見出しだけ。TOPIX が読めなければ相対の段を出さない。

**スマホと PC。** 同じ構造。操作の行と日付行は折り返す。表は横スクロール。スマホではチャートと期間のバーを `.panel` の左右の余白まで広げる。

## ニュース

**目的。** その銘柄が出した書類と、その銘柄についての届出を新しい順に見て、読みたいものを開く。

**要素。**

1. 種類の絞り込み `#st-news-kinds`（チップ。すべて / 決算 / 修正 / 有報 / 自社株買い / 大量保有 / TOB。既定はすべて。その種類が 0 件のチップは出さない）
2. 一覧 `#st-news`（`table.sheet`）。1 行が 1 件で、列は左から 日時（`26/10/20 15:30`。時刻の無い書類は日付だけ）、種類（小さなバッジ）、題名、要点（`--sub`）

| 種類 | 元 | 題名 | 要点 |
|---|---|---|---|
| 決算 | `xbrl_filings`（`source = tdnet`、`doc_type` が `annual` / `semiannual` / `quarterly`）と `tdnet_pdf_documents`（`ok`）と `briefing_documents`（`saved`。`GET /api/stock/{code}/decks` と同じ行。同じ開示番号は 1 行） | 書類名。PDF から変換した回は末尾に `（PDF から変換）`。説明資料は表題 | なし |
| 修正 | `xbrl_filings`（`source = tdnet`、`doc_type` が `forecast_revision` / `dividend_revision` / `other`） | 書類名 | なし |
| 有報 | `xbrl_filings`（`source = edinet`） | 書類名 | なし |
| 自社株買い | `edinet_buybacks`（`is_latest` で取下げでない） | `自己株券買付状況報告書（YYYY年M月）` | `取得 12,300株`、決議が 1 つなら `累計の進捗 52.9%` を足す |
| 大量保有 | `large_holding_reports`（`code` がこの銘柄、`is_latest` で取下げでない） | 提出者名と `大量保有報告書` / `変更報告書` | `5.21% → 6.40%`（大量保有報告書は `6.40%`） |
| TOB | `edinet_tender_offers`（`target_code` がこの銘柄） | 買付者名と `公開買付け`（自社株は `自社株 TOB`） | `1株 1,500円 / 成立`（状態は 期間中 / 成立 / 不成立 / 撤回） |

訂正の書類は元の種類のまま並べ、種類のバッジの横に `訂正`。原文の無い決算・修正（`documents: []`）は行は出すが押せない。有報は押せない（原文は対象外）。説明資料は日時が `pubdate`（秒は出さない。時刻が無ければ日付だけ）。行のキーは短信が `x{xbrl_filings.id}` / `p{disclosure_no}`、説明資料が `d{key}`（`key` は説明資料の key）。

**操作。** チップで種類を絞る（ルートには残さない）。短信の押せる行を押すとニュースの詳細。説明資料の行を押すと説明資料の中身（`#stock/{code5}/decks/{key}`。ニュースの詳細は開かない）。

**空とエラー。** 短信も説明資料も無ければ `ニュースがありません。` API 失敗は `読み込めませんでした。`

**スマホと PC。** 同じ構造。題名と要点は折り返す。チップは折り返す。

## ニュースの詳細

**目的。** 1 件の中身を読む。

**要素。** 上に `← ニュース`（一覧へ戻る）と日時・種類・題名。その下は種類で変わる。

- 決算・修正: 原文 `#st-doc`。右上に原文の大きさ `#st-zoom`（幅に合わせる / 中 / 原寸。既定は幅に合わせる。選んだ方は localStorage `stock.zoom` に残す）。PDF から変換した回は題名の下に `#st-src`（`出典: IR BANK（TDnet）。PDF から変換した原文（画像は出ません）`）。選んだ書類の部品を上から順に 1 つずつ iframe で出す。iframe は中身の幅・高さまで伸ばし、画面のスクロールで読む。中身は会社が作った HTML のまま（見た目は PDF とほぼ同じ。ページのヘッダー・フッター、ロゴ、FASF マークは無い）
- 自社株買い: 報告月と報告期間、発行済株式総数、自己株式数（発行済に対する割合）、その月の取得株数と金額。決議ごとに 1 行の表（決議日、取得期間、枠の株数と金額、累計の株数と金額、進捗）
- 大量保有: 提出者、共同保有者の数、保有割合（前回 → 今回）、保有株数、発行済株式等総数、報告義務発生日、提出事由。保有者ごとに 1 行の表（名前、種別、保有割合、保有株数、保有目的、取得資金の合計）
- TOB: 買付者、状態、買付価格（引き上げていれば当初の価格も）、買付け等の期間、買付予定数（下限・上限）、買付け後の所有割合、対象者の意見と応募の推奨、結果（応募数・買付数。報告書が出ていれば）

**操作。** `← ニュース` かブラウザの戻るで一覧へ（絞り込みは保つ）。原文の大きさを切り替える。原文の中のリンクは押しても開かない。

**空とエラー。** 書類が無ければ `書類が見つかりません。` 原文の読み込みに失敗したら `読み込めませんでした。`

**スマホと PC。** 同じ構造。原文は幅が約 172mm 固定。iframe は中身の幅・高さまで広げ、中ではスクロールさせない（入れ子のスクロールは指で滑らせると引っかかる）。原文が `#st-doc` より広いとき、幅に合わせるは iframe を `transform: scale()` で幅いっぱいに縮め、外枠 `.st-page` を縮めた後の大きさにする（細かいところはピンチで拡大）。中は 0.75 倍（幅に合わせるより小さくはしない）。中と原寸ではみ出す分は `#st-doc` が横スクロール。原文が収まる幅（PC）は 3 つとも同じ見た目。測り直すのは読み込んだとき・大きさを切り替えたとき・画面の幅が変わったときだけ（スマホはスクロールでアドレスバーが出入りして高さだけの resize が続く）。カードの表は横スクロール。

## 株主

**目的。** 誰が大きく持っていて、増やしているか減らしているか、会社が自社株をどれだけ買っているかを見る。

**要素。** 上から:

1. 大量保有 `#st-holders-large`（`table.sheet`）。提出者（共同保有はまとめて 1 人）ごとの最新の報告で 1 行。列は 提出者（先頭 5 文字。下に EDINET。`title` に正式名）、保有割合、差（`+1.19pt`）、義務発生日、保有目的（先頭の 1 行。折り返さない）。保有割合の大きい順。最新の報告が 5% 未満（`5%以下に減少` の変更報告）の提出者は下にまとめ、淡色にする
2. 保有割合の推移 `#st-holders-chart`。大量保有の提出者ごとに折れ線（横は報告義務発生日、縦は保有割合）。線は上の表と同じ並びで最大 6 人
3. 自己株 `#st-holders-treasury`。最新の自己株券買付状況報告書の 発行済株式総数、自己株式数と割合。実施中の決議（取得期間の終わりが今日以降）があれば、枠と累計と進捗のバー

**操作。** 提出者名をクリックすると大量保有報告書タブのその人のページ（`#holders/{edinet}`。`docs/DESIGN_holders.md`）。ニュース詳細（大量保有の原文カード）はこのタブでは開かない。

**空とエラー。** 大量保有が無ければ `大量保有報告はありません。`（推移も出さない）。自己株券買付状況報告書が無ければ自己株に `自己株券買付状況報告書はありません。`

**スマホと PC。** 同じ構造。表は横スクロール。提出者列は `pinCols` で左に残す。

## 説明資料

**目的。** 決算説明資料を、原本の PDF を開かずに数字と要点で読む（VPS に原本を置き続けないため、読み取った表と要約から組み直す）。

**要素。** 中のタブは無い。ニュースの決算説明資料の行から開く（`#st-sub-decks`）。

1. 中身 `#st-deck-detail`。上に `← ニュース`。表題・開示日・`原本の PDF`（出所の URL を新しいタブで。TDnet の URL は約 1 か月で切れる）。その下に「読み取った数値と要約から組み直したもの（原本ではない）」と、数字の件数・文字データで確かめた件数・内訳の合計が合わない件数
2. ページごとに `p{N}` とタイトル、要約（灰色の帯）、グラフ、表。表紙・中扉・注意事項のページは出さない。読めなかったページは `このページは読めませんでした。` 文字データで確かめられない数字・内訳の合計が合わない行があれば、ページの末尾に件数
3. グラフ（SVG。`static/js/stock-deck.js`。規則は `analyzer/deck_reader/view.py` と同じ）。実績・予想・計画の列が 3 つ以上ある表だけ。内訳（`of`）は積み上げ棒（9 区分以上は 8 番目から「その他」）、内訳にマイナスが混ざれば内訳と合計を並べた棒、内訳の無い金額の行は 3 本までの棒、率（%・pts）は折れ線（金額と同じ軸にしない）。為替の行（指標名に「為替」を含む。単位が円でも）は通貨ごとに折れ線で、縦軸は 0 を起点にしない。円（為替・1 株当たり）は他とまとめない。予想・計画の棒は斜線、率の折れ線は白抜き、為替の折れ線は破線と白抜き。値はすべての棒・点に付ける（横に入らなければ縦書き、積み上げの区分は棒の中、入らなければ右横。置けなければ省いて表で読む）。凡例は 2 系列から
4. 表（`table.sheet`）。列は期間と種類（実績・予想・前回予想・計画・増減）、行は指標（区分）と単位。値は資料の表記のまま（丸めない）。マイナスは `−`、増減のプラスは `+`。内訳の行は字下げ

**操作。** ニュースの説明資料の行を押すと中身（`#stock/{code5}/decks/{key}`。中のタブはニュースのまま）。`← ニュース` か中のタブの `ニュース` でニュースの一覧へ。読み取り前の資料も行を押せば中身を開く。

**空とエラー。** 中身が読み取り前なら状態（`読み取り中` など）だけ。key が無ければ `説明資料が見つかりません。` API 失敗は `読み込めませんでした。`

**スマホと PC。** 同じ構造。グラフは幅に合わせて縮む（SVG）。表は横スクロール。二段組にしない。

## API

`GET /api/stock/{code}/overview`（`code` は 4 桁か 5 桁）

```json
{
  "code": "59330", "name": "アルインコ", "market": "プライム", "sector33": "金属製品",
  "quote": {"date": "2026-10-23", "close": 1234.0, "change": 12.0, "change_pct": 0.0098, "market_cap": 24500.0},
  "next_earnings": {"date": "2026-11-07", "fq": "2Q"},
  "metrics": {"per": 12.3, "pbr": 0.85, "dividend_yield": 0.032, "roe": 0.071, "equity_ratio": 0.45}
}
```

株価が無ければ `quote: null`。次回の決算日の行が無ければ `next_earnings: null`、未定なら `date: null`。算出できない指標は null。マスタに無い銘柄は 404、形の違うコードは 400。

`GET /api/stock/{code}/news`

```json
{
  "code": "59330",
  "items": [
    {"id": "x305", "kind": "earnings", "at": "2026-10-20 15:30",
     "title": "2027年３月期 第２四半期（中間期）決算短信〔日本基準〕（連結）",
     "summary": null, "is_amendment": false, "openable": true},
    {"id": "lS100ABCD", "kind": "large_holding", "at": "2026-09-15 09:00",
     "title": "○○アセットマネジメント 変更報告書", "summary": "5.21% → 6.40%",
     "is_amendment": false, "openable": true}
  ]
}
```

`kind` は `earnings` / `revision` / `annual_report` / `buyback` / `large_holding` / `tender_offer`。`id` は元のテーブルを頭文字で示す（`x{xbrl_filings.id}` / `p{disclosure_no}` / `b{doc_id}` / `l{doc_id}` / `t{tender_offer_id}`）。`at` の新しい順。件数の上限は置かない。

`GET /api/stock/{code}/news/{news_id}` は 1 件の詳細。決算・修正は今の `filings` の 1 件と同じ形（部品 `documents` と各部品の `url`）。自社株買い・大量保有・TOB は元のテーブルの列と子の行（決議 / 保有者 / 書類）。無ければ 404。

`GET /api/stock/{code}/holders`

```json
{
  "code": "59330",
  "large_holders": [
    {"filer_edinet_code": "E12345", "filer_name": "○○アセットマネジメント", "holding_ratio": 0.064,
     "holding_ratio_prev": 0.0521, "obligation_date": "2026-09-08", "purpose": "純投資",
     "news_id": "lS100ABCD",
     "history": [{"date": "2026-03-02", "ratio": 0.0521}, {"date": "2026-09-08", "ratio": 0.064}]}
  ],
  "treasury": {"report_month": "2026-09", "issued_shares": 20000000, "treasury_shares": 1200000,
               "active": [{"resolution_date": "2026-05-12", "acquire_to": "2027-03-31",
                           "limit_shares": 500000, "cumulative_shares": 264500, "progress_shares": 0.529}]}
}
```

`treasury` は報告書が無ければ null。

原文は今までどおり。`GET /api/stock/filings/{filing_id}/documents/{seq}` は原文の HTML（`text/html`）。`script` / `iframe` / `link` / イベント属性 / `javascript:` / 外の画像を除いて返す。ヘッダー `Content-Security-Policy` で script・外への通信を止め、`sandbox allow-same-origin`（親が高さを測るため）。`ETag` は原文の sha256 と除去の版（`SANITIZE_VERSION`。返す HTML を変えたら上げる。上げないと 304 が返り続け、ブラウザは古い HTML を使う）。iOS Safari の文字の自動拡大を止める `-webkit-text-size-adjust: 100%` を head の直後に差し込む。無ければ 404。

`GET /api/stock/pdf/{disclosure_no}` は PDF から変換した原文（`tdnet_pdf_documents` の `ok` の行）。ヘッダーは上と同じ。`ok` でなければ 404。

`GET /api/stock/{code}/filings` は残す（ニュースの決算・修正の元。説明資料は混ぜない）。形は 1 件が `{id, submitted_at, title, doc_type, period_type, is_amendment, documents}`、PDF から変換した回は `id: null`・`disclosure_no`・`attribution` が付き `source: "pdf"`。ニュース一覧は画面がこの応答と `decks` を `submitted_at` / `pubdate` で混ぜる。

`GET /api/stock/{code}/decks` は銘柄の決算説明資料の一覧（最大 200 件、開示の新しい順。同じ開示番号は tdnet → irbank → homepage の 1 行）。1 件は `{key, pubdate, title, url, status, pages, facts}`。`status` は読み取りの状態（`done` / `submitted` / `failed`、未読は null）。銘柄が無ければ 404。

`GET /api/stock/{code}/decks/{key}` は 1 冊の中身。`{document: {key, pubdate, title, url, status}, extract, pages}`。`extract` は `done` のときだけ `{model, prompt_version, pages, llm_pages, facts, verified, sum_checks, sum_mismatch, extracted_at}`、それ以外は null で `pages` は空。`pages` の 1 件は `{page, kind, title, summary, tables, error, unverified, mismatch}`（`tables` は読み取ったときの表そのまま。`unverified` は文字データで確かめられない数字の数、`mismatch` は内訳の合計が合わない行の数）。key がその銘柄の資料に無ければ 404。原本の PDF は返さない。

## 対象外

- 概要: BS / CF の表、PBR の過去レンジ（PER は株価の業績の段）、セグメント、月次の抜粋
- 株価: 決算ごとの騰落を業績の増減率と並べる表、スクリーナーなどの一覧から銘柄を次々に送る見方と先読み、価格帯別出来高、期間を URL に残すこと
- ニュース: TDnet の決算以外の適時開示（XBRL の付かない書類。自己株買いの決議・配当予想の修正・M&A など）、決算・修正の要点（修正の幅など）、有報・半期報の原文、決算補足説明資料、前回の短信との文章の差分、訂正前後の差分
- 株主: 大株主の上位 10 社（有報）、所有者別の構成、信用残・空売り残
- 説明資料: 原本のページ画像、銘柄をまたいだ指標の検索、画面からの読み取りの依頼（ジョブは手で回す。`deploy/README.md`）
- 原文の印刷・PDF の保存
