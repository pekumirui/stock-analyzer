# 画面仕様の書き方

画面の見た目と操作は `docs/DESIGN_<タブ名>.md` に書く。タブひとつにファイルひとつ。モードは参照。実装の約束は `AGENTS.md`。取込とスキーマは `DESIGN.md`。同じ文を三箇所に置かない。

例は `docs/DESIGN_monthly.md`。

## 共通見た目

全タブ。タブ別ファイルには繰り返さない。金融 UI は情報密度が先。

1. キャンバスは白。`--bg` と `--panel` は同じ `#fff`。グレーの床に白カードを浮かさない。
2. タブ全体を角丸・枠・影で包まない。決算速報の 4 区画だけ、白の上で 1px 罫線で区切ってよい（角丸なし）。チャート・スクリーナー・月次に外枠カードは置かない。
3. 横幅はビューポート。`main` で 1200/1600 に絞らない。左右は数 px のパディングだけ。
4. 表は中身の幅。`min-width: 100%` で空列を引き伸ばさない。列が多いとき（決算表・月次年表）だけ横スクロールでビューポートを使い切る。
5. 数字は `tabular-nums`。行の padding を広げない。スマホは `@media (max-width: 640px)` で触れる大きさ。新しいフォント・グラデ・影・フレームワークは足さない。
6. スマホと PC は同じ構造。表をカードに差し替えない。列を隠さない。足りない幅は横スクロール。padding・字サイズ・sticky・同じ区画の折り返しだけ変えてよい。月次年表の左 sticky は、項目列が画面を占有するときだけ外す。

## 置く場所

ファイル名はタブの英語 id に合わせる。月次タブは `data-tab="monthly"` なので `docs/DESIGN_monthly.md`。決算速報を切るなら `docs/DESIGN_earnings.md`。

`DESIGN.md` の「○○の表示」は作らない。そこにはこのファイルへの一文だけ残す。

## 見出しの順

この順で書く。飛ばさない。

1. 誰のための画面か
2. 画面と遷移
3. データ形
4. 画面ごとに `##` 見出し。下に 目的 / 要素 / 操作 / 空とエラー / スマホと PC
5. API
6. 対象外

`## 画面と遷移` に画面名とクリック先を書く。各画面の詳細は 4 の見出しへ。

## 各画面見出しの中身

**目的。** その画面でユーザーが終わらせる作業を一文で書く。

**要素。** 見えるものの名前、並び、値の出所。列なら左から順。DOM id が決まっているなら書く。

**操作。** クリック、戻る、絞り込み。条件を先に置く。

**空とエラー。** データ無し、マッピング無し、API 失敗で何を出すか。

**スマホと PC。** 同じ構造か、どこだけ横スクロールか。幅で二段組にしないなら、そう書く。

## 書いてはいけないこと

PDF の列割り当て、unit の付け方、MCP の認証、バッチ時刻。それらは `DESIGN.md` と `AGENTS.md` のまま。

未決をプレースホルダで残さない。決まっていない項目は `## 対象外` へ。
