# 画面仕様の書き方

画面の見た目と操作は `docs/DESIGN_<タブ名>.md` に書く。タブひとつにファイルひとつ。モードは参照。実装の約束は `AGENTS.md`。取込とスキーマは `DESIGN.md`。同じ文を三箇所に置かない。

例は `docs/DESIGN_monthly.md`。

## 共通見た目

全タブ。タブ別ファイルには繰り返さない。金融 UI は情報密度が先。

1. キャンバスは白。`--bg` と `--panel` は同じ `#fff`。グレーの床に白カードを浮かさない。
2. タブ全体を角丸・枠・影で包まない。決算速報の一覧は外枠を置かない。チャートと決算表の区画だけ、白の上で 1px 罫線で区切ってよい（角丸なし）。銘柄・スクリーナー・月次に外枠カードは置かない。
3. 横幅はビューポート。`main` で 1200/1600 に絞らない。左右は数 px のパディングだけ。
4. 表は中身の幅。`min-width: 100%` で空列を引き伸ばさない。列が多いとき（決算表・月次年表・保有者の銘柄一覧）だけ横スクロールでビューポートを使い切る。
5. 数字は `tabular-nums`。行の padding を広げない。スマホは `@media (max-width: 640px)` で触れる大きさ。新しいフォント・グラデ・影は足さない。一覧の表（決算速報・スクリーナー・ランキング・大量保有報告書）は同じ見た目: 縞とホバー、見出し 11px、銘柄は先頭 5 文字（`title` に正式名）の下に 4 桁コード、上揃え。縦罫は決算速報・スクリーナーだけ銘柄の右。ランキングは銘柄と市場の間に置かない。実装は `table.sheet`。`shortName` は `static/js/api.js`。保有者の名前も同じ（先頭 5 文字、下に EDINET）。保有目的は 1 行（`title` に全文）。本文セルの字サイズは `table.sheet td` でひとつ（保有目的に別サイズを持たせない）。スマホの自動拡大は `text-size-adjust: 100%` で止める。
   表の銘柄・市場・業種の書き方は全タブ同じ。どれも `static/js/api.js` の関数を通し、生の値を出さない（`title` 属性の正式名はよい）。X 用の画像など canvas に描くときも市場と業種は同じ（銘柄名は画像ごとの仕様。ランキングは正式名を幅で `…`）。市場と業種は `tests/nonfunctional/test_table_labels.py` が見る。
   - 銘柄: `shortName`（先頭 5 文字）。下段は `under()` で 4 桁コード。`title` に正式名
   - 保有者: `shortName`（先頭 5 文字）。下段は EDINET コード。`title` に正式名
   - 市場: `fmtMarket`。`東証P` / `東証S` / `東証G` と色の点（`td.mkt`）。J-Quants の `プライム` も株探の `東Ｐ` も同じになる。ほかの市場は元の名前
   - 業種: `fmtSector`。33 業種の末尾の `業` を外して先頭 5 文字（`情報･通信業` → `情報･通信`）。`title` に正式名
6. スマホと PC は同じ構造。表をカードに差し替えない。列を隠さない。足りない幅は横スクロール。padding・字サイズ・sticky・同じ区画の折り返しだけ変えてよい。月次年表の左 sticky は、項目列が画面を占有するときだけ外す。
7. 再読込は直近のタブを復元する。月次 Detail の発行体と銘柄タブの銘柄・中のタブ、ランキングの中のタブも含む。個人ツール `/app` は URL ハッシュと localStorage（`ui.route`）。実装は `static/js/tabs.js`。公開月次はパス `/monthly` / `/monthly/{code4}`。
8. `/app` は古いページを使い続けない。メモリから復元された（bfcache）ときは読み直す。1 分以上裏にいた後に戻ったら、ページと `/static` の CSS / JS の ETag を読み込み時と比べ、変わっていれば読み直す（iOS Safari はタブに戻るとデプロイ前の画面のまま動くため）。実装は `static/js/boot.js`。読み直し後の画面は 7 の復元で戻る。配信する HTML（`/app` と公開月次）の `/static` URL には中身のハッシュ `?v=` を付ける（`app/assets.py`）。iOS Safari はメモリの古い CSS を `no-cache` でも再読込でも確かめずに使うため、URL ごと変える
9. `/app` のヘッダー。ブランド名は出さない。PC はタブを 1 行で並べる。720px 以下はヘッダーを 1 行にし（左端に三本線、その右にパンくず。パンくずが無いときはいまのタブ名 `#cur-tab`）、タブの一覧は三本線を押すと左から出るドロワーに置く（タブが 2 行に折り返して縦を取るため）。ドロワーはタブを選ぶ・外の暗いところを押す・左へスワイプ・Esc で閉じる。タブの右（ドロワーでは末尾）に wiki への外部リンクを置く（`/app` のみ。公開月次には出さない。`app/assets.py` が配信 HTML に足す）。ヘッダーの上に色の線は付けず、`<meta name="theme-color">` は白にする（iPhone の Safari が画面の上下の枠をページと同じ白にするため）。ドロワーの暗い幕は画面の上下端を塗らず、閉じたら `display:none`（iOS Safari は幕の色を枠に残すため）。実装は `static/js/tabs.js`
10. パンくず。`nav#crumbs` はヘッダーに置く（`#menu-btn` の右。PC はタブ行の下の同じヘッダー。公開月次はサイト名の右）。`main` には置かない。パンくずがある画面は `#cur-tab` のページ名を出さない。無い画面はページ名のまま。区切りは ` > `。幅に収まらないときは折り返さず横スクロールし、先頭を省略して末尾（いまの画面）が見えるようにする。遷移元は URL の `?from=`（`/app` はハッシュ、公開月次はパス）。画面ごとに既定の経路を 1 つ持つ。`from` はその画面が受け付ける遷移元だけ。ルート定義と設定は `static/js/screens.js`
11. スマホ（端末の `screen.width` が 720px 以下）だけ、ページ末尾に「PC版を表示」を置く。押すと viewport を `width=1280` にして PC レイアウトにする。そのときは同じ場所に「スマホ版に戻す」。選択は localStorage（`ui.pcView`）。最初から広い画面では出さない。`/app` と公開月次。実装は `static/js/view-mode.js`

## 置く場所

ファイル名はタブの英語 id に合わせる。月次タブは `data-tab="monthly"` なので `docs/DESIGN_monthly.md`。決算速報を切るなら `docs/DESIGN_earnings.md`。

`DESIGN.md` の「○○の表示」は作らない。そこにはこのファイルへの一文だけ残す。

## 見出しの順

この順で書く。飛ばさない。

1. 誰のための画面か
2. 画面と遷移
3. データ形
4. 画面ごとに `##` 見出し。下に 目的 / 要素 / 操作 / 空とエラー / スマホと PC
5. API
6. 対象外

`## 画面と遷移` に画面名とクリック先を書く。各画面の詳細は 4 の見出しへ。

## 各画面見出しの中身

**目的。** その画面でユーザーが終わらせる作業を一文で書く。

**要素。** 見えるものの名前、並び、値の出所。列なら左から順。DOM id が決まっているなら書く。

**操作。** クリック、戻る、絞り込み。条件を先に置く。

**空とエラー。** データ無し、マッピング無し、API 失敗で何を出すか。

**スマホと PC。** 同じ構造か、どこだけ横スクロールか。幅で二段組にしないなら、そう書く。

## 書いてはいけないこと

PDF の列割り当て、unit の付け方、MCP の認証、バッチ時刻。それらは `DESIGN.md` と `deploy/README.md` のまま。

未決をプレースホルダで残さない。決まっていない項目は `## 対象外` へ。
