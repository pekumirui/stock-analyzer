# サプライタブ

素材のサプライチェーン、月次の生産・輸出入量、企業別の生産能力を俯瞰する画面の仕様を定める。共通の見た目と配置規則は [画面仕様の共通規則](SPEC.md) に従い、素材マスタと企業マスタの読み込み・整合検査は `app/supply/chain.py` で行う。月次統計の取込規則は [サプライの取込規則](../jobs/supply.md) を参照する。

## 誰のための画面か

個別銘柄を調べるときに、対象素材がどの原料から作られてどの最終製品に行き着くか、毎月どれだけ生産・輸入・消費されているか、どの企業がどれだけの生産能力を持つかを一画面で辿りたい利用者向けの画面である。

現在の収録範囲は以下の 4 系統とリサイクル資源である。工程間の流量表示は対象外とする。

| 系統 | 収録している範囲 |
|---|---|
| 原油・石油化学系統 | 原油と合流原料（天然ガス・天然ゴム・塩）から石油製品・基礎化学品・合成樹脂・合成繊維・合成ゴムを経て最終製品へ至る流れ |
| 鉄鋼系統 | 鉄鉱石・原料炭からコークス・銑鉄・粗鋼を経て普通鋼鋼材・特殊鋼鋼材・最終製品へ至る流れ |
| 銅系統 | 銅鉱石（精鉱）から粗銅・電気銅を経て伸銅品・電線とケーブル・銅箔・電子部品ほかへ至る流れ |
| アルミ系統 | ボーキサイトからアルミナ・アルミ地金を経て板・押出品・箔・飲料缶・自動車ほかへ至る流れ、および二次合金地金からダイカスト・鋳物を経て自動車部品・家電へ至る流れ |
| リサイクル資源 | 使い終わった製品や加工時の切りくずから回収して上流工程へ戻る鉄スクラップ・銅スクラップ・アルミスクラップ |

## 画面と遷移

サプライタブ（`data-tab="supply"`）は 1 画面で構成する。URL ハッシュと `localStorage`（`ui.route`）の経路は以下のとおりであり、ページ再読込時も選択中の素材または企業を復元する（素材 ID と企業 ID は重複しない）。

| 状態 | 画面 ID | ルート |
|---|---|---|
| 未選択 | `supply` | `#supply` |
| 素材または企業を選択中 | `supply` | `#supply/{id}`（`^[a-z][a-z0-9_]*$` に一致しない文字列は `#supply` に戻す） |

画面内の操作による状態遷移は以下のとおりである。

| 操作箇所 | 遷移と動作 |
|---|---|
| マップ上の素材ノードをタップ | その素材を選択する。ズーム倍率は変えず、スマートフォンで詳細シートの下に隠れるときだけマップを上下にずらす |
| 詳細パネルの素材チップ、または企業パネルの生産能力表の行をクリック | 対象の素材（生産能力表は `materials` 先頭の素材）を選択し、経路全体が収まる位置へマップを寄せる |
| 詳細パネルの企業チップ、生産能力シェア表の行、またはドーナツチャートの企業区画をクリック | その企業を選択し、製造している素材ノードが収まる位置へマップを寄せる（「その他」の区画は対象外） |
| 企業パネルの「株価を開く」（`#supply-chart-link`）をクリック | 銘柄タブの株価（`#stock/{code5}/price?from=supply`）を開く |
| マップの空白部分をタップ | 選択を解除し、詳細パネルを初期表示に戻す |
| 操作行の「全体表示」（`#supply-reset`）をクリック | 選択と検索欄（`#supply-q`）の入力をクリアし、マップ全体が収まる位置へアニメーションで戻す |

## データ形

### 素材マスタ（`config/supply/supply_chain.json`）

素材ノードと工程のつながりは、リポジトリで管理する手書きの `config/supply/supply_chain.json` に定義する。

```json
{
  "materials": [{"id": "naphtha", "name": "ナフサ", "kind": "mid", "note": "石油化学の出発点"}],
  "flows": [["crude", "naphtha"]],
  "returns": [["car", "steel_scrap"]]
}
```

トップレベルの各キーの仕様は以下のとおりである。

| キー | 仕様 |
|---|---|
| `materials` | `{id, name, kind, note?}` の配列である。`id` は `^[a-z][a-z0-9_]*$` とし、URL と `flows` で参照するため変更しない。`kind` は `raw`（地球から直接採る原料）・`mid`（中間財）・`prod`（最終製品）・`recycled`（使用済み製品や加工くずから回収するリサイクル資源）の 4 種類とする。`note` は任意の補足文で、未指定または空文字のときは `null` になる |
| `flows` | `[原料 id, それから作られる素材 id]` の配列で表す有向非巡回グラフ（DAG）である。木構造ではなく、PET 樹脂に対するエチレングリコールとテレフタル酸、エチレンに対するナフサとエタンのように複数原料の合流を許す。自動車部品から自動車、重油からカーボンブラックのように `prod` から下流への接続も許す |
| `returns` | 任意の配列で、`[使い終わる製品・加工材 id, リサイクル資源 id]` の回収関係を表す。リサイクル資源から素材を作る工程（鉄スクラップから粗鋼など）は `flows` に書く。`returns` を `flows` に混ぜると閉路が生じるため別配列に分け、閉路検査・ノード配置・祖先と子孫の探索には使わない。マップ外周を回る線が束になるのを避けるためエッジは引かず、回収元ノード右端の循環アイコンと選択時の紫枠で表す |

独立した素材ノードを作るかどうかは生産量の大小では決めず（銅箔のように少量でも銘柄分析に効く素材があるため）、以下の 3 基準で判断する。

1. 原料または行き先が既存ノードと異なること。同じであれば近い既存ノードの `note` に含める（例: 銅合金の鋳物は行き先が伸銅品と同じため伸銅品の `note` に書く）。
2. 製造する上場企業の顔ぶれが既存ノードと異なるか、独立した月次統計を取得できること。
3. 最終製品は自動車・家電・建設・電子部品などの大枠で止め、コネクタや半導体などの内訳は全体図に展開しない。

`validate_supply_chain` は以下の整合条件を検査し、違反があれば初回 API 呼び出し時に HTTP `500` を返す（自動テストでも検証する）。

- 未知のキーが無いこと、および素材の `id` と `name` に重複が無いこと。
- `flows` の両端が実在し、自己ループ・重複・閉路が無いこと。
- `raw` と `recycled` は `flows` の入力を持たず、`mid` と `prod` は `flows` の入力を 1 本以上持つこと。
- `returns` の両端が実在して重複が無く、行き先が `recycled`、出どころが `raw`・`recycled` 以外であり、すべての `recycled` が `returns` を 1 本以上持つこと。

### 企業マスタ（`config/supply/supply_companies.json`）

製造企業・生産能力・企業間取引は、リポジトリで管理する手書きの `config/supply/supply_companies.json` に定義する。数百社規模までは JSON で管理し、EDINET から全上場企業へ広げるときに DB へ移行する。

```json
{
  "sources": {"meti_cap_2024": {"title": "経済産業省 主要石油化学製品生産能力調査 2024年12月末", "url": "https://example.com", "checked": "2026-10-14"}},
  "companies": [
    {"id": "tosoh", "name": "東ソー", "code": "40420", "status": "listed"},
    {"id": "taiyoenbi", "name": "大洋塩ビ", "status": "private", "parent_id": "tosoh"},
    {"id": "keiyo", "name": "京葉エチレン", "status": "private", "owners": [["maruzen", 55], ["sumichem", 45]], "source": "meti_cap_2024"}
  ],
  "makes": [["toyota", "car"]],
  "capacities": [{"id": "ethylene", "materials": ["ethylene"], "label": "エチレン生産能力", "unit": "千t/年",
                  "as_of": "2024-12", "source": "meti_cap_2024", "url": "https://example.com", "rows": [["tosoh", 493]]}],
  "trade": [["denso", "toyota", "meti_cap_2024"]]
}
```

トップレベルの各キーの仕様は以下のとおりである。

| キー | 仕様 |
|---|---|
| `sources` | 出典キーをキーとする `{title, url?, checked}` の辞書である。`checked` は `YYYY-MM-DD` 形式の確認日とする |
| `companies` | 企業の配列である。`id` は素材と同じ `^[a-z][a-z0-9_]*$` で、企業間・素材間ともに重複しない。`status` は `listed`（上場）・`private`（非上場）・`foreign`（海外）の 3 種類で、`listed` のみ `stocks.code` と同じ 5 桁の `code`（`^[1-9][0-9A-Z]{3}[0-9]$`、画面表示は先頭 4 桁）を必須とする。上場持株会社の 100% 事業会社（ENEOS株式会社・コスモ石油・三菱ケミカル・JFEスチールなど）は持株会社の `id` に統合する。親子関係は `parent_id`（単独親）または `owners`（合弁の `[[出資者 id, 比率%], ...]`、各比率は `0` 超 `100` 以下かつ合計 `100` 以下）の片方のみ指定でき、`owners` で `50%` を超える出資者がある場合は API 応答の `parent_id` に自動設定する。`source` は親子・出資関係の出典キー、`note` は任意の補足文である |
| `capacities` | 会社別の生産能力表 `{id, materials, label, unit, as_of, source, url?, note?, rows: [[company_id, value]]}` の配列である。出典の数値をそのまま写し、`0` 以下の行は載せない。原油処理能力のように 1 つの表を複数素材（ナフサ・ガソリン・灯油・軽油・重油・アスファルト）に紐づけてもよく、製品別の能力でない場合は `note` に明記する。低密度・高密度ポリエチレンのように 1 つの素材に複数の能力表を持たせてもよい |
| `makes` | 明示の `[企業 id, 素材 id]` または `[企業 id, 素材 id, 出典 key]` と、`capacities` に載る `企業 × 素材` の和集合である。明示の出典が無い組でも能力表に載っていれば能力表の `source` を引き継ぎ、どちらにも出典が無い組は「出典未確認」となる。ペットボトルを使う飲料メーカーのように素材を消費するだけの企業は登録しない |
| `trade` | 販売先関係 `[売り手 id, 買い手 id]` または `[売り手 id, 買い手 id, 出典 key]` の配列である。有価証券報告書の「主な相手先別の販売実績」（総販売実績の 10% 以上）から登録し、現状はデンソーからトヨタ自動車への 1 件のみ収録する |

`validate_companies` は以下の整合条件を検査する。

- 未知のキーが無いこと、および企業 `id`・社名・能力表 `id` に重複が無いこと。
- `listed` のみ `code` を持ち、`parent_id`・`owners`・`makes`・`trade`・`capacities` の全参照先 ID と `source` キーが実在すること。
- 親会社の自己参照・同一出資者の重複・親の循環が無く、`trade` に自己取引や重複が無く、`makes` の明示配列に重複が無いこと。
- `as_of` が `YYYY-MM`、`checked` が `YYYY-MM-DD` であり、能力表の値が正の数で 1 つの表に同じ企業が 1 行しか出ないこと。

## サプライ

### 目的

素材または企業を 1 つ選び、上流の原料から下流の最終製品までの経路、製造企業と能力シェア、輸入相手国、および月次の生産・輸出入推移を把握する。

### 要素

画面は上から操作行、左のマップ、右（スマートフォンでは下シート）の詳細パネルで構成する。

#### 1. 操作行（`#supply-controls`）

操作行には左から以下の部品を並べる。

| 部品 | DOM ID | 内容 |
|---|---|---|
| 検索欄 | `#supply-q`・`#supply-names` | 素材名・社名・証券コードの検索入力欄である。`<datalist id="supply-names">` に全素材名と全企業名（上場企業は `<社名> <4桁コード>`）を候補として並べる |
| 全体表示ボタン | `#supply-reset` | 選択と検索語を解除して全体表示に戻すボタンである |
| 線をまとめる切替 | `#supply-merge` | 同じ素材ノードから出るエッジを 1 本の幹に束ねるチェックボックスである（既定オン） |
| 凡例 | なし（`.supply-legend`） | 4 つの `kind`（原料・中間財・最終製品・リサイクル資源）の色見本と、「使い終わると回収」の循環アイコンを並べる |

#### 2. サプライチェーンマップ（`#supply-map`）

白地に角丸なしの `1px` 罫線を引いた領域内に、上流（左）から下流（右）へ素材ノードと直角折れ線エッジを描画する。配置計算には `elkjs` `0.9.3`（`layered`・`RIGHT`・`ORTHOGONAL`・`NETWORK_SIMPLEX`、`#supply-merge` がオンなら `mergeEdges=true`）、描画には `Cytoscape.js` `3.30.2` を使い、どちらもサプライタブを初めて開いたときに `unpkg` から遅延読み込みする。

ノード幅は素材名の描画幅を計測して決める。`returns` の出どころ（使い終わると回収される素材）にはノード右端に紫の循環矢印アイコンを描き、その分だけノード幅を `14px` 広げる。`kind` ごとの塗りと枠線の配色は以下のとおりである。

| `kind` | 表示ラベル | 背景色と枠線色 |
|---|---|---|
| `raw` | `原料` | アンバー系（背景 `#fdf1de`・枠線 `#b37314`） |
| `mid` | `中間財` | 青緑系（背景 `#e3f0f4`・枠線 `#2f7489`） |
| `prod` | `最終製品` | 緑系（背景 `#e6f2e0`・枠線 `#4a8a37`） |
| `recycled` | `リサイクル資源` | 紫系（背景 `#efe9f8`・枠線 `#6f4fb0`） |

#### 3. 素材の詳細パネル（`#supply-panel`・`#supply-body`）

素材を選択したときは、`#supply-body` の上部に素材名、`kind` バッジ、`上流 M ・ 下流 N` の件数を出し、その下にスクロール時も上端に固定（`position: sticky`）されるタブ行（`概要`・`企業 n`・`輸入元`・`推移`）を置く。`企業` タブの `n` は製造企業数（`0` 社のときは数字を付けない）であり、`輸入元` タブは国別輸入データが存在する素材のみ API 取得完了後に表示する。選択タブは別の素材を選び直しても維持し、遷移先に該当タブが無いときだけ `概要` に戻す。

各タブの表示内容は以下のとおりである。素材チップはすべて `supply_chain.json` の定義順に並べる。

| タブ | 表示要素と規則 |
|---|---|
| `概要` | `note`（ある場合）、`直接の原料`、`これから作られるもの`、`元をたどった原料`（`raw`・`recycled` の祖先。選んだ素材自身が `raw` または `recycled` なら見出しごと出さない）、`行き着く最終製品`（`prod` の子孫。下流ノードが 0 件なら見出しごと出さない）、`回収元`（選んだ素材が `recycled` のときのみ）、`使い終わると`（`returns` の行き先がある素材のときのみ）の順に素材チップを並べる。該当が 0 件の欄には `なし` を出す |
| `企業` | `作っている企業` の企業チップ（上場企業は 4 桁コードを添える）を、出典ありを先・出典未確認を後にそれぞれ `supply_companies.json` の企業順で並べる。出典未確認チップは点線枠とし、下に `点線は出典未確認（n 社）` を出す。続けて能力表がある素材には、表ごとに `<label>のシェア`・表の `note`・ドーナツチャート・全社一覧表（`table.sheet`、列は左から色ドット付き `会社` または `グループ`・`能力`・`シェア` 小数 1 桁 `%`）・出典行（`<単位>・YYYY年M月末・<出典リンク>`）・`親会社でまとめる` チェックボックスを出す |
| `輸入元`（`#supply-countries`） | 見出し `輸入元の国` の下に、ドーナツチャートと 2 列の凡例表（`table.sheet`、見出し行なし、左列が色ドット付き国名・右列が小数 1 桁 `%` のシェア）を並べ、下に `YYYY-MM〜YYYY-MM（最新月は速報）の輸入量 <合計> <単位>・普通貿易統計（品別国別表）` を出す（速報を含まないときは `（最新月は速報）` を省く）。同じ割合を二度読ませないため、凡例表に数量列は置かず、区画と行の `title` 属性に `<数量> <単位>` を入れる |
| `推移` | 見出し `月次の生産・輸出入` の下に `#supply-monthly` を置く（詳細は次々項） |

ドーナツチャートと「親会社でまとめる」の規則は以下のとおりである。

- 生産能力シェアのドーナツチャートは、能力上位 5 社に固定順の 5 色（青 `#2a78d6`・橙 `#eb6834`・青緑 `#1baf7a`・黄 `#eda100`・桃 `#e87ba4`）を割り当て、6 位以下を灰色の `その他 n 社` 1 区画にまとめる（表側の色ドットは 6 位以下も灰色とし、各表内の順位で色を振る）。区画間は `2px` の白線で区切り、中央に合計値と単位を表示し、区画の `title` に `<社名> <能力> <単位>（<シェア>%）` を入れる。
- 輸入元のドーナツチャートは、上位 5 か国のうちシェア `0.1%`（`0.001`）以上の国を同じ 5 色で出し、残りを灰色の `その他 n か国` にまとめる。中央には直近 12 か月合計を 2 段で `<丸めた合計>` と `<単位>・12か月計` として出す（`1万` 未満は整数、`1万` 以上 `100万` 未満は小数 1 桁の `万`、`100万` 以上 `1億` 未満は整数の `万`、`1億` 以上は小数 1 桁の `億`）。
- `親会社でまとめる` をオンにすると、`parent_id` を最上位まで辿った親会社ごとに能力を合算し（`50%` 超出資の合弁は全量を親会社に寄せる）、表の 1 列目の見出しを `グループ` に変える。オン・オフの状態はタブを開いている間すべての能力表で共有し、ページ再読込で既定（オフ）に戻る。

#### 4. 企業の詳細パネル（`#supply-panel`・`#supply-body`）

企業を選択したときは、`#supply-body` の内容を企業パネルに差し替え、上から以下の要素を並べる。`生産能力` は該当する能力表が無い企業では見出しごと省略し、それ以外のチップ欄で該当が 0 件のときは `なし` を表示する。

| 順序 | 要素 | 内容 |
|---|---|---|
| 1 | 見出しと株価リンク | 社名と区分バッジ（`上場 <4桁コード>`・`非上場`・`海外`）を出す。上場企業には `#supply-chart-link`（`株価を開く`）を添える |
| 2 | 補足文 | `note` がある場合のみ表示する |
| 3 | `作っている素材` | 製造する素材のチップを `supply_chain.json` の素材順で並べる（出典未確認は点線枠） |
| 4 | `生産能力` | その企業が載る能力表がある場合のみ `table.sheet` を出す。列は左から `品目`（表の `label` から末尾の `生産能力` を除いた名前）・`能力`・`単位`・`シェア`（表全体に対する小数 1 桁 `%`）である |
| 5 | `親会社` または `出資者` | `owners` がある合弁会社は見出しを `出資者` として出資比率（`%`）付き企業チップを並べ、`parent_id` のみの会社は見出しを `親会社` として親会社チップを出す |
| 6 | `子会社・出資先` | その企業を `parent_id` に持つ子会社チップと、`owners` に含む出資先チップ（出資比率 `%` 付き）を並べる |
| 7 | `販売先`・`仕入先` | `trade` の売り手が自社である相手を `販売先`、買い手が自社である相手を `仕入先` として企業チップで並べる |
| 8 | 出典行 | 自社の `source`、`makes` の `source`、自社が関わる `trade`（販売先・仕入先の両方）の `source` を重複なく集め、`出典: <title を " / " で連結>（確認 <checked を " / " で連結>）` を出す。1 件も無ければ `出典未確認` を出す |

#### 5. 月次の生産・輸出入（`#supply-monthly`）

`推移` タブ内の `#supply-monthly` には、上から単位表示（`#supply-unit`）、2 行分の高さを確保した凡例（`#supply-legend`）、`lightweight-charts` の折れ線グラフ（`#supply-chart`）とホバー吹き出し（`#supply-tip`）、全系列の一覧表（`table.sheet`）、操作ヒント文（`指標を押すと選んだ指標だけ（複数可）。もう一度押すと外す`）を並べる。

折れ線グラフと一覧表の表示規則は以下のとおりである。

- 初期状態では、`生産`・`輸入`・`輸出`・`原油処理`・`国内向販売`・`見掛け消費` のうち、`生産` と同じ単位（`生産` が無い素材は先頭系列の単位）を持つ系列を描画する（`出荷` と `月末在庫` は既定では描かない）。
- 複数単位の系列を同時に選んだときは単位ごとに縦軸を分け、1 つ目の単位を右軸、2 つ目を左軸、3 つ目以降を目盛りなしとし、`#supply-unit` に `単位 <u1>（右） / <u2>（左） / <u3>（目盛りなし）` を出す（単一単位なら `単位 <unit>`）。
- 横軸の目盛りは年変わりを `YYYY年`、月を `M月` とし、水平グリッドの値ラベルは出さない。グラフ上にポインタを乗せると、ポインタ位置の横（グラフ右半分にあるときは左側）に `#supply-tip` を出し、対象月（`YYYY-MM`）と描画中の全系列のその月の値（値がない系列は `` `–` ``）を並べる。ポインタが離れると吹き出しを隠す。
- 下の表は全系列を `生産`・`出荷`・`月末在庫`・`輸入`・`輸出`・`原油処理`・`国内向販売`・`見掛け消費` の順で並べ、列は左から色ドット付き `指標`・`最新月`（`revision == 1` の速報月なら先頭に `速報` バッジを付ける）・`値`・`単位` とする。統計ごとに公表時期が異なるため、系列間で最新月は必ずしも一致しない（石油製品 7 素材は全指標が速報から揃うため最新月が一致するが、原油は国内生産が確報のみのため速報段階では他の指標より遅れる）。

### 操作

画面上の選択・検索・マップ操作・グラフ操作に対する動作は以下のとおりである。

- 素材を選択したときは、その素材の祖先・子孫と経路上のエッジを強調表示（選択ノードは青太枠、経路エッジはアクセント色 `#0077b6` で太くノードより前面に描画）し、それ以外を薄くする。選択した素材に `returns` の相手（リサイクル資源なら回収元、製品なら回収先）があるときは、経路外であっても薄くせず紫の太枠（`.ret`）で残す（閉路を一周して系統全体が残るのを防ぐため、`returns` の先へは展開しない）。輸入相手国はマップ上のノードとしては置かない。
- 検索欄またはチップから素材を選んだときは、強調された経路が収まる位置へマップをアニメーションで寄せる（最大ズーム倍率は `1.2`）。
- 企業を選択したときは、その企業が製造する素材ノードを青太枠で残し、他のすべてのノードと全エッジを薄くして、対象素材が収まる位置へマップを寄せる。
- 検索欄（`#supply-q`）の確定時は、候補ラベルの完全一致、4 桁証券コード（`^[0-9][0-9A-Z]{3}$`、大文字小文字不問）の一致、素材名の部分一致の先頭、社名の部分一致の先頭の優先順で対象を決める。
- 「線をまとめる」（`#supply-merge`）を切り替えたときは、ELK で再レイアウトしてマップ全体を表示し直す。
- マップはドラッグでパン移動（ノード上からドラッグを始めてもパンでき、動かさずに離したときだけノード選択になる）、ホイールまたはピンチで拡大縮小できる。ノード自体のドラッグ移動は禁止する。ブラウザのピンチズームでページ自体が拡大されている間（`visualViewport.scale > 1.01`）は、マップが 2 本指操作を奪ってページを縮小できなくなるのを防ぐため、マップのパン・ズームを無効化してブラウザ側へ操作を渡す。
- 月次推移の表で指標行をクリックしたときは、選んだ指標（複数選択可）だけを描画して縦軸もそれに合わせる。選択中の行をもう一度クリックすると解除し、すべて解除すると既定の系列に戻る。スマートフォンでグラフ再生成時の高さ `0` によるスクロール跳びを防ぐため、チャート本体は破棄せず系列データだけを差し替える。

### 空とエラー

データ未選択・読み込み中・取得失敗時の表示は以下のとおりである。

| 状況 | 表示場所 | 表示文言と挙動 |
|---|---|---|
| 初回読み込み中 | `#supply-map` 内の `#supply-msg` | `読み込み中…` を表示し、描画準備完了時に要素を削除する |
| 初回 API またはライブラリの読込失敗 | `#supply-msg` | `読み込めませんでした (<エラー内容>)` を表示し、次回タブを開いたときに再試行する |
| 素材・企業とも未選択 | `#supply-body` | `素材を選ぶと、原料と行き先が出ます。` を表示する |
| 概要タブ・企業パネルの各チップ欄が 0 件 | 各見出し直下 | `なし` を表示する（企業パネルの `生産能力` のみ 0 件時は見出しごと非表示） |
| 素材の `作っている企業` が 0 社 | `企業` タブ内 | `まだありません` を表示する |
| 月次統計の読み込み中 | `#supply-monthly` | `読み込み中…` を表示する |
| 月次統計の系列が 0 件 | `#supply-monthly` | `統計の対応がまだありません。` を表示する |
| 月次統計 API の失敗 | `#supply-monthly` | `読み込めませんでした (<エラー内容>)` を表示する |

### スマホと PC

画面幅 `900px` 以上（PC）では、マップの右に幅 `300px` の詳細パネルを横並びで置き、マップの高さを `calc(100vh - 174px)`（最小 `360px`）とする。操作行の凡例は項目の途中で折り返さない。

画面幅 `899px` 以下（スマートフォン）では、マップの下にパネルを置くとスクロールするまで詳細が見えないため、`#supply-panel` を画面下端から出る高さ `45dvh` 固定のボトムシート（上端のつまみ `#supply-grip` とスクロール領域 `#supply-body`）に切り替える。マップの高さはヘッダー（パンくずを含む）と操作行を除いた `calc(100dvh - 210px)`（最小 `300px`）とし、ページ全体の縦スクロールを発生させない。

スマートフォンでのボトムシートとマップ追従の動作は以下のとおりである。

- 素材または企業を選ぶとシートが開き、選択を解除すると閉じる（内容はタブで分かれているため、シートをさらに全画面へ広げる段階は持たない）。
- つまみ（`#supply-grip`）をタップするか、下方向へ `40px` を超えてスワイプするとシートを閉じる。下スワイプは `#supply-grip` 上からは常時、`#supply-body` 上からはスクロール位置が先頭（`scrollTop == 0`）のときだけ受け付ける。シートを閉じても選択状態は残り、マップ上のノードをタップすると再び開く。
- 検索やチップ選択でマップを寄せるときは、マップのうちシートに覆われていない上側領域に収める。経路が長く縮小しすぎると文字が読めなくなるため、ズーム下限を `0.6` とし、下限に当たったときは選択した素材を可視領域の中央に置く。マップ上のノードを直接タップしたときはズームを変えず、そのノードがシートの下に隠れる場合だけマップを上へずらす。

## API

すべてのエンドポイントは本番環境では Cloudflare Access の背後に置く。

### `GET /api/supply/graph`

`config/supply/supply_chain.json` を検証して `{materials: [{id, name, kind, note}], flows: [[from, to]], returns: [[from, to]]}` を返す。`note` が無い素材は `null` とする。プロセス内で初回のみ読み込み（`@lru_cache`）、JSON 変更時はデプロイの再起動で反映する。

### `GET /api/supply/companies`

`config/supply/supply_companies.json` を検証して `{sources: {key: {title, url, checked}}, companies: [{id, name, code, status, parent_id, owners, note, source}], makes: [{company, material, source}], capacities: [{id, materials, label, unit, as_of, source, url, note, rows: [[company_id, value]]}], trade: [{seller, buyer, source}]}` を返す。`parent_id` には `owners`（`50%` 超出資）から導出した親会社も入り、`makes` には能力表由来の組も含まれる。未設定の任意項目は `null` とし、プロセス内で初回のみ読み込む。

### `GET /api/supply/countries/{material_id}`

クエリ `flow`（`import` または `export`、省略時は `import`）を受け取り、保存済みの最新月から遡る 12 か月間の相手国別合計を多い順に `{material_id, flow, unit, from, to, sokuho, total, countries: [{code, name, value, share}]}` で返す。

- `sokuho` は最新月に `revision == 1`（速報）の行を含むかどうかを表す真偽値である。
- 期間内に異なる単位の行が混在する場合は、最新月の単位と一致する行だけを集計する。
- 該当行が 0 件のときは `countries: []`・`total: 0.0`・その他のメタ項目 `null`（`sokuho: false`）を返す。未登録の `material_id` は `404`、不正な `flow` は `400` を返す。

### `GET /api/supply/monthly/{material_id}`

指定素材の月次系列を `{material_id, series: [{metric, unit, sources, points: [[YYYY-MM, value, revision]]}]}` で返す。未登録の `material_id` は `404` を返す。

- `revision` は `1`（速報）・`2`（確報）・`3`（年報）である。系列は `production`・`shipment`・`inventory`・`import`・`export`・`processing`・`domestic_sales`・`apparent` の順に並べ、同じ指標でも単位が異なれば別系列に分ける。
- 同じ指標・同じ単位に複数の `source` がある素材（例: アルミダイカスト・鋳物の `seidou:2560` と `seidou:2550`）は月ごとに合算し、全 `source` が揃わない月は出力しない。`revision` は合算元の最小値とする。
- `apparent`（見掛け消費）は DB に保存せずこの API で算出し、`sources` は空配列、`revision` は構成 4 指標（生産・輸入・輸出・月末在庫）のその月の最小値とする。
- 貿易統計のみをデータ源とする系列（`sources` が `["trade"]` のみ）は、DB に数量 `0` の月が保存されないため、いずれかの素材に貿易統計の当該指標行が存在する公表済みの月を `0.0`（`revision` はその月の貿易統計行の最小値）で補完する。これにより、天然ガスの輸出のように実績がまれな素材でも未公表月と `0` の月を区別して連続系列として描画できる。

## 対象外

以下の項目は現時点では実装せず、対象外または今後の段階的な拡張課題とする。

| 項目 | 扱いと理由 |
|---|---|
| 企業データの全社拡充と生産量シェア | EDINET の有価証券報告書（主要な販売先・関係会社）から `trade` と親子関係を機械抽出して全上場企業へ広げる対応は今後の課題とし、その時点で JSON から DB 管理へ移行する。能力表の無い素材（自動車の月次生産実績や、会社別公開値の無いタイヤ・家電）のシェア表示、および生産能力ではなく実生産量ベースのシェア表示も行わない |
| 統計未対応の素材 | エタン、硫酸の生産、PAN 系炭素繊維、および多くの最終製品の月次統計は未対応とする |
| 工程間の流量表示 | 「直接の原料 → 素材 → 用途」を表すサンキー図は実数が入るまでダミー値では出さず、導入時は按分推計値を斜線で区別する |
| 他系統の追加と系統切替 | 天然ガス化学・非鉄他金属・生物資源などの系統追加、および素材数が数百規模になった際の系統別フィルタは今後の拡張とする |
| 全上場企業の俯瞰マップ | 上場約 4,000 社全体を一度に並べるマップは作らない |
| ダークテーマ | アプリケーション全体がライトテーマ固定のため対応しない |
| 輸出相手国表示と国別月次推移 | API は `flow=export` に対応済みだが画面には出さず、相手国別の月次推移グラフも表示しない |
| 原料を運ぶ海運会社 | 会社 × 航路別の輸送量は公開されず、隻数や傭船契約も機械的に最新状態へ保てないため収録しない |
| 素材ノードの内部展開 | 電子部品の箱を開いてコネクタ・リードフレームから半導体・プリント基板への内部サプライチェーンを見せる階層表示は未実装とする（導入時はタップを選択のまま残し、展開操作を別に設ける） |
