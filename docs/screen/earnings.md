# 決算速報

日ごとの決算発表実績と発表予定を一覧し、1 銘柄の業績推移・通期予想修正履歴・短信原文・決算説明資料・株価チャートを同じ画面で確認するタブ（`#tab-earnings`）の仕様を定める。株価・決算データの取込規則は [株価・決算の取込規則](../jobs/market.md)、画面が呼ぶ API とテーブルの対応図は [画面設計: 決算速報](gen/earnings.md)、共通の見た目とテーブル規約は [画面仕様の共通規則](SPEC.md)、API の共通規約は [API 仕様](api.md) を参照する。

## 誰のための画面か

引け後にその日の開示を上から順に確認したい個人投資家と、翌日以降の決算発表予定を前もって把握したい個人投資家のための画面である。一覧で増減率・進捗率・予想修正・PTS 反応を見比べながら、気になった銘柄の四半期推移と開示原文をその場で掘り下げられる構成とする。

## 画面と遷移

ハッシュは `#earnings` の 1 画面であり、`/app` を開いたときの既定タブである。トップ画面のためパンくずは出さない。

画面内の主な操作と遷移先は以下のとおりである。

| 操作箇所 | 対象要素 | 動作・遷移先 |
|---|---|---|
| 日付ボタン | `#cal-btn` | カレンダーポップアップ `#cal-pop` を開閉する |
| カレンダーの日付セル | `#cal .d` | 指定日の実績開示・発表予定を読み直す（`selectDate`） |
| 決算日の銘柄検索 | `#earn-sym`、`#earn-suggest` | 候補を確定すると直近の実績開示日へ移動して該当行を選択する（実績が無ければ選択を解除してチャートと未開示案内を出す） |
| 銘柄名リンク | `.clicky`（一覧・`#e-chart-title`） | 銘柄タブの株価画面 `#stock/{code5}/price` へ遷移する（`gotoChart`、[銘柄](stock.md)「株価」） |
| 一覧の実績行 | `tr[data-no]` | その開示番号 `disclosure_no` で決算表（4 表）と `#e-chart` を更新する（`selectRow`）。選択中の `#earn-tabs` と `.ftab` のタブ位置は維持する |
| 一覧の予定行 | `tr[data-code]` | 直近開示 `latest` があればその開示番号で決算表と `#e-chart` を更新し、無ければ `#e-chart` と未開示案内を表示する（`selectSched`） |
| 業績・ニュース切替 | `#earn-tabs` | 同じ枠内で決算表 `#fin-box` とニュース `#news-wrap` を切り替える |

## データ形

`GET /api/earnings?date=YYYY-MM-DD`（任意の `today=YYYY-MM-DD` で基準日を上書き可能）は、指定日と当日（JST）の前後関係に応じて以下の 3 種類の `kind` を返す。

| `kind` | 対象日 | 返却データの構成 |
|---|---|---|
| `actual` | 過去日（`date < today`） | 発表済みの `actuals` 配列のみを返す（`scheduled` は空配列） |
| `mixed` | 当日（`date == today`） | 発表済みの `actuals` と、その期にまだ短信本体が出ていない未発表の `scheduled` を両方返す |
| `scheduled` | 未来日（`date > today`） | 発表予定の `scheduled` 配列と、J-Quants がその四半期の予定表を公開済みかを表す真偽値 `ready` を返す |

各レコードの対象範囲と付与データの規則は以下のとおりである。

| 対象項目 | 規則 |
|---|---|
| REIT の除外 | `stocks.product_category` が `'013'` または `'022'` の銘柄は、一覧とカレンダー件数の両方から除外する |
| 決算短信本体への限定 | `actuals` は 1 開示 1 行とし、売上・営業利益・経常利益・純利益のいずれかに実績値がある開示のみを載せる。業績予想修正・配当予想修正のみの開示は一覧にもカレンダー件数にも含めない |
| 古い訂正短信の除外 | 過去の訂正短信のうち、期末日 `CurrentPeriodEndDate` が開示日より 180 日超前の行は一覧とカレンダー件数から除外する（KAB-278） |
| 過年度の遡及修正判定 | 当期短信の前期欄と過年度短信の実績が食い違う銘柄には `restated: true` を付ける（KAB-402）。比較は同一会計基準（`AccountingStandards`）どうしに限定し、日本基準から IFRS への移行などは遡及修正とみなさない |
| PTS 価格の対応づけ | `pts_snapshots` から銘柄ごとの最新 `fetched_at` 行を引く。引け後開示（`disclosed_time >= "15:30"`）には `session == "night"` かつ `trade_date >= disclosed_date` の夜間 PTS のみを対応づけ、場中開示（`disclosed_time < "15:30"`、時刻空欄を含む）には `trade_date == disclosed_date` の昼・夜どちらの PTS も対応づける。未来日の開示には付けない。基準値 `ref` は `pts_snapshots.ref_price` を優先し、無ければ開示日以前の直近 `daily_prices.close` を使う |
| 発表予定行の構造 | `scheduled` は 1 銘柄 1 行とし、`periods: [{fy_end, fq}]`（同日に本決算と来期 1Q 予定が重なる場合は複数要素）と直近実績開示の要約 `latest`（`disclosure_no`・`period`・`fiscal_year_end`・`fy_label`・`qoq`・`yoy`・`single`・`cumulative`・`forecast_fy`・`progress`）を持つ |
| 当日の未発表突合 | 当日の `mixed` における未発表判定は `(code, fq)` 単位で突き合わせる。予定と同じ四半期の短信本体が開示された時点で `scheduled` から消え、予想修正だけでは消えない。予定表に無かった銘柄が当日開示した場合は `actuals` にそのまま加わる |

## カレンダー

### 目的

月内の決算発表件数と未発表予定件数を日別に俯瞰し、確認したい日付へ素早く切り替える。

### 要素

一覧上部の `.phead-right` にカレンダーアイコンボタン `#cal-btn` を置き、開くとポップアップ `#cal-pop` を出す。`#cal-pop` の上部 `.row` には前月ボタン（`◀`）・月見出し `#cal-title`（`YYYY年M月`）・翌月ボタン（`▶`）を並べ、その下に日曜始まりの 7 列グリッド `#cal` を描く。

各日付セル `#cal .d` の状態と件数バッジは以下のとおりである。

| 要素・クラス | 表示内容と条件 |
|---|---|
| `.d.empty` | 当月外の前後マスを空欄にする |
| `.d.today`・`.d.sel` | 当日に `.today`、現在選択中の日付に `.sel` を付ける |
| `.cnt` | 過去日と当日の確定開示銘柄数（distinct）が 1 件以上のとき、右下にアクセント色（`--accent`）で `N件` と出す |
| `.cnt.sched` | 未来日の発表予定銘柄数が 1 件以上のとき、右下に `--sub` 色で `N件` と出す |
| `.cnt.pend` | 当日に未発表の予定銘柄が 1 件以上残るとき、左下に `--warn` 色で `+N`（`件` なし）を添える |

開示も予定も 0 件の日はバッジを出さず、日付の数字のみを表示する。

### 操作

`#cal-btn` を押すと `#cal-pop` を開閉する。前月・翌月ボタンを押すと `GET /api/earnings/calendar?month=YYYY-MM` を呼んでカレンダーの月だけを更新し、背後の一覧の日付は変えない。

日付セル `.d` を押すとその日付で `selectDate` を実行し、`#cal-pop` を閉じる。`Escape` キーの押下、`#cal-btn` の再クリック、または `#cal-wrap` の外側クリックでも `#cal-pop` を閉じる。

### 空とエラー

月内に開示も予定も 1 件も無いときは、全日付セルを数字のみで表示する。`GET /api/earnings/calendar` が失敗したときは `#cal` を書き換えない。

### スマホと PC

PC・スマホとも `#cal-btn` の直下右揃えに最大幅 `300px`（`min(300px, calc(100vw - 24px))`）の絶対配置ポップアップとして開く。

## 決算日の銘柄検索

### 目的

証券コードまたは銘柄名から、その銘柄の直近の決算発表日へ直接移動する。

### 要素

日付見出しの下の `.row` に検索入力 `#earn-sym`（`placeholder="銘柄名 or コード"`）と候補リスト `#earn-suggest`（`.suggest`）を置く。各候補 `div` は `{4桁コード} {銘柄名}` を 1 行で並べる。

### 操作

入力変更（`input`・`compositionend`）ごとに `GET /api/stocks/search?q=…` を呼び、最大 20 件の候補を表示する。候補のクリックまたは `Enter` キー（先頭候補を選択）で確定し、`Escape` キーまたは外側クリックで候補を閉じる。

候補を確定すると `GET /api/earnings/detail/{code}` を呼び、`disclosed_date` が返ればその日へ `selectDate` で移動して該当行を選択する。実績開示が無い（`404` 等の）銘柄では選択を解除し、`loadSched` で株価チャートと `まだ開示されていません` の案内を表示する。

### 空とエラー

入力が空文字のとき、検索結果が 0 件のとき、または検索 API が失敗したときは `#earn-suggest` を空にして非表示にする。

### スマホと PC

PC・スマホとも一覧上部の `.row` に幅 `200px` で配置する。

## 一覧

### 目的

選択した日の発表済み銘柄と未発表予定銘柄を一覧し、業種・四半期での絞り込み、比較軸（累計・3 か月・進捗率）の切り替え、列ソートで横断比較する。

### 要素

パネル上部に日付見出し `#earn-title` と件数 `#earn-count`、その下に銘柄検索、業種チップ列 `#earn-groups`、表示枠 `.earn-box`（表示切替 `#earn-view`、四半期チェックボックス `#earn-qf`、およびスクロール枠 `#earn-list` 内のテーブル `#earn-tbl` `table.sheet`）を置く。

見出し・件数・絞り込みコントロールの表示規則は以下のとおりである。

| 要素 | 表示規則 |
|---|---|
| `#earn-title` | 過去日と当日は `YYYY-MM-DDの決算発表`、未来日は `YYYY-MM-DDの決算発表予定` を出す（初期 HTML は `日付を選択してください`） |
| `#earn-count` | 当日の `mixed` で実績と未発表が両方あるときは `N件・未発表 M`、実績のみまたは予定のみの日（未来日を含む）は `N件`、0 件またはエラー時は空文字にする |
| `#earn-groups` | 先頭に `すべて` を置き、その日の銘柄数が多い上位 5 業種を件数付き `.mchip` で並べる。6 業種以上ある日は `他 N業種` / `閉じる` チップで残りの業種を開閉する |
| `#earn-qf` | `1Q`・`2Q`・`3Q`・`4Q` の 4 つのチェックボックス（既定はすべて ON）とする。`FY` は `4Q` として扱う。予定行は `periods` のいずれかが一致すれば残し、`periods` が空のときは `latest.period` で判定する |
| `#earn-view` | `累計`（`data-view="cum"`、既定）・`3か月`（`q`）・`進捗率`（`prog`）の 3 択とする |

`#earn-tbl` は左端 3 列を `pinCols`（`pin0`〜`pin2`）で固定し、以下の 9 列を並べる。

| 列名 | `data-sort` | 上段の表示 | 下段 `.g`・バッジ・補足 |
|---|---|---|---|
| `時刻` | なし | 実績行は `disclosed_time` の `HH:MM`、予定行は `–` | 実績行は下段に予想修正バッジ・訂正バッジを並べる |
| `決算期` | なし | 期末ラベル `fyShort`（例: `26.3`） | 四半期バッジ（`1Q`〜`3Q`、本決算は `通期`）または予定・実績バッジを並べる |
| `銘柄` | なし | `shortName` の先頭 5 文字（PC 表示は 10 文字）のリンク `.clicky`（`title` に正式名称） | 4 桁コードを出す |
| `売上` | `net_sales` | 百万円単位の実数（`prog` 時は進捗率 `XX.X%`） | `cum` は前年同期累計比（YoY）、`q` は前四半期単独比（QoQ）、`prog` は通期予想または実績額を出す |
| `粗利` | `gross_profit` | 百万円単位の実数（`prog` 時は `–`） | 売上と同じ規則の増減率を出す |
| `営利` | `operating_profit` | 百万円単位の実数（赤字は `.loss`、`prog` 時は進捗率） | 売上と同じ規則の増減率を出す |
| `経利` | `ordinary_profit` | 百万円単位の実数（欠損は `–`、`prog` 時は進捗率） | 売上と同じ規則の増減率を出す |
| `純利` | `net_income` | 百万円単位の実数（赤字は `.loss`、`prog` 時は進捗率） | 売上と同じ規則の増減率を出す |
| `PTS` | `pts` | PTS 現在値。PTS 無し・予定行は `–` | 基準値比 `+X.XX%` または `-X.XX%`（正は `.pos`、負は `.neg`）を出す |

`時刻` 列の下段に付く補助バッジと予定行の表記規則は以下のとおりである。

| バッジ・行種別 | 条件と表示内容 |
|---|---|
| `上方`・`下方` | 通期営業利益予想（`fy_operating_profit`）を、同じ事業年度（`fiscal_year_end` が同じ）の直前の時点の予想と比べ、`+0.1%` 以上なら `.qb-up` の `上方`、`-0.1%` 以下なら `.qb-dn` の `下方` を出す（`title` に `通期営業利益予想 +X.X%`。`±0.1%` 未満は出さない）。売上・経常利益・純利益は見ない。直前の時点の予想は、同じ年度の開示を古い順に畳んで作る: 予想修正の空欄は前の値のまま、決算短信の空欄は未定で予想なし、営業利益の取り下げの印（[株価・決算の取込規則](../jobs/market.md)「予想の取り下げの印」）がある開示の後は予想なし。`1Q`・`3Q` 型の業績予想修正（四半期の速報値、KAB-553）と、その短信と同じ日の予想修正のみの開示は畳まない。直前の予想が無い・`0` のとき、今回の予想が空のときは出さない（今期予想を初めて出した開示や、未定・取り下げの後に予想を出し直した開示を含む）。本決算（`FY`）の短信は当期予想が空なので出さず、本決算の来期予想（`NxF*`）とは比べない。赤字予想は直前の絶対値を分母にし、損失の縮小を `上方` とする（KAB-279・KAB-407・KAB-551） |
| `訂正` | `restated: true` の実績行に `.qb-rev` の `訂正`（`title="既出期間の訂正"`）を出す（KAB-402） |
| 予定行（`latest` あり） | 直近開示の期末・数値と `{Q}実績` バッジ（灰 `.b-lt`、例: `1Q実績`）を出し、予定本来の期は `title`（例: `予定: 27.3 2Q`）に入れる |
| 予定行（`latest` なし） | 予定の期末（複数期ある場合は `/` 区切り）と `.b-sc` の `{Q}予定` バッジを並べ、数値列はすべて `–` とする |

`#earn-view` が `3か月`（`q`）のとき、`1Q` の行は前期 4Q 単独との比較になるため、5 指標のセルに `title="前期4Q単独比"` を付ける。予定行には予想修正バッジ・`訂正` バッジを出さない。

### 操作

列見出し `th[data-sort]` を押すとソートが切り替わり、降順→昇順→解除の順で回る。

5 指標のソートキーは、`cum` では前年同期累計比 `yoy`、`q` では前四半期単独比 `qoq`、`prog` では進捗率を使う。`pts` は `change_pct` で並べ、欠損値（`null`）は昇順・降順ともに末尾へ送る。当日の `mixed` では常に実績行の組を先、未発表予定行の組を後に固定し、各組の中でソートする。

ソート状態 `earnSort` は `#earn-view` 切替・業種チップ・四半期フィルタ・日付切替をまたいで保持する。列ソートと `#earn-view` 切替では選択行と `#earn-list` のスクロール位置を維持し（列ソート時は選択行が見える位置へスクロールする）、業種・四半期フィルタ変更時は選択行が絞り込み後に残っていれば維持し、外れていれば先頭行を選び直す。日付を切り替えたときはその日の先頭行（銘柄検索からのジャンプ時は対象銘柄）を自動選択する。

### 空とエラー

一覧が 0 件のときや API 失敗時の表示文言は以下のとおりである。

| 状態 | `#earn-list` の表示 | `#e-chart-title` の表示 |
|---|---|---|
| 過去日または当日で開示・予定とも 0 件 | `開示なし` | `開示なし` |
| 未来日で `ready: true` かつ予定 0 件 | `予定なし` | `予定なし` |
| 未来日で `ready: false` かつ予定 0 件 | `予定未取得` | `予定未取得` |
| 業種チップまたは `#earn-qf` で 0 件 | `該当なし` | 選択済み銘柄の表示を維持する |
| `GET /api/earnings` が失敗 | `取得できませんでした`（`#earn-title` は `YYYY-MM-DDの決算発表`） | `取得できませんでした` |

### スマホと PC

画面幅 `1100px` 以上では `.egrid` の左カラム（`.a-list`）に一覧、右カラム上段に株価チャート（`.a-chart`）・下段に決算表とニュース（`.a-fin`）を置き、`1100px` 未満では 1 カラム縦並びとする。スマホ（`640px` 以下）でも 9 列を省略せず横スクロールとする。

## 決算表

### 目的

選択した銘柄について、同一四半期累計の過年度比較・直近 12 四半期の 3 か月単独推移・通期進捗率の過年度比較・通期業績予想の修正履歴を確認する。

### 要素

`.a-fin` 上部の `#earn-tabs` で `業績` が選ばれているとき、`#fin-box` を表示する。サブタブ `.ftab[data-fin]` で以下の 4 表を切り替える（既定は `累計`、右端に `単位: 百万円` を添える）。

| サブタブ | `data-fin`・テーブル ID | 列構成 | 行構成と計算規則 |
|---|---|---|---|
| `累計` | `cum`・`#cum-tbl` | `決算期`・`売上`・`粗利`・`営利`・`経利`・`純利`・`EPS`・`発表日` | 選択開示と同じ四半期の累計実績を古い順に最大 5 行（過去 4 期 + 当期 `tr.now`）並べ、`tr.sep` の下に予想行 `tr.fc`（`中予`・`通予`）と参考行 `tr.prevfy`（`1Q`〜`3Q` 開示時の前期通期実績）を置く |
| `3か月` | `q`・`#q-tbl` | `累計` と同じ 8 列 | 直近最大 12 四半期の 3 か月単独実績を古い順に並べ、最新行を `tr.now` とする。`決算期` は当該 3 か月期間のラベルと四半期バッジを出し、下段 `.g` は前年同期単独比（YoY）とする |
| `進捗率` | `prog`・`#prog-tbl` | `決算期`・`売上`・`営利`・`経利`・`純利`・`発表日` | `累計` と同じ最大 5 期（当期は `tr.now`）について、完了期は通期実績に対する累計進捗率、進行中の当期は最新通期予想に対する累計進捗率を出し、下段 `.g` の `.base` に分母（通期実績または通期予想）の百万円実額を添える |
| `修正履歴` | `rev`・`#rev-tbl` | `決算期`（下段に種別バッジ）・`発表日`・`売上`・`営利`・`経利`・`純利`・`EPS` | 直近 `revision_history_years`（`4`）年度の通期業績予想の推移と通期実績を古い順に並べ、年度境界の行に `tr.sep`、選択開示と同日の行に `tr.now` を付ける（KAB-406）。`1Q`・`3Q` 型の業績予想修正（四半期の速報値）は予想欄が四半期の累計値なので並べない（KAB-553） |

各表の詳細な計算・表示規則は以下のとおりである。

| 項目 | 計算・表示規則 |
|---|---|
| `累計` の予想行 | `1Q`〜`3Q` 開示では当期の中間予想・通期予想を出し、増減率はそれぞれ前期 2Q 累計実績・前期通期実績と比較する（2Q 通過後に中間予想欄が空なら `中予` 行を省く）。本決算（`FY`・`4Q`）開示では来期の予想（`raw_json` の `NxF*`、期末は `NxtFYEn`）を出し、増減率は当期 2Q 累計実績・当期通期実績と比較する。過去を含め中間予想を出さない銘柄（`notes.half_forecast: false`）で中間予想が空のときは `中予` 行を出さない。予想行の `粗利` と `発表日` は常に `–` とする |
| `3か月` の差分計算 | `2Q`〜`4Q` は同一年度の直前四半期累計との差分で求め、直前四半期が欠けている期は単独値を欠損とする。決算期変更（変則決算）の期は同一年度内の連続四半期であれば差分を取り、前年度との YoY は算出しない |
| `粗利`（`app/xbrl/gross_profit.py`）と利益率 | `粗利` は XBRL から取得し、日本基準の段階利益 `GrossProfit` が無い IFRS 等の開示では売上と売上原価の対（差が正かつ売上の `105%` 以下）から算出する。粗利概念の無い業種や XBRL 未収録期は `–` とする。`累計`・`3か月` の `粗利` と `営利`（および `修正履歴` の `営利`）には、売上が正のとき右隣に薄い括弧 `.opm`（例: `10,771(13.4%)`、負の利益率は `.opm.loss` で赤字と同じ `--loss`）で対売上比率を添える |
| `経利` 列の減光 | `累計` と `3か月` の全行で `ordinary_profit` が空の銘柄（`notes.no_ordinary: true`）や、`修正履歴` の全行で `ordinary_profit` が空の銘柄では、`経利` 列の見出しとセルに `.dim` を付けて薄くする |
| `発表日` の表記 | `YY/MM/DD` 形式で出し、過年度の遡及修正値から補った行（`source == "restated"`）では `–` とする |
| `修正履歴` の `種別`（`app/revisions.py`・`app/market/revisions.py`） | 年度の最初の予想に `期初`（`forecast_initial`、前期末から `100` 日以内の開示）または `予想`（`forecast`、それより後。どちらも `.qb-init`）、損益（売上・営業利益・経常利益・純利益）が前の行から変わった予想に `修正`（`forecast_revised`、`.qb-mod`）、予想の取り下げに `取下`（`forecast_withdrawn`、`.qb-wd`）、通期実績に `実績`（`actual_fy`、`.qb-act`、行は `tr.act`）を付ける。損益が変わらない開示（EPS だけの変化を含む）は行にしない。下段には前の行からの修正率を出し、同じ値は `→` とする。各行の値は、共通の層（`app/market/forecasts.py`）で開示を古い順に畳んだその年度のその時点の予想で、予想修正で出し直していない項目は前の値のまま、決算短信の空欄は未定（`–`）、取り下げの印がある項目は `–` になる。予想 EPS は開示に書かれた値だけを使い、純利益から割らない。年度は本決算の短信の予想が来期（`NxtFYEn`）、それ以外は開示の `fiscal_year_end`。`(年度の始まり, 四半期)` と `(年度末, 四半期)` の両方で既に見たそれぞれの最新より前の決算短信（過年度の訂正の再提出、遅れて出た過去の期の短信、同じ年度の前の四半期の訂正）は予想に使わない（年度の始まりは `fiscal_year_start`、空なら `fiscal_year_end` の 1 年前の翌日）。決算期変更で年度末が早まった短信は年度の始まりのキーで前でないので使い、本決算の来期予想がその年度の `期初` の行になる（`60850` の 2026-04-17 の本決算など）。`fiscal_year_start` が誤っている行の後の短信も年度末のキーで前でなければ使う（`62090`・`29010`）。`取下` の行は取り下げた項目を `–` にして修正率を出さず、すべての損益を取り下げた後に予想を出し直した行は直前の値が無いので `予想` として修正率を出さない。既定は J-Quants の予想値（`rev_source=jquants`）で、`rev_source=xbrl` を指定すると TDnet XBRL の予想（レンジは下限と上限の中点）を使う。XBRL を使うときは取り下げの印を見ないので `取下` の行は出ない |

### 操作

`.ftab[data-fin]` ボタンで 4 表を切り替える。`#e-chart-title` の銘柄名リンクを押すと銘柄タブの株価画面 `#stock/{code5}/price` へ遷移する。

### 空とエラー

選択行の状態に応じた 4 表の表示文言は以下のとおりである。

| 状態 | 表示文言 |
|---|---|
| 予定行で直近開示 `latest` が無い銘柄 | 4 表すべてに `まだ開示されていません` を出す |
| 本決算（`FY`・`4Q`）開示時の `#prog-tbl` | `本決算は進捗率なし` を出す |
| 決算期変更等で `3か月` が算出不能（`notes.single_unavailable: true`） | `#q-tbl` に `算出不能 (決算期変更など)` を出す |
| 実績行または修正履歴が 0 件 | `#cum-tbl`・`#q-tbl`・`#prog-tbl` は `データなし`、`#rev-tbl` は `修正履歴なし` を出す |

### スマホと PC

各表は `.tbl-wrap` で横スクロールでき、左端列（`決算期`）を `position: sticky` で固定する。

## ニュース

### 目的

決算速報タブに留まったまま、選択中銘柄の決算短信・予想修正の原文と決算説明資料を閲覧する。

### 要素

`#earn-tabs` で `ニュース` を選ぶと `#fin-box` を隠して `#news-wrap` を表示する。一覧枠 `#en-list` には `#en-news`（`table.sheet`、列は `日時`・`種類`・`題名` の 3 列）とメッセージ `#en-msg` を置き（表の枠 `.tbl-wrap` は画面の高さで縦スクロールさせ、列見出し `thead` を上端に固定する）、行の組み立ては銘柄タブの `stockNewsRows`（[銘柄](stock.md)「ニュース」）と共有する。

詳細枠 `#en-detail` には戻るリンク `#en-back`（`← ニュース`）、見出し `#en-head`、PDF 変換短信の出典注記 `#en-src`（`出典: IR BANK（TDnet）。PDF から変換した原文（画像は出ません）`）、原文枠 `#en-doc`、および説明資料枠 `#en-deck` を置く。

### 操作

`ニュース` タブを開いたときに `GET /api/stock/{code}/filings` と `GET /api/stock/{code}/decks` を並列に呼んで `#en-news` を描画する。同じ銘柄を選択している間は取得済みキャッシュを使い回し、別銘柄へ切り替えたときにキャッシュと表示状態をリセットする。

一覧の行を押すと `#en-list` を隠して `#en-detail` を開き、短信・修正はサニタイズ済み HTML の `iframe` を `#en-doc` に、説明資料は `GET /api/stock/{code}/decks/{key}` から組み立てた要約・表・グラフ（`deckDocHtml`）を `#en-deck` に描画する。`#en-back` を押すと一覧へ戻る。

### 空とエラー

ニュース一覧および詳細の空・エラー文言は以下のとおりである。

| 状態 | 表示先と文言 |
|---|---|
| 短信・説明資料がともに 0 件 | `#en-msg` に `ニュースがありません。` を出す |
| 一覧 API（`filings`・`decks`）が失敗 | `#en-msg` に `読み込めませんでした。` を出す |
| 選択した短信に書類が無い | `#en-head` に `書類が見つかりません。` を出す |
| 選択した説明資料が `404` | `#en-head` に `説明資料が見つかりません。` を出す |
| 説明資料 API が `404` 以外で失敗 | `#en-head` に `読み込めませんでした。` を出す |

### スマホと PC

`#en-news` の題名列は枠幅に合わせて折り返す。短信 `iframe` と説明資料の表・グラフの表示は [銘柄](stock.md)「ニュースの詳細」および「説明資料」と同じ規則に従う。

## 株価チャート

### 目的

選択中銘柄の直近 1 年間の株価推移・出来高と、決算発表日の位置を確認する。

### 要素

右パネル `.a-chart` に見出し `#e-chart-title`（初期 HTML は `銘柄を選択してください`）、チャート領域 `#e-chart`（高さ `320px`、`chart-core.js` の日足ローソク足・既定 `MA50`・`MA150`・`MA200`・下段出来高）、およびイベント表示切替 `.evt-toggles`（`決算発表` と `月次発表` のチェックボックス、`localStorage` の `chartEventOverlays` で銘柄タブと共有）を置く。月次の印の形と凡例は [銘柄](stock.md)「株価」と同じである。

銘柄選択時の `#e-chart-title` は正式名称のクリックリンク（`gotoChart`）の右に `{4桁コード} / {期末} {期}` を添える（予定行で `latest` が無いときは `{4桁コード}` のみ）。選択した開示の `disclosed_date` には `.evt-toggles` の状態に関わらずアクセント色の `決` マーカーを立て、その開示日が直近 1 年の表示範囲より過去にあるときは開示日を中央に据えて表示する（`showAround`）。

### 操作

チャート上のドラッグやピンチで表示期間を移動・拡縮し、ホバーまたはタップで 4 本値・移動平均・出来高を更新する。`.evt-toggles` の `決算発表` を切り替えると過去の全決算日の `決` が一括で切り替わり、`月次発表` を切り替えると月次の四角と凡例の対象月が一括で切り替わる。

### 空とエラー

株価データが無い銘柄や `GET /api/chart/{code}` の失敗時は `#e-chart` を空にする。選択した日付の行が 0 件または一覧取得失敗のときは、`#e-chart-title` にも一覧と同じ空・エラー文言を表示する。

### スマホと PC

画面幅 `1100px` 以上では右カラム上段に配置し、`1100px` 未満では縦並びで配置する。

## API

エンドポイント共通のエラー形式と一覧は [API 仕様](api.md)、JS と DB テーブルの対応図は [画面設計: 決算速報](gen/earnings.md) を参照する。本タブが利用する API は以下のとおりである。

| エンドポイント | 用途と主なクエリ引数 |
|---|---|
| `GET /api/earnings` | 指定日の実績開示・発表予定を返す。`date`（必須、`YYYY-MM-DD`）、`today`（任意）を受け取る |
| `GET /api/earnings/calendar` | 指定月の日別件数マップを返す。`month`（必須、`YYYY-MM`）、`today`（任意）を受け取る |
| `GET /api/earnings/detail/{code}` | 1 銘柄の累計・3 か月・進捗率・修正履歴を返す。任意の `date`・`disclosure_no`・`rev_source`（`jquants` 既定、または `xbrl`）を受け取り、実績が無ければ `404` を返す |
| `GET /api/chart/{code}` | `#e-chart` 用の日足データと決算発表日配列を返す |
| `GET /api/stocks/search` | `#earn-sym` のインクリメンタル検索候補（`q` 必須、最大 20 件）を返す |
| `GET /api/stock/{code}/filings` | ニュースタブの決算短信・予想修正一覧を返す |
| `GET /api/stock/{code}/decks` | ニュースタブの決算説明資料一覧を返す |
| `GET /api/stock/{code}/decks/{key}` | ニュースタブ内で選択した決算説明資料の要約・数値表を返す |

## 対象外

以下の項目は本画面の対象外とする。

1. 発表予定銘柄の発表予定時刻は扱わない（J-Quants の決算発表予定データに時刻が無いため、実績行のみ `disclosed_time` を表示する）。
2. 開示 PDF ファイルの直接ダウンロード導線は置かない（ニュースタブでは HTML 原文または構造化済みの説明資料を表示する）。
3. アナリストのコンセンサス予想は扱わない。
4. PTS 価格の自動ポーリング更新は行わず、日付選択や再読込のタイミングで取得する。
