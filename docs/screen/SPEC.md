# 画面仕様の共通規則

各タブの見た目と操作は `docs/screen/<タブ名>.md` に 1 タブ 1 ファイルで記述する。画面の一覧・ルート・呼び出す API の対応表は [画面設計](../SCREENS.md)（自動生成）を参照する。

同じ仕様を複数ファイルに重複して書かない。データの取込規則は `docs/jobs/`、テーブル定義は [データモデル](../SCHEMA.md)（自動生成）、実装上の規約は [`AGENTS.md`](../../AGENTS.md) に置く。

## 共通見た目

以下の 12 項目は全タブに適用する。タブ別の仕様書には繰り返さない。金融情報画面として情報密度を優先し、装飾用のフォント・グラデーション・影は追加しない。

### 1. 背景色

ページ背景（`--bg`）と区画背景（`--panel`）は同じ白（`#fff`）に統一する。灰色の背景の上に白いカードを浮かせる配色は使わない。

### 2. 外枠と罫線

タブ全体を角丸・外枠・影で囲まない。決算速報の一覧、銘柄、スクリーナー、月次の外側にカード枠は置かない。チャートや決算表のように領域を区切る必要がある箇所だけ、白地の上に角丸なしの `1px` 罫線を引く。

### 3. コンテンツ横幅

`main` に `1200px` や `1600px` の最大幅制限を掛けず、左右数 px の余白を除いてビューポート幅いっぱいに表示する。

### 4. 表の横幅とスクロール

表は内容に応じた自然幅で組み、`min-width: 100%` で空列を引き伸ばさない。決算表・月次年表・保有者の銘柄一覧のように列数が多い表だけ、枠内の横スクロールでビューポートを使い切る。

### 5. 一覧表の書式と共通フォーマッタ

決算速報・スクリーナー・ランキング・大量保有報告書の一覧表は `table.sheet` クラスで見た目を揃える。数値は `tabular-nums` で桁を揃え、行の上下余白は広げない。見出しは `11px`、本文セルの文字サイズは `table.sheet td` の 1 種類に統一し、上揃え・縞模様・行ホバーを付ける。縦罫は決算速報とスクリーナーのみ銘柄列の右に引き、ランキングには引かない。スマートフォンでの勝手な文字拡大は `text-size-adjust: 100%` で抑止し、`@media (max-width: 640px)` ではタップできる行高を確保する。

表に出す銘柄・保有者・市場・業種はすべて `static/js/api.js` の共通関数を通し、生の文字列をそのまま表示しない（`title` 属性に入れる正式名は除く）。X 投稿用の画像など `<canvas>` に描画するときも市場と業種は同じ関数を使う。市場と業種の呼び出し漏れは `tests/nonfunctional/test_table_labels.py` が検査する。

| 表示項目 | 使う関数 | 表示規則 |
|---|---|---|
| 銘柄名 | `shortName` + `under` | 上段に先頭 5 文字、下段に 4 桁コードを出す。`title` 属性に正式名を入れる |
| 保有者名 | `shortName` + `under` | 上段に先頭 5 文字、下段に EDINET コードを出す。`title` 属性に正式名を入れる。保有目的も 1 行で切り、`title` 属性に全文を入れる |
| 市場区分 | `fmtMarket` | `東証P`・`東証S`・`東証G` と色付きの点（`td.mkt`）に揃える。J-Quants の `プライム` も株探の `東Ｐ` も同じ表記になり、それ以外の市場は元の名前を出す |
| 33 業種 | `fmtSector` | 末尾の `業` を除いた先頭 5 文字を出す（例: `情報･通信業` は `情報･通信`）。`title` 属性に正式名を入れる |

### 6. スマートフォンと PC の共通構造

スマートフォンでも表をカード表示に差し替えず、列も隠さない。画面幅に収まらない列は横スクロールで見せる。画面幅に応じて変えてよいのは余白、文字サイズ、`position: sticky` の有無、同一区画内の折り返しだけである。月次年表の左端固定列は、項目列だけで画面幅を塞ぐ狭い端末でのみ固定を解除する。

### 7. 再読込時のルート復元

ページの再読込時は直前に開いていた画面を復元する（実装は `static/js/tabs.js`）。月次詳細の発行体、銘柄タブの銘柄と中のタブ、ランキングの中のタブも復元対象に含める。個人用ツール（`/app`）は URL ハッシュと `localStorage`（`ui.route`）に経路を持ち、公開月次は URL パス（`/monthly`・`/monthly/{code4}`）で表す。

### 8. アセット更新と古い画面の再読込

配信する HTML（`/app` と公開月次）内の `/static/...` URL には、`app/assets.py` がファイル内容の SHA-256 先頭 12 桁を `?v=` クエリとして付与する。iOS Safari がメモリ上の古い CSS を再検証せずに使い続けるのを防ぐため、ファイル内容が変わるたびに URL 自体を変える。

さらに `static/js/boot.js` は、bfcache からの復元時（`pageshow` の `persisted`）に即座にページを再読込する。タブが 1 分以上バックグラウンドにあった後に復帰したときは、HTML を再取得してレスポンスの `ETag` と `/static/...?v=` の一覧を初期読込時と比べ、変化があれば再読込する（プロキシが `ETag` を外す経路があるため両方を見る）。再読込後の表示位置は項目 7 の仕組みで元の画面に戻る。

### 9. ヘッダー・メニュー・銘柄検索

`/app` のヘッダーにはブランド名を出さず、画面上端の色帯も引かない。`<meta name="theme-color">` は `#fff` に固定し、iOS Safari の上下バーをページと同じ白に揃える。画面全体を覆う `position: fixed` の背景幕やドロワーは使わない（iOS Safari 26 が画面端の固定要素の背景色をシステム枠に取り込み、閉じた後も色が残るため）。

画面幅に応じたヘッダーの配置は以下のとおりである（実装は `static/js/tabs.js`）。

| 要素 | PC（幅 721px 以上） | スマートフォン（幅 720px 以下） |
|---|---|---|
| タブ一覧（`#app-nav`） | ヘッダー内に 1 行で横並びにする | 非表示にし、左端の三本線ボタン（`#menu-btn`）を押したときだけヘッダー直下に縦並びで展開する（本文は下へ押し下げる）。タブ選択・再押下・Esc キーで閉じる |
| 現在の画面表示 | パンくずがある画面はタブ行の下に `nav#crumbs` を出す | `#menu-btn` の右に `nav#crumbs` を出し、パンくずが無い画面は現在のタブ名（`#cur-tab`）を出す |
| wiki リンク（`#wiki-link`） | タブ列の右端に置く（`/app` のみ。`app/assets.py` が HTML に差し込み、公開月次には出さない） | 展開メニューの末尾に置く |
| 銘柄検索（`#sym-btn`） | ヘッダー右端に置く。押すとヘッダー直下に検索欄 `#sym-pop` を開く（詳細は [`docs/screen/stock.md`](stock.md)「銘柄検索」） | PC と同じ右端に置く。銘柄画面自体はメニューのタブに並べない |

### 10. パンくずとブラウザ履歴

パンくず（`nav#crumbs`）は `main` ではなくヘッダー内に置く（公開月次ではサイト名の右）。パンくずが出る画面では `#cur-tab` のページ名を隠す。区切り文字は ` > ` とし、横幅に収まらないときは折り返さずに横スクロールさせ、先頭側を隠して末尾（現在の画面）が見える位置に合わせる。遷移元は URL の `?from=`（`/app` はハッシュ内、公開月次はクエリ）で渡し、`static/js/screens.js` に定義された許可リストと既定の戻り先で解決する。

`/app` のブラウザ履歴（戻る・進む）は `static/js/tabs.js` で制御する。タブまたは対象（銘柄・保有者・月次の発行体・サプライの素材）が変わる遷移、および銘柄ニュース一覧からニュース詳細・説明資料の中身を開く遷移は履歴に積み、戻ったときは前の画面をスクロール位置ごと復元する（取得済みの一覧・ランキングは再取得しない）。同じ画面内のサブタブ切替（銘柄の 5 タブ、ランキングの PTS 切替）と `?from=` のみの変化は履歴に積まず `replaceState` で書き換える。

### 11. スマートフォンでの PC 版表示切替

端末の `screen.width` が `720px` 以下のときだけ、ページ末尾に **PC版を表示** ボタンを出す（`/app` と公開月次の両方、実装は `static/js/view-mode.js`）。押すと `<meta name="viewport">` を `width=1280` に切り替えて再読込し、同じ位置のボタン文言を **スマホ版に戻す** に変える。選択状態は `localStorage`（`ui.pcView`）に保存する。最初から広い画面ではボタン自体を出さない。

### 12. タブ部品の使い分け

画面内の切り替え部品は用途で 2 種類に分ける。

| クラス | 用途 | 見た目 |
|---|---|---|
| `.nav-tabs` | ページ内の独立した画面の切り替え（銘柄の概要・株価・業績詳細・ニュース・株主、決算速報の業績・ニュース） | フォルダ型タブ。選択中は上と左右の枠線で下の内容領域とつなげ、非選択は下線のみを引く。背景は塗りつぶさず、幅 `390px` でも 1 行に収める |
| `.fin-tabs` | 同一区画内の表示値や期間の切り替え（累計・3か月、日足・週足、BS・PL・CF、上昇率・下落率、およびランキング内の `#rk-subs`） | 背景を塗りつぶすピル型タブ |

### 13. グラフの値の札

グラフの値の札（業績詳細・月次・サプライ）は `chartTip`（`static/js/api.js`）を通し、グラフの外をタップするか `Esc` で消す。画面ごとの仕様書にはこの動きを書かない。

## ファイル配置と見出し構成

タブ別の仕様書は `data-tab` 属性の英語 ID と同じファイル名で置く（例: `data-tab="monthly"` は `docs/screen/monthly.md`）。`docs/jobs/` 配下の文書には画面表示の節を作らず、該当する画面仕様ファイルへのリンク 1 文だけを置く。

各ファイルの見出しは以下の順序で並べ、途中の節を省略しない。

1. `## 誰のための画面か`
2. `## 画面と遷移`（画面名・ルート・クリック遷移の一覧）
3. `## データ形`
4. 画面・区画ごとの `##` 見出し
5. `## API`
6. `## 対象外`

4 番目の各画面見出しの下には、以下の 5 項目をこの順で書く。

| 項目 | 書く内容 |
|---|---|
| 目的 | その画面でユーザーが完了させる作業を 1 文で書く |
| 要素 | 表示する部品の名前、並び順（表は左の列から順）、値の出どころ、固定の DOM ID を書く |
| 操作 | クリック・戻る・絞り込みの振る舞いを、条件を先に置いて書く |
| 空とエラー | データ 0 件、未取得、API 失敗のそれぞれで表示する文言を書く |
| スマホと PC | PC と同じ構造か、どこが横スクロールになるか、2 段組にしないかを明記する |

## 画面仕様書に書かないこと

PDF の列割り当て規則、`unit` の正規化、MCP の認証方式、バッチの起動時刻は画面仕様書には書かず、`docs/jobs/` と `deploy/README.md` に置く。未決事項をプレースホルダのまま残さず、実装しない項目はすべて `## 対象外` に移す。
