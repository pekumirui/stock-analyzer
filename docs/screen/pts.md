# PTS

ランキングタブ内の `PTS` サブ画面（`#rk-sub-pts`）の見た目と操作を定める。株探からの取得と保存規則は [株価・決算の取込規則](../jobs/market.md)「PTS ランキング」、親タブの構成は [ランキングタブ](ranking.md)、共通の見た目と配置規則は [画面仕様の共通規則](SPEC.md) を参照する。

## 誰のための画面か

夜間 PTS（ナイトタイムセッション）で大きく動いた銘柄を確認し、翌営業日の東証の寄り付き（始値）が PTS の株価にどれだけ追随したかを確かめたい利用者向けの画面である。

## 画面と遷移

ヘッダーの `ランキング` タブ（`data-tab="ranking"`）を開き、内部サブタブ `#rk-subs` で `PTS`（`data-rksub="pts"`）を選択したときに `#rk-sub-pts` を表示する。ヘッダーに独立した PTS タブは置かない。

経路と遷移の規則は以下のとおりである。

| 項目 | 仕様 |
|---|---|
| 画面 ID とルート | 画面 ID は `ranking-pts`、ルートは `#ranking/pts` とする。`localStorage`（`ui.route`）にも `ranking/pts` を保存し、再読込時に復元する |
| 旧ルートの互換変換 | 旧ルートの `#pts`（URL ハッシュおよび `ui.route`）は `#ranking/pts` に置き換える |
| 銘柄名のクリック | 銘柄タブの株価（`#stock/{code5}/price`）へ遷移する |

## データ形

`GET /api/pts` の 1 スナップショット分の応答をランキング順位（`rank`）順に表示する。各銘柄の翌営業日始値（`next_open`）は `session_date` より後の最初の日足（`daily_prices`）から引き、翌営業日の日次バッチ（`19:30`）が走るまでは `null` となる。

翌始値に関するギャップ指標と追随率の算出式は以下のとおりである。

| 項目 | フィールド名 | 算出式と規則 |
|---|---|---|
| 終値から翌始値への騰落率 | `open_gap_pct` | `(next_open / base_close - 1) * 100`（小数 2 桁丸め） |
| PTS から翌始値への騰落率 | `open_vs_pts_pct` | `(next_open / pts_price - 1) * 100`（小数 2 桁丸め） |
| 追随率 | `follow_ratio` | `(next_open - base_close) / (pts_price - base_close)`（小数 2 桁丸め）。`1` は PTS 価格どおりに寄り付いた状態、`0` は通常取引の終値まで戻った状態を表す。`pts_price == base_close` または値が欠損しているときは `null` とし、画面には `` `–` `` を出す |

## ランキング

### 目的

指定したセッション日・取得時刻における夜間 PTS ランキングと、翌営業日始値とのギャップおよび追随率を一覧で確認する。

### 要素

`#rk-sub-pts` 区画内に、上から操作行、サマリー行、ランキング表を並べる。

1. 操作行には、セッション日セレクト `#pts-date`（新しい順で最大 `60` 日）、ランキング種別の切り替え `#pts-ranking`（`.fin-tabs`、`値上がり` `night_up`・`値下がり` `night_down`・`出来高` `night_volume`、既定は `値上がり`）、取得時刻セレクト `#pts-at`（`MM-DD HH:MM（HH:MM現在）` 形式、`as_of` が空なら括弧なし、新しい順、スナップショット 0 件時は非表示）、および基準情報 `#pts-info`（`` `<セッション日> 終値比 / 翌営業日 <日付または未取込>` ``）を並べる。
2. サマリー行 `#pts-summary` には、翌始値と PTS の比較が可能な銘柄が 1 件以上あるときに `` `翌始値あり <N> 銘柄: PTS→翌始値 平均 <+X.XX>% / 追随率 中央値 <Y.YY>` ``（中央値が欠損なら `` `–` ``）を表示する。該当銘柄が 0 件のときは空にする。
3. ランキング表 `#pts-tbl`（`table.sheet`）の列は左から以下の順に並べる。`%` 表示の列は `0` 以上を赤（`.pos`）、負を緑（`.neg`）で色分けする。

| 列順 | 見出し | 表示内容と書式 |
|---|---|---|
| 1 | `順位` | スナップショット内の順位（`rank`）を表示する |
| 2 | `銘柄` | 上段に先頭 5 文字、下段に 4 桁コードを出し、`title` 属性に正式名を入れる |
| 3 | `市場` | `fmtMarket` で `東証P`・`東証S`・`東証G` と色付きの点に整形する |
| 4 | `終値` | 比較元となる通常取引の終値（`base_close`、小数 1 桁）を表示する |
| 5 | `PTS` | 夜間 PTS の株価（`pts_price`、小数 1 桁）を表示する |
| 6 | `終値比` | 通常取引終値に対する PTS 騰落率（`pts_chg_pct`、小数 1 桁 `%`）を表示する |
| 7 | `PTS出来高` | 夜間 PTS の出来高（`volume`、整数桁区切り）を表示する |
| 8 | `翌始値` | 翌営業日の始値（`next_open`、小数 1 桁）を表示する。売買停止明けなどで `next_date` が表内で最初に `next_date` を持つ行の日付（`#pts-info` に出る翌営業日）と異なる銘柄には、横に小さく `M/D` を添える |
| 9 | `終値→翌始値` | `open_gap_pct`（小数 1 桁 `%`）を表示する |
| 10 | `PTS→翌始値` | `open_vs_pts_pct`（小数 1 桁 `%`）を表示する |
| 11 | `追随率` | 見出しの `title` 属性を `1=PTSどおり、0=終値に戻った` とし、`follow_ratio`（小数 2 桁、算出不可は `` `–` ``）を表示する |

翌営業日の日足が未取込で全行の `翌始値` が無い（夜間セッション中など）ときは、列 8〜11 の見出しとセルに `.dim` を付けて減光する。

### 操作

各コントロールと行の操作に対する動作は以下のとおりである。

- `#pts-ranking` のボタンでランキング種別（`値上がり`・`値下がり`・`出来高`）を切り替えたときは、セッション日を維持したままその組の最新スナップショットを取得して表示する。
- `#pts-date` でセッション日を変更したときは、選択中のランキング種別におけるその日の最新スナップショットを取得して表示する。
- `#pts-at` で取得時刻を選択したときは、同じセッション日・ランキング種別のうち指定した `fetched_at` のスナップショットを取得して表示する。
- 表内の銘柄名をクリックしたときは、銘柄タブの株価（`#stock/{code5}/price`）へ遷移する。

### 空とエラー

データ未投入・該当なし・通信失敗時の表示は以下のとおりである。

| 状況 | 表示場所 | 表示文言と挙動 |
|---|---|---|
| DB 全体に PTS データが 1 件も無い（`dates` が空） | `#pts-info` | `#pts-at` を隠し、`#pts-summary` と `#pts-tbl` を空にして `PTS のデータがまだありません` を表示する |
| 選択したセッション日に当該ランキングのスナップショットが無い | `#pts-info` | `#pts-at` を隠し、`#pts-summary` と `#pts-tbl` を空にして `この日のランキングはありません` を表示する |
| API の失敗 | `#pts-info` | `#pts-tbl` を空にして `読み込みに失敗しました` を表示する |

### スマホと PC

スマートフォンと PC で同じ構造を使う。操作行は画面幅に応じて折り返し、表は内容に応じた自然幅で組んで収まらない分を横スクロールで見せる。左側の 2 列（`順位`・`銘柄`）は `pinCols` で左端に固定し、横スクロールしても銘柄が見えるようにする。表の枠（`.tbl-wrap`）は画面の高さで縦スクロールさせ、列見出しを上端に固定する。

## API

### `GET /api/pts`

クエリ `date`（`YYYY-MM-DD`、省略時は最新の `session_date`）、`ranking`（`night_up`・`night_down`・`night_volume`、省略時は `night_up`、それ以外は `400`）、`at`（`YYYY-MM-DD HH:MM:SS`、省略または不一致時はその組の最新 `fetched_at`）を受け取り、1 回分のランキングとサマリーを返す。

```json
{
  "dates": ["2026-10-16"], "date": "2026-10-16", "ranking": "night_up",
  "snapshots": [{"fetched_at": "2026-10-17 00:00:00", "as_of": "23:45"}],
  "fetched_at": "2026-10-17 00:00:00", "as_of": "23:45",
  "rows": [{"rank": 1, "code": "73600", "name": "オンデック", "market": "東Ｇ",
            "base_close": 711, "pts_price": 900, "pts_chg_pct": 26.58, "volume": 1700,
            "next_date": "2026-10-19", "next_open": 850,
            "open_gap_pct": 19.55, "open_vs_pts_pct": -5.56, "follow_ratio": 0.74}],
  "summary": {"n": 1, "avg_open_vs_pts_pct": -5.56, "median_follow_ratio": 0.74}
}
```

`dates` には `pts_snapshots` に存在する `session_date` を新しい順で最大 `60` 日分入れる。対象セッションまたはスナップショットが存在しない場合は `snapshots: []`・`fetched_at: null`・`as_of: null`・`rows: []`・`summary: null` を返す。スナップショットは存在するが翌営業日の日足が未取込のときは、`summary` は `{"n": 0, "avg_open_vs_pts_pct": null, "median_follow_ratio": null}` となる。

## 対象外

以下の項目は本画面の対象外とする。

- 日中 PTS（デイタイムセッション）のランキングは取得・表示しない。
- 複数セッションをまたいだ追随率の統計集計は画面で行わない（オフライン分析用の `analyzer/` で `stock.db` を直接読む）。
- 株探側の市場別・時価総額別フィルタによる絞り込みは行わない。
