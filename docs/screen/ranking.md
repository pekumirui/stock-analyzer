# ランキングタブ

月別の決算発表後パフォーマンスランキングと夜間 PTS ランキングを切り替えて表示する画面の仕様を定める。決算発表後パフォーマンスの算出規則は [全体像](../OVERVIEW.md)「決算日からの相対パフォーマンス」、夜間 PTS サブ画面の仕様は [PTS](pts.md)、共通の見た目と配置規則は [画面仕様の共通規則](SPEC.md) を参照する。

## 誰のための画面か

特定の月に決算を発表した銘柄のうち、決算発表直後に買える価格から次回決算の前営業日終値まで保有したときの上昇率・下落率を一覧で比較し、上位ランキング画像を X に共有したい利用者向けの画面である。

## 画面と遷移

ヘッダーの `ランキング` タブ（`data-tab="ranking"`）の直下にピル型サブタブ `#rk-subs`（`.fin-tabs`、`data-rksub="perf"` と `data-rksub="pts"`）を置き、`決算後パフォーマンス`（既定）と `PTS` を切り替える。

| 画面 | 画面 ID | ルート |
|---|---|---|
| 決算後パフォーマンス | `ranking` | `#ranking` |
| PTS | `ranking-pts` | `#ranking/pts` |

画面遷移とルート復元の規則は以下のとおりである。

- 初回表示時は `決算後パフォーマンス`（`#ranking`）を開く。サブタブを切り替えたあと別タブへ移動して戻っても、直前に選んでいたサブタブを維持する。
- ページ再読込時は URL ハッシュと `localStorage`（`ui.route`）から選択中のサブタブまで復元する。
- ヘッダーに独立した PTS タブは置かない。旧ルートの `#pts`（ハッシュおよび `ui.route`）は `#ranking/pts` に置き換える。
- 表内の銘柄名をクリックしたときは、銘柄タブの株価（`#stock/{code5}/price`）へ遷移する。

## データ形

決算後パフォーマンス画面は `GET /api/ranking/earnings-perf` の応答 1 回分を保持し、上昇率と下落率の切り替えはクライアント側で同じ応答データを並べ替えて描画する。日次バッチが初回決算短信フラグ（`is_first`）・発表時刻・各期間リターンを `earnings_events` テーブルへ保存済みであるため、画面表示のたびに日足から再計算したり重い `statements` テーブルを読んだりしない。

各期の起点は、銘柄 × 決算期 × 四半期ごとの最初の決算短信本体の発表日（`disclosed_date`）とし、その日が属する暦月（`YYYY-MM`）を決算月とする。後日の訂正開示は起点にせず、業績予想修正のみの開示は対象外とする。次回決算が未発表の銘柄には、DB 内の最新営業日終値までの途中経過リターンが入る。

## 決算発表後パフォーマンス

### 目的

選択した決算月に初回決算短信を発表した銘柄を、発表後の基準値から次回決算発表日の前営業日終値（未発表なら最新営業日終値）までの上昇率または下落率順に並べて確認し、X 投稿用の画像を出力する。

### 要素

`#rk-sub-perf` 区画内に、上から向きの切り替えタブ、操作行、ランキング表を並べる。

1. 向きの切り替え `#rk-kind`（`.fin-tabs`）には、`上昇率`（`data-dir="up"`、既定）と `下落率`（`data-dir="down"`）の 2 ボタンを置く。
2. 操作行には、決算月セレクト `#rk-month`（`YYYY年M月決算` 形式、新しい順で最大 `36` か月）、件数・基準日表示 `#rk-info`（`<N> 銘柄 / <M/D> 終値まで`）、および共有ボタン `#rk-share`（`X に投稿`）を並べる。
3. ランキング表 `#rk-tbl`（`table.sheet`）の列は左から以下の順に並べる。

| 列順 | 見出し | 表示内容と書式 |
|---|---|---|
| 1 | `順位` | 現在の向き（上昇率または下落率）の中で `1` から振り直した連番を表示する |
| 2 | `銘柄` | 上段に先頭 5 文字（PC 表示は 10 文字）、下段に 4 桁コードを出し、`title` 属性に正式名を入れる |
| 3 | `市場` | `fmtMarket` で `東証P`・`東証S`・`東証G` と色付きの点に整形する（空なら `` `–` ``） |
| 4 | `業種` | `fmtSector` で 33 業種名の末尾 `業` を除いた先頭 5 文字を出し、`title` 属性に正式名を入れる（空なら `` `–` ``） |
| 5 | `騰落率`（下段 `(対TOPIX)`） | 上段に `return_to_next`（小数 1 桁 `%`）、下段に括弧付きの対 TOPIX 超過リターン `alpha_to_next`（例: `(+11.1%)`、欠損なら `` `–` ``）を出す。`0` 以上は赤（`.pos`）、負は緑（`.neg`）で色分けする |
| 6 | `決算日` | 上段に発表日の `M/D`、下段に `.qb` バッジで `場中`（`session == "intraday"`）または `引け後`（`session == "after"`）を表示する |
| 7 | `経過日数` | 次回決算が発表済み（`next_disclosed_date` あり）なら終点日の `〜M/D`、未発表なら発表日の翌営業日から終点日までの営業日数 `<N>日`（TOPIX 日足の営業日基準、欠損時は `` `–` ``）を出す（`保有中` という文言は出さない） |

API は指定月の全対象銘柄を `return_to_next` 降順で返し、クライアント側で `上昇率` は `return_to_next > 0` を高い順、`下落率` は `return_to_next < 0` を小さい順（マイナス幅が大きい順）に抽出する（同率は銘柄コード昇順）。`return_to_next` が `0` または `null` の行はどちらの向きにも表示しない。

### 操作

各コントロール・銘柄名・共有ボタンの操作に対する動作は以下のとおりである。

- `#rk-month` で決算月を変更したときは、その月のデータを API から再取得して描画する（既定は最新の決算月）。
- `#rk-kind` で `上昇率` と `下落率` を切り替えたときは、API を呼び直さずに保持中の応答データを並べ替えて再描画する。
- 銘柄名をクリックしたときは、銘柄タブの株価（`#stock/{code5}/price`）へ遷移する。
- `X に投稿`（`#rk-share`）をクリックしたときは、表示中のランキング上位最大 `20` 銘柄を `<canvas>` で論理幅 `760px` の 2 倍解像度 PNG（ファイル名 `earnings-perf-{up|down}-{YYYY-MM}.png`）に描画し、以下の 3 行の投稿文（`N` は表示行数と `20` の小さい方、下落率時は `下落率ランキングTOPN`）を組み立てる。

```text
YYYY年M月決算 上昇率ランキングTOPN
計測方法は決算発表後初値〜
※場中決算は翌営業日初値
```

PNG 画像の上部タイトルには 1 行目のみを描き（2〜3 行目の注記は投稿本文と重複するため画像内には描かない）、表の列構成と 2 段表示は画面の表と揃える。画像内の銘柄名と業種名は NFKC 正規化し、画面の 5 文字切りは行わず列幅を超える分だけ末尾を `…` で省略する。端末に応じた共有動作は以下のとおりである。

| 端末条件 | 共有の動作 |
|---|---|
| スマートフォン（`pointer: coarse` かつ `navigator.canShare` が画像ファイル共有に対応） | OS の共有シートに PNG ファイルと投稿文をそのまま渡す |
| PC（上記以外） | PNG ファイルをダウンロード保存し、投稿文を入れた `https://x.com/intent/post` を別タブで開く（Web Intent URL では画像を渡せないため、保存した画像を手動で添付する） |

### 空とエラー

読み込み中・データ 0 件・通信失敗時の表示は以下のとおりである。決算月を連続で切り替えたときは、最後に発行したリクエストの応答だけを反映する。

| 状況 | 表示場所 | 表示文言と挙動 |
|---|---|---|
| API 読み込み中 | `#rk-info` | `読み込み中…` を表示し、`#rk-share` を隠す |
| DB 全体に決算データが 1 件も無い（`months` が空） | `#rk-info` | 表と `#rk-month` と `#rk-share` を隠し、`決算のデータがまだありません` を表示する |
| 指定した決算月の対象行が 0 件 | `#rk-info` | 表を空にして `#rk-share` を隠し、`この月の決算はありません` を表示する |
| 選択した向きの該当行が 0 件 | `#rk-info` | 表を空にして `#rk-share` を隠し、`この月の上昇率はありません` または `この月の下落率はありません` を表示する |
| API の失敗 | `#rk-info` | 表を空にして `#rk-share` を隠し、`読み込みに失敗しました` を表示する |

### スマホと PC

スマートフォンと PC で同じ構造を使う。操作行は画面幅に応じて折り返し、表は内容に応じた自然幅で組んで収まらない分を横スクロールさせる。左側の 2 列（`順位`・`銘柄`）は `pinCols` で左端に固定し、横スクロール時に `市場`・`業種` が `銘柄` の下へ隠れて `騰落率` 以降の列がすぐ見えるようにする。

## PTS

`#rk-sub-pts` 区画には夜間 PTS ランキングを表示する。目的・要素・操作・空とエラー・スマホと PC・API の仕様は [PTS](pts.md) に定め、`#pts-date`・`#pts-ranking`・`#pts-at`・`#pts-info`・`#pts-summary`・`#pts-tbl` の DOM ID をそのまま使う。

## API

### `GET /api/ranking/earnings-perf`

クエリ `month`（`YYYY-MM`、省略時は最新の決算月、形式不正は `400`）を受け取り、その月に初回決算短信（`earnings_events.is_first == true`）を開示した銘柄一覧を `return_to_next` 降順（`null` は末尾、同率は `code` 昇順）で返す。

```json
{
  "months": ["2026-10", "2026-09"], "month": "2026-10", "as_of": "2026-10-26",
  "rows": [{"rank": 1, "code": "52460", "name": "ＥＬＥＭＥＮＴＳ",
            "disclosed_date": "2026-10-14", "disclosed_time": "16:00", "session": "after",
            "base_date": "2026-10-15", "base_price": 1150.0,
            "return_to_next": 11.39, "alpha_to_next": 11.07,
            "next_disclosed_date": null, "end_date": "2026-10-26", "bdays": 8,
            "market": "グロース", "sector33": "情報・通信業"}]
}
```

`months` には初回決算短信が存在する月を新しい順で最大 `36` 件入れ、`as_of` には `daily_prices` の最新営業日（日足が空なら `null`）を入れる。`session` は東証の大引け時刻を境に `intraday`（場中）または `after`（引け後・発表時刻欠損）となる。初回決算短信が DB に 1 件も無く `month` も省略されたときは、`months: []`・`month: null`・`rows: []` を返す。

## 対象外

以下の項目は現時点では実装しない。

- 保有期間の切り替え（最新日まで・`+1d`・`+5d`・`+20d`・`+60d` への変更）は行わず、次回決算前営業日までのみを扱う。
- 市場区分・33 業種・時価総額によるランキングの絞り込みは行わない。
