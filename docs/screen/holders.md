# 大量保有報告書タブ

大量保有報告書・変更報告書の提出一覧、提出者検索、および保有者別の保有銘柄と推移を表示する画面の仕様を定める。EDINET からの取込と補正規則は [EDINET の取込](../jobs/edinet.md)「大量保有報告書」、銘柄側の株主サブタブは [銘柄タブ](stock.md)、共通の見た目と配置規則は [画面仕様の共通規則](SPEC.md) を参照する。

## 誰のための画面か

大量保有報告書の提出者（運用会社・事業会社・個人）が現在どの銘柄をどれだけ保有し、直近で買い増したか売却したかを、提出日または名前・コードから確認したい利用者向けの画面である。銘柄タブの株主サブタブから提出者を辿る遷移先としても使う。

## 画面と遷移

ヘッダーナビ末尾（`ランキング` の右）に置く `大量保有報告書` タブ（`data-tab="holders"`）は、以下の 2 画面で構成する。

| 画面 | 画面 ID | ルート |
|---|---|---|
| 提出日の一覧と検索 | `holders` | `#holders` |
| 保有者 | `holders-detail` | `#holders/{edinet}`（`E` と数字 5 桁。形式が異なる文字列は `#holders` に戻す） |

画面間の遷移と再読込時の復元規則は以下のとおりである。

- タブを初めて開いたときは提出日の一覧（`#holders`）を表示する。ページ再読込時は URL ハッシュと `localStorage`（`ui.route`）から保有者ページ（`#holders/{edinet}`）まで復元する。
- 一覧表の保有者名または検索候補、および銘柄タブの株主サブタブの提出者名をクリックしたときは、`gotoHolder` で `#holders/{edinet}` を開く。
- 一覧表または保有者ページの銘柄名をクリックしたときは、`gotoChart` で銘柄タブの株価（`#stock/{code5}/price`）を開く。

## データ形

データは既存の `large_holding_reports`・`large_holdings`・`daily_prices`・`stocks` を読み取るだけであり、保有者候補は `GET /api/holders/search`、提出一覧と検索結果は `GET /api/holders/activity`、保有者詳細は `GET /api/holders/{edinet}` から取得する（銘柄側の株主サブタブは `GET /api/stock/{code}/holders` を使う）。

対象データの絞り込み、名寄せ、指標計算の規則は以下のとおりである。

| 観点 | 規則 |
|---|---|
| 対象とする発行体 | 発行体が株券でない報告（`stocks.product_category` が `'011'` 内国株券・`'021'` 外国株券以外の ETF・ETN・REIT・出資証券）は、保有者候補・一覧・保有者ページのいずれにも出さない。`stocks` に存在しない未上場などの発行体は表示し、`product_category` が DB に 1 件も入っていない環境では絞り込まない（銘柄の株主サブタブは商品区分で絞らない） |
| 保有者の名寄せ単位 | 共同保有や表記ゆれは `large_holdings.edinet_code` 単位で名寄せする。EDINET コードが空の行は検索候補・一覧・保有者ページのいずれにも出さない（銘柄の株主サブタブは書類の `filer_edinet_code` 単位でまとめ、共同保有を書類合計の 1 行で表す） |
| 最新保有と 5 年推移 | `is_latest = true`・`withdrawn = false`・`parse_status = 'parsed'` の報告を対象とし、発行体ごとに `(file_date, submit_datetime, obligation_date)` が最も新しい 1 件を現在の保有とする。推移履歴は同じ条件の報告のうち、`obligation_date` または `file_date` が基準日から過去 5 年以内のものを報告義務発生日の昇順で並べる |
| 時価・単価・損益の目安 | 時価は `最新終値 × 保有株数`、平均取得単価は `total_funds ÷ 保有株数`、評価損益は `(最新終値 - 平均取得単価) × 保有株数` で算出する。終値または保有株数が `0` 以下・欠損なら時価を含め算出せず、取得資金（`total_funds`）が `0` 以下・欠損、または報告義務発生日時点の `adj_factor` と最新の `adj_factor` が異なる（義務発生日以降に株式分割・併合があった）場合は取得単価と評価損益を算出しない |
| 報告義務発生日の異常値 | 元データの誤記で報告義務発生日が提出日より先、または今日より未来になっている行も削除しない（既知の年ずれは取込時に `config/large_holding_date_fixes.json` で補正する）。報告義務発生日が提出日より `30` 日を超えて先、または JST の今日より未来のセルには `.odd-date` の注意色を付ける |

提出一覧に出す動きの種類（`kind`）は、保有者本人の保有割合（`large_holdings.holding_ratio` と `holding_ratio_prev`）および様式コード（`form_code`）から以下の優先順で判定する。割合が変わらない変更報告（住所変更や担保契約の変更のみなど）や、変更報告で前回割合が無く今回 `5%` 未満の行は一覧に出さない。

| 優先順 | `kind` | 画面バッジ | 判定条件 |
|---|---|---|---|
| 1 | `below` | `5%割れ`（`.qb-dn`） | 前回割合が `5%` 以上かつ今回割合が `5%` 未満 |
| 2 | `new` | `新規5%超え`（`.qb-init`） | 様式が大量保有報告書（`010000`）または特例対象株券等の大量保有報告書（`030000`）、あるいは前回割合が `null` で今回割合が `5%` 以上 |
| 3 | `buy` | `買い増し`（`.qb-up`） | 前回割合が存在し、今回割合が前回より大きい |
| 4 | `sell` | `売り`（`.qb-dn`） | 前回割合が存在し、今回割合が前回より小さい |

## 提出日の一覧と検索

### 目的

指定した提出日の大量保有報告書・変更報告書を一覧で確認し、特定の銘柄や保有者を探すときは日付条件を外して横断検索する。

### 要素

`#hd-top` 内に上から操作行（`#hd-search`）、メッセージ欄（`#hd-feed-msg`）、一覧表（`#hd-feed`）を置く。

1. 操作行（`#hd-search`）には、提出日入力 `#hd-date`（`input[type="date"]`、初期値は `Asia/Tokyo` の当日）と検索欄 `#hd-sym`（プレースホルダ `銘柄名・保有者名 or コード`）、および入力欄直下に開く保有者候補リスト `#hd-suggest`（`<名前>  <EDINETコード>` 形式で最大 20 件）を並べる。
2. 一覧表 `#hd-feed`（`table.sheet`）の列は左から以下の順に並べる。

| 列順 | 見出し | 表示内容と書式 |
|---|---|---|
| 1 | `提出日` | `file_date` を `YY/MM/DD` で出し、`title` 属性に `報告義務発生日 YYYY-MM-DD` を入れる。報告義務発生日が提出日より `30` 日超先または今日より未来なら注意色（`.odd-date`）にする |
| 2 | `種類` | `.qb` バッジで `新規5%超え`・`買い増し`・`売り`・`5%割れ` を表示する |
| 3 | `保有者` | 上段に先頭 5 文字（PC 表示は 10 文字）、下段に EDINET コードを出し、`title` 属性に正式名を入れる |
| 4 | `銘柄` | 上場銘柄は上段に先頭 5 文字（PC 表示は 10 文字）、下段に 4 桁コードを出し、`title` 属性に正式名を入れる。未上場（`code` が `null`）は発行者名をそのまま出し、空なら `` `–` `` とする |
| 5 | `保有割合` | 上段に保有割合（小数 2 桁 `%`）、下段に前回からの差（例: `+1.19pt`、プラスは赤 `.pos`、マイナスは緑 `.neg`、欠損は `` `–` ``）を表示する |

### 操作

日付指定・検索・候補選択・一覧クリック時の動作は以下のとおりである。

- 検索欄（`#hd-sym`）が空または検索条件に満たない状態で `#hd-date` を変更したときは、その `file_date` の提出分を取得して表示する（取得上限 `1,000` 件）。
- `#hd-sym` に検索として有効な文字列（2 文字以上、`E` + 1〜5 桁数字の EDINET コード、または 4〜5 桁の銘柄コード）を入力したときは、`#hd-date` を無効化（`disabled`）し、日付で絞らずに提出日の新しい順で検索結果を表示する（`200ms` デバウンス、取得上限 `200` 件）。あわせて保有者検索 API を呼び、一致する保有者候補を `#hd-suggest` に出す。
- `#hd-sym` を空に戻したときは、`#hd-date` の無効化を解除し、選択していた提出日の提出一覧に戻す。
- `#hd-suggest` の候補をクリックしたとき、または候補が出ている状態で `Enter` キーを押したときは、対象（`Enter` は先頭候補）の保有者ページ（`#holders/{edinet}`）を開く。`Escape` キーを押すか `#hd-search` の外側をクリックしたときは候補リストを閉じる。
- 一覧表の保有者名をクリックしたときは保有者ページへ、上場銘柄名をクリックしたときは銘柄タブの株価へ遷移する。

### 空とエラー

一覧・検索結果が 0 件のときと通信失敗時の表示は以下のとおりである。

| 状況 | 表示場所 | 表示文言と挙動 |
|---|---|---|
| 指定した提出日の該当報告が 0 件 | `#hd-feed-msg` | 表を空にし、`この日の大量保有報告書はありません。` を表示する |
| 検索時の該当報告が 0 件 | `#hd-feed-msg` | 表を空にし、`該当する大量保有報告書はありません。` を表示する |
| 一覧 API の失敗 | `#hd-feed-msg` | 表を空にし、`読み込めませんでした。` を表示する |
| 保有者候補が 0 件または検索 API 失敗 | `#hd-suggest` | 候補リストを非表示にする |

### スマホと PC

スマートフォンと PC で同じ DOM 構造を使い、画面幅に収まらない列は横スクロールで見せる。左側の 3 列（`提出日`・`種類`・`保有者`）は `pinCols` で左端に固定する。

## 保有者

### 目的

特定の保有者が現在保有している銘柄一覧と評価額の目安を確認し、選んだ銘柄の保有割合・保有株数の推移を辿る。

### 要素

`#hd-detail` 内に上から見出し行、メッセージ欄（`#hd-msg`）、保有銘柄一覧（`#hd-holdings`）、上位銘柄の推移グラフ（`#hd-chart`）、選択銘柄の推移（`#hd-series`）を縦に並べる。

1. 見出し行には戻るボタン `#hd-back`（`← 大量保有報告書`）と、保有者名・EDINET コードを並べた見出し `#hd-title` を置く。
2. 保有銘柄一覧 `#hd-holdings`（`table.sheet`）は、最新保有割合が `5%` 以上の銘柄を先に割合降順で並べ、`5%` 未満の銘柄がある場合は全列結合の小見出し行 `5%未満`（`tr.below-h`）を挟んでその下に淡色（`tr.below`）で並べる（同率は銘柄コード昇順）。
3. 保有割合の推移 `#hd-chart` には、`#hd-holdings` の並び順で先頭最大 `6` 銘柄について、横軸を報告義務発生日（`YY/MM/DD`）、縦軸を保有割合（`%`）とする SVG 折れ線グラフと凡例を描画する。
4. 選択銘柄の推移 `#hd-series` には、見出し `<銘柄名> の推移`、横並び（折り返し可）の 2 つの SVG 折れ線グラフ（`#hd-series-ratio` の保有割合と `#hd-series-shares` の株数）、および過去最大 5 年分の報告履歴表（`table.sheet`、列は左から `日付`・`株数`・`保有割合`、古い順、`日付` の `title` に提出日・異常日は `.odd-date`）を表示する。

保有銘柄一覧 `#hd-holdings` の列は左から以下の順に並べ、数値は右寄せ・桁区切りとする。

| 列順 | 見出し | 見出し `title` | 表示内容と書式 |
|---|---|---|---|
| 1 | `銘柄` | なし | 上場銘柄は上段に先頭 5 文字（PC 表示は 10 文字）・下段に 4 桁コード（`title` に正式名）、未上場は発行者名を表示する |
| 2 | `保有割合` | なし | 小数 2 桁の `%` を表示する |
| 3 | `差` | `前回からの差` | 前回比のポイント差（小数 2 桁 `pt`、符号・色付き）を表示する |
| 4 | `株数` | なし | 整数桁区切りの `<株数>株` を表示する |
| 5 | `時価` | `時価（目安）` | `1億円` 以上は小数 1 桁の `億円`、`1万円` 以上は整数の `万円`、それ未満は整数の `円` で表示する |
| 6 | `取得単価` | `平均取得単価（目安）` | 整数桁区切りの `<単価>円` を表示する |
| 7 | `評価損益` | `評価損益（目安）` | 時価と同じ単位丸めで表示し、正は赤 `.pos`、負は緑 `.neg` を付ける |
| 8 | `義務発生日` | `報告義務発生日` | `obligation_date` を `YY/MM/DD` で出し、セルの `title` に `提出日 YYYY-MM-DD` を入れる（異常日は `.odd-date`） |
| 9 | `保有目的` | なし | 1 行目のみを折り返さずに表示し、セルの `title` に同じ文字列を入れる |

### 操作

保有者ページ内のボタン・銘柄名・データ行クリック時の動作は以下のとおりである。

- `#hd-back` をクリックしたときは提出日の一覧画面へ戻る（`#hd-sym` に検索語が残っている場合はその検索結果を表示する）。
- `#hd-holdings` の銘柄名をクリックしたときは銘柄タブの株価へ遷移する。
- `#hd-holdings` のデータ行をクリックしたときは、表自体は作り直さずに選択行のハイライト（`tr.on`）と `#hd-series` の対象銘柄を切り替える。ページを開いた直後の初期選択行は、保有割合 `5%` 以上の先頭銘柄（すべて `5%` 未満なら一覧先頭）とする。選択中の銘柄は URL ルートには含めない。

### 空とエラー

保有者ページの空状態・欠損値・エラー時の表示は以下のとおりである。

| 状況 | 表示場所 | 表示文言と挙動 |
|---|---|---|
| 指定した EDINET コードの該当報告が無い（HTTP `404`） | `#hd-msg` | `保有者が見つかりません。` を表示する |
| 保有者 API の通信・サーバー失敗 | `#hd-msg` | `読み込めませんでした。` を表示する |
| `holdings` が 0 件 | `#hd-holdings` | `大量保有報告はありません。` を表示する |
| 選択銘柄の `history` が 0 件 | `#hd-series` | 見出しの下に `推移はありません。` を表示し、グラフは出さない |
| 算出できない時価・取得単価・評価損益、または欠損値 | 各セル | `` `–` `` を表示する |

### スマホと PC

スマートフォンと PC で同じ縦積みの構造を使い、2 段組にはしない。表は横スクロールとし、`#hd-holdings` の左端 1 列（`銘柄`）を `pinCols` で固定する。`#hd-series` 内の 2 つの折れ線グラフ（`.hd-pair`）は、幅が狭い画面では上下に折り返す。

## API

### `GET /api/holders/search`

クエリ `q` を受け取り、保有者名の部分一致または EDINET コードの前方一致（`E` + 5 桁の完全指定時は完全一致）で最新の提出から最大 `20` 件を返す。`q` が空、または完全な EDINET コード以外で `2` 文字未満のときは `results: []` を返す。EDINET コードの無い保有者や株券以外の発行体のみの保有者は返さない。

```json
{"q": "ブラックロック", "results": [{"edinet_code": "E09096", "name": "ブラックロック・ジャパン株式会社"}]}
```

### `GET /api/holders/activity`

クエリ `file_date`（`YYYY-MM-DD`、省略時は `Asia/Tokyo` の当日）・`q`・`limit`（`1`〜`1000`、省略時 `80`、検索時は最大 `200`）・`offset`（`0` 以上）を受け取る。

`q` が検索条件を満たすとき（`2` 文字以上、`E` + 1〜5 桁数字、または 4〜5 桁の銘柄コード）は `file_date` を無視し、NFKC 正規化とひらがなからカタカナへの変換を含む保有者名・発行者名・銘柄名の部分一致およびコード一致で検索する。満たさないときは `large_holding_reports.file_date` の等号検索（`ix_large_holding_reports_file_date`）を行う。

```json
{"file_date": "2026-10-29", "q": "", "has_more": false, "items": [
  {"kind": "buy", "edinet_code": "E09096", "holder_name": "ブラックロック・ジャパン株式会社",
   "code": "18020", "issuer_name": "株式会社大林組", "market": "プライム", "sector33": "建設業",
   "obligation_date": "2026-10-22", "file_date": "2026-10-28",
   "holding_ratio": 0.0202, "holding_ratio_prev": 0.0195, "shares_held": 14008800}
]}
```

検索モードの応答では `"file_date": null`・`"q": "<検索語>"` となる。`kind` は `new`・`buy`・`sell`・`below` の 4 種類で、並び順は提出日・提出時刻の新しい順、未上場発行体は `code: null`、続きがあるときは `has_more: true` を返す。

### `GET /api/holders/{edinet}`

パスパラメータ `edinet`（`E` + 数字 5 桁、形式不正は `400`）と任意のクエリ `today`（`YYYY-MM-DD`、5 年履歴の基準日）を受け取り、保有者の保有銘柄一覧と直近の動きを返す。該当する報告が 1 件も無い場合は `404` を返す。

```json
{
  "edinet_code": "E09096", "name": "ブラックロック・ジャパン株式会社",
  "holdings": [
    {"code": "18020", "name": "大林組", "market": "プライム", "sector33": "建設業",
     "shares_held": 14008800, "holding_ratio": 0.0202, "holding_ratio_prev": 0.0195,
     "obligation_date": "2026-10-22", "file_date": "2026-10-28", "purpose": "純投資",
     "price": 1850.0, "price_date": "2026-10-28",
     "market_value": 25916280000.0, "avg_cost": 1914.0, "unrealized": -896563200.0,
     "history": [{"date": "2026-03-02", "shares": 12000000, "ratio": 0.018,
                  "file_date": "2026-03-08"}]}
  ],
  "activity": []
}
```

`holdings` は保有割合 `5%` 以上の銘柄が先、`5%` 未満の銘柄が後にそれぞれ割合降順で並ぶ。算出できない `market_value`・`avg_cost`・`unrealized` は `null` となり、`history` は報告義務発生日の古い順で最大 5 年分が入る。`activity` にはその保有者の動きが一覧と同じ形式で最大 `80` 件入る（画面では表示しない）。銘柄別の株主 API（`GET /api/stock/{code}/holders`）の仕様は [銘柄タブ](stock.md) を参照する。

## 対象外

以下の項目は本タブの対象外とする。

- 日ごとの売買内訳・約定単価、および `5%` に一度も届いていない保有は扱わない。
- 有価証券報告書の大株主上位一覧、所有者別株式分布状況、信用残・空売り残は表示しない。
- EDINET コードを持たない共同保有者や、本文中に文章でのみ記載された共同保有者名の名寄せは行わない。
