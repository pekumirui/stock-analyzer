# 銘柄

1 つの銘柄について、株価・バリュエーション指標・決算サマリー・財務 3 表・短信原文・決算説明資料・大量保有と自己株買いを横断して調べるタブ（`#tab-stock`）の仕様を定める。

関連する設計と取込規則は [株価・決算の取込規則](../jobs/market.md)、[XBRL の設計](../jobs/xbrl.md)、[EDINET の取込](../jobs/edinet.md)、[画面設計: 銘柄](gen/stock.md)、[画面仕様の共通規則](SPEC.md)、および [API 仕様](api.md) を参照する。

## 誰のための画面か

個別銘柄の現在のバリュエーション・過去の業績推移・財務諸表・開示原文・大株主の動向を 1 か所でまとめて調べたい個人投資家のための画面である。他タブの一覧やランキングで気になった銘柄のリンクから直接チャートへ入り、サブタブで概要・財務 3 表・開示資料・株主へ横展開できる構成とする。

## 画面と遷移

銘柄タブはヘッダーの上部タブ列には置かず、ヘッダー右端の虫眼鏡ボタン `#sym-btn`（どの画面からでも検索して概要へ遷移）または他タブの銘柄名リンク（`gotoChart` で株価へ遷移）から開く。URL ハッシュの証券コードは J-Quants の 5 桁コード（例: `#stock/72030/price`）を正とし、4 桁コード（例: `#stock/7203`）で開かれたときは末尾に `0` を補って `history.replaceState` で正規化する。

本タブが持つルートと表示画面の対応は以下のとおりである。

| ハッシュ | 画面 ID | 表示内容とパンくずの戻り先 |
|---|---|---|
| `#stock` | `stock` | 銘柄未選択の案内を出し、ヘッダー直下の検索欄 `#sym-pop` を自動で開く |
| `#stock/{code}`、`#stock/{code}/summary` | `stock-summary` | 概要サブタブ（5 指標カード + 決算表）を表示する |
| `#stock/{code}/price` | `stock-price` | 株価サブタブを表示する。決算速報・スクリーナー・ランキング・PTS・サプライ・大量保有報告書から `gotoChart` で入ったときは、パンくず `#crumb` で元のタブへ戻れる |
| `#stock/{code}/financials` | `stock-financials` | 業績詳細サブタブ（財務 3 表 `BS`・`PL`・`CF`）を表示する |
| `#stock/{code}/news` | `stock-news` | ニュースサブタブ（決算短信・予想修正・決算説明資料の一覧）を表示する |
| `#stock/{code}/news/{id}` | `stock-news-detail` | ニュースの詳細を表示する。`id` は XBRL 短信が `filing_id`、PDF 変換短信が `pdf-{disclosure_no}` である。サブタブの選択は `ニュース` のまま保ち、パンくずで `ニュース` 一覧へ戻れる |
| `#stock/{code}/decks/{key}` | `stock-deck-detail` | 決算説明資料の中身を表示する。`key` は `briefing_documents.r2_key` のファイル名から拡張子 `.pdf` を除いた文字列である。サブタブの選択は `ニュース` のまま保ち、パンくずで `ニュース` 一覧へ戻れる |
| `#stock/{code}/holders` | `stock-holders` | 株主サブタブを表示する。提出者名リンクを押すと大量保有報告書タブの保有者画面 `#holders/{edinet}` へ遷移し、パンくずで `株主` へ戻れる |

## データ形

共通ヘッダーと概要サブタブが読む `GET /api/stock/{code}/overview`（任意の `today=YYYY-MM-DD` で基準日を上書き可能）の各項目と算出規則は以下のとおりである。

| 項目 | 応答フィールド | 算出元と計算式 |
|---|---|---|
| 株価・前日比 | `quote.price`、`quote.change`、`quote.change_pct`、`quote.date` | `daily_prices` の最新営業日と直前営業日から求める。両日に調整後終値 `adj_close` があれば `change_pct = cur.adj_close / prev.adj_close - 1` とし、分割・併合の権利落ち日でも歪まないよう現在株数ベースの差額 `change = round(cur.close - cur.close / (1 + change_pct), 4)` に換算する（`adj_close` 欠損時のみ生の `close` 差を使う） |
| 時価総額 | `quote.market_cap` | 最新 `statements` の期末発行済株式数 `ShOutFY`（無ければ期中平均株式数 `AvgSh`）から期末自己株式数 `TrShFY`（無ければ `0`）を引き、開示日より後の `daily_prices.adj_factor` で現在の株数へ揃えたうえで最新終値 `close` を掛け、百万円単位（`÷ 1e6`）で返す |
| PER（予想） | `metrics.per` | `株価 ÷ 予想 EPS` とする。予想 EPS は `今期予想純利益 ÷ 最新の株数` で、会社の予想 EPS（期中平均株式数で割った値）は使わない（自社株買いで期中に株数が大きく減ると会社の予想 EPS は小さく出るため。KAB-582）。予想純利益は `forecast_points` の最新値、最新の株数は下の「最新の決算短信」の `ShOutFY - TrShFY`（自己株が無ければ `ShOutFY`）で、その短信の開示日より後の `adj_factor` で現在株数に調整する。予想純利益か最新の株数が無いとき、実績の `EPS` と `NP ÷ AvgSh` が 2% より食い違う会社（優先株の配当を引くなど）、期末の株数が期中平均株式数 `AvgSh` の 3 分の 2 に満たない会社（参加型の優先株を普通株に換算して平均に足すなど）は、どちらも値のある一番新しい決算短信で見て、株価チャートの業績の段と同じ `fund_steps`（`app/market/chart_fund.py`）の最新の予想 EPS を使う。予想 EPS が空または `0` 以下なら `null` とする |
| PBR（実績） | `metrics.pbr` | `株価 ÷ BPS` とする。BPS は「最新の決算短信」の `raw_json` の `BPS` で、空なら `自己資本 ShEq ÷ (ShOutFY - TrShFY)`（決算短信の 1 株当たり純資産と同じく、純資産から新株予約権と非支配株主持分を除いた額を期末の株数で割る）で作る。J-Quants の `BPS` はほぼ本決算にしか入らないため（KAB-582）。`BPS` と `ShEq ÷ 株数` の両方がある一番新しい短信で 2% より食い違う会社（優先株のある会社など）は作らず、`BPS` のある一番新しい短信の値を使う。開示日後の `adj_factor` で現在株数に調整し、BPS が空または `0` 以下なら `null` とする |
| 配当利回り（予想） | `metrics.dividend_yield` | `年間配当予想 ÷ 株価` とする。年間配当予想は、開示を古い順に畳んで開示ごとの予想を作る共通の層（`app/market/forecasts.py` の `forecast_points`、KAB-551）の最新値で、その値を決めた開示の開示日より後の `adj_factor` で現在株数に調整する。`0` は無配として `0.0` を返し、未定なら `null` とする |
| ROE（実績） | `metrics.roe` | 直近の本決算（`FY`）の `raw_json` の `ROE`（小数値）を使う。純利益が負などで `ROE` が空のときは `純利益 ÷ 自己資本`（`NP / Eq`）で補い、自己資本が `0` 以下なら `null` とする |
| 自己資本比率 | `metrics.equity_ratio` | 最新開示の `raw_json` の `EqAR`（小数値）を使う |
| 次回の決算予定日 | `next_earnings` | `earnings_date_pubs` を四半期名 `fq_name`（`1Q`・`2Q`・`3Q`・`FY`）ごとに最新 `pub_date` の行へ絞り、`sch_date >= today` のうち最も早い `{date, fq}` を返す。予定日が無く、いずれかの四半期の最新行で `sch_date` が `null`（未定）なら `{"date": null, "fq": null}`、予定行自体が無ければ `null` を返す |

1 株指標の分割調整と予想値の走査では以下の境界条件を守る。

- PER の株数と PBR の「最新の決算短信」は、値のある決算短信のうち期（年度末・四半期）が一番新しいもの、同じ期なら後に出たもの（開示日・時刻・開示番号）とする。期の古い訂正短信が後から届いても、空欄の訂正短信が出ても、新しい期の値を残す（`app/market/reported.py` の `latest_reported`。KAB-582）。
- ROE・自己資本比率の「最新開示」は、決算短信を開示日・年度末・四半期・時刻・開示番号の新しい順に見て、値のある最初の短信とする（決算の詳細の既定の開示と同じ順。同じ日・同じ時刻に過年度の訂正短信と新しい期の短信が並んでも新しい期を先に見る。KAB-580）。
- 開示日 `d` より後に `daily_prices.adj_factor`（例として 1 対 3 の株式分割なら権利落ち日に `1/3`）が存在するときは、1 株あたりの値（予想 EPS・年間配当予想・BPS）に `adj_factor` を掛けて現在の株数基準に揃える。
- 年間配当予想は開示を古い順に見て決める。決算短信は本決算なら来期予想 `NxFDivAnn`、第 1〜3 四半期なら当期予想 `FDivAnn` で置き換え、空なら未定（`null`）にして前の開示へ遡らない。決算短信以外の開示（`DividendForecastRevision`・`EarnForecastRevision` など）は `FDivAnn` に値があるときだけ上書きし、空なら前の値を続ける。取り下げの印で `div_annual` を取り下げた開示（[取込と保存の規則: 株価・決算・説明資料](../jobs/market.md)「予想の取り下げの印」）からは、次に値を出した開示まで未定とする。
- 年間配当予想は決算短信の期の前後を見ない。過年度の訂正短信が新しい開示日で出たときも、その短信の予想で置き換わる（株価チャートの予想 EPS は、`(年度の始まり, 四半期)` と `(年度末, 四半期)` の両方で既に見た最新より前の短信を無視する。配当は KAB-551 の前の動きを変えないため、そろえていない）。1Q・3Q 型の業績予想修正も `FDivAnn` に値があれば使う。

## 銘柄検索

### 目的

現在どのタブを開いていても、証券コードまたは銘柄名の一部から目的の銘柄の画面へ即座に移動する。

### 要素

ヘッダー右端に虫眼鏡ボタン `#sym-btn` を置き、押すと直下にポップアップ `#sym-pop`（検索入力 `#sym-q` と候補リスト `#sym-list`）を開く。候補 `.sym-item` は最大 20 件で、左に 4 桁コード `.sym-code` と銘柄名 `.sym-name`、右に `fmtMarket` の市場名と `fmtSector` の業種名を `・` でつないだ `.sym-meta`（例: `東P・輸送用機器`）を 1 行で並べる。

検索対象は株券（`stocks.product_category` が `'011'` または `'021'`）に限定し、ETF・REIT・出資証券は除外する（`product_category` 未投入の DB では全銘柄を対象とする）。コード前方一致を先、NFKC 正規化およびひらがな→カタカナ変換を通した銘柄名の部分一致を後に、コード昇順で並べる。

### 操作

`#sym-btn` のクリック、または入力欄以外にフォーカスがある状態での `/` キー押下で `#sym-pop` を開き、`#sym-q` にフォーカスして入力文字列を全選択する。入力から `120ms` のデバウンス後に `GET /api/stocks/search?q=…` を呼ぶ。

`ArrowDown`・`ArrowUp` キーで `.on` を移動し、`Enter` キーまたは候補の `mousedown` で `#stock/{code5}/summary` へ遷移してポップアップを閉じる。`Escape` キー、`#sym-btn` の再クリック、または `#sym-pop` 外のクリックでも閉じる。

### 空とエラー

入力が空文字のときや API が失敗したときは `#sym-list` を空にする。一致する銘柄が 0 件のときは `#sym-list` に `該当なし` を表示する。

### スマホと PC

PC ではヘッダー右端の直下に幅 `360px` で開く。スマホ（画面幅 `640px` 以下）では左右 `10px` を残して画面横幅いっぱいに開く。

## 共通ヘッダー

### 目的

銘柄タブ内のどのサブタブを開いていても、対象銘柄の基本属性・最新株価・時価総額・次回決算予定日を同じ位置で確認できるようにする。

### 要素

`#st-head` 内に銘柄属性ブロック `#st-title` と株価ブロック `#st-quote` を置き、その直下にサブタブ帯 `#st-subtabs`（`概要`・`株価`・`業績詳細`・`ニュース`・`株主` の 5 タブ）を並べる。

| ブロック | 表示要素 |
|---|---|
| `#st-title` | 省略しない正式社名（`.stock-name`）、4 桁コード、市場バッジ（`fmtMarket`）、業種バッジ（`fmtSector`）を並べる |
| `#st-quote` | 最新終値（`.stock-price`）、前日比の差額と騰落率（正は `.pos`、負は `.neg`、前営業日が無ければ `–`）、`MM/DD 終値`、`時価総額 N億円`（算出不能時は非表示）、および `次回決算 MM/DD`（未定時は `次回決算 未定`、予定データ無し時は非表示）を並べる |

### 操作

`#st-subtabs` のボタン `.stab[data-sub]` を押すと `#stock/{code5}/{sub}` へ遷移する。ニュース詳細や説明資料を開いている状態で `ニュース` サブタブを押したときは、`#stock/{code5}/news` の一覧へ戻る。

### 空とエラー

銘柄未選択や取得失敗時の `#st-msg` の表示は以下のとおりである。

| 状態 | 表示動作 |
|---|---|
| `#stock`（銘柄未選択） | `#st-head` と `#st-subtabs` を隠し、`#st-msg` に `右上の検索から銘柄を選んでください。` を出して `#sym-pop` を開く |
| 存在しないコード（`overview` が `404`） | `#st-msg` に `銘柄が見つかりません。` を出す |
| `GET /api/stock/{code}/overview` が `404` 以外で失敗 | `#st-msg` に `読み込めませんでした。` を出す |
| 日足データが無い銘柄 | 終値と前日比を `–` にし、時価総額を非表示にする |

### スマホと PC

PC では `#st-title` と `#st-quote` を左右に並べ、幅が足りないときは折り返す。スマホでは縦に折り返し、`#st-subtabs` は横スクロール可能なタブ帯となる。

## 概要

### 目的

バリュエーション・収益性・安全性の主要 5 指標と、決算速報と同じ 4 種類の業績表を 1 画面で確認する。

### 要素

上段に 5 枚の指標カード `#st-metrics`、下段に業績パネル `#st-fin`（サブタブ `#st-fin-tabs` と `#st-cum-tbl`・`#st-q-tbl`・`#st-prog-tbl`・`#st-rev-tbl`）を置く。業績パネルの 4 表（`累計` 既定・`3か月`・`進捗率`・`修正履歴`）の列構成と計算規則は [決算速報](earnings.md)「決算表」と同一である。

`#st-metrics` に並べる 5 枚のカードと桁数は以下のとおりである。

| カード名 | 値の書式 | 欠損・特例時の表示 |
|---|---|---|
| `PER（予想）` | 小数第 1 位 + `倍`（例: `12.3倍`） | 予想赤字または予想未定は `–` |
| `PBR（実績）` | 小数第 2 位 + `倍`（例: `0.85倍`） | BPS 非正または欠損は `–` |
| `配当利回り（予想）` | 小数第 2 位 + `%`（例: `3.20%`） | 無配予想は `0.00%`、予想未定は `–` |
| `ROE（実績）` | 小数第 1 位 + `%`（例: `7.1%`） | 自己資本非正または欠損は `–` |
| `自己資本比率` | 小数第 1 位 + `%`（例: `45.0%`） | 欠損は `–` |

### 操作

`#st-fin-tabs` のボタン `.ftab[data-sfin]` で `累計`・`3か月`・`進捗率`・`修正履歴` の 4 表を切り替える。

### 空とエラー

算出できない指標カードは `–` を表示する。`GET /api/earnings/detail/{code}` が `404`（短信未収録）のときは `#st-cum-tbl`・`#st-q-tbl`・`#st-prog-tbl` に `データなし`、`#st-rev-tbl` に `修正履歴なし` を出し、`404` 以外の失敗時は 4 表すべてに `読み込めませんでした。` を出す。

### スマホと PC

PC では `#st-metrics` を 5 列均等幅で横に並べ、スマホ（`640px` 以下）では 2 列グリッドに折り返す。

## 株価

### 目的

分割調整済みの株価・移動平均・出来高・売買代金に、過去の予想 PER バンド・業績の階段（営業利益・予想 PER・時価総額÷営業利益）・決算発表後の騰落率を重ねて確認する。

### 要素

上部に操作バー `.chart-bar`、中央に Lightweight Charts（v4.2.0）のチャート領域 `#s-chart`（既定高さ `460px`、業績の段を表示中は `560px`）とメッセージ `#chart-msg`、その下にイベント切替 `.evt-toggles`、最下部に決算発表後パフォーマンス表 `#ep-wrap` を置く。

`.chart-bar` の各コントロールと描画規則は以下のとおりである。

| コントロール | 選択肢・既定値 | 描画規則 |
|---|---|---|
| 足種 `.tf[data-tf]` | `日足`（`D`、既定）・`週足`（`W`）・`月足`（`M`）・`年足`（`Y`） | 初期表示期間は日足 1 年・週足 3 年・月足 10 年・年足全期間とし、ドラッグで上場来まで遡れる。週足（月曜始まり）・月足・年足は日足配列からブラウザ側で集計し、各足の日付は期間の最終営業日とする |
| 対数 `#log` | チェックボックス（既定 OFF） | 価格軸を対数スケールにする。対 TOPIX 比較が ON の間は無効化する |
| 対 TOPIX `#rel` | `対TOPIX (%)`（既定 OFF） | 表示期間の左端営業日を `0%` とし、`((銘柄終値 / 左端) / (TOPIX終値 / 左端) - 1) * 100` のベースライン折れ線（プラスは `--up` 赤、マイナスは `--down` 緑）を描く。パン・ズームのたびに左端を取り直し、ON の間は移動平均・下段・PER バンド・業績の段を隠す |
| 移動平均 `.ma-cb[data-i]` | 3 本チェックボックス（既定すべて ON） | 日足は `MA5`・`MA25`・`MA75`、週足は `MA13`・`MA26`・`MA52`、月足は `MA6`・`MA12`・`MA24` を青 `#2c6bed`・橙 `#e09b2d`・紫 `#9b59b6` で描く。年足ではチェックボックスを隠して描かない |
| 下段 `#chart-sub` | `出来高`（`vol`、既定）・`売買代金`（`tv`）・`下段なし`（`none`） | チャート下部に陽線日は赤半透明、陰線日は緑半透明のヒストグラムを描く |
| 業績の段 `#chart-fund` | `業績なし`（`""`、既定）・`営業利益`（`op`）・`予想PER`（`per`）・`時価総額÷営業利益`（`mcop`） | チャート最下段（高さ比率約 `26%`）に横軸を揃えて描く（KAB-300）。週足・月足・年足では各足の最終営業日時点の値を取る |

| 四半期単独営業利益（`op_q`）と 12 か月累計営業利益（`op_ttm`） | 決算短信の累計営業利益 `OP` から同一年度の直前四半期累計を引いて 3 か月単独 `op_q` を求め、連続する直近 4 四半期がすべて揃った時点のみ合算して `op_ttm` とする（途中に 1 四半期でも欠損があれば `null` として線を切る）。銀行など営業利益を開示しない銘柄は両方 `null` になる |

### 操作

足種・対数・対 TOPIX・移動平均・下段・業績の段・PER バンドの切り替えは、取得済みの配列からブラウザ側で即座に再計算して描き直す（対 TOPIX を初めて ON にしたときのみ `GET /api/topix` を取得する）。

同じ銘柄を開いている間はサブタブを切り替えて戻っても再取得しない。別銘柄へ移動してから戻った場合も、`chartGet` が最大 30 件の URL をメモリ上で 10 分間保持するため 10 分以内は通信を行わず、10 分経過後は `ETag` による条件付きリクエスト（未変更なら `304`）で検証する。

### 空とエラー

`GET /api/chart/{code}` が `404` のときは `#s-chart` を隠して `#chart-msg` に `株価データなし` を出し、それ以外の失敗時は `読み込めませんでした。` を出す。営業利益が無い銘柄で `営業利益`・`時価総額÷営業利益` を選んだときや、予想 EPS が無い銘柄で `予想PER`・`PERバンド` を選んだときは、エラー文を出さずに該当系列のみ描画しない。

### スマホと PC

`.chart-bar` は画面幅に応じて複数段へ折り返す。スマホ（`640px` 以下）では `.chart-legend` の 4 本値見出しを `O`・`H`・`L`・`C` に縮め、前足比の差額を省いて騰落率のみを表示する。

|---|---|
| `#st-holders-large` | 提出者ごとに最新の報告書を集約した大量保有者テーブル（`table.sheet`、最大 80 社）を出す。列は `提出者`（`#holders/{edinet_code}` へのリンク + 共同保有者があるときの `(共同N)`）・`保有割合`（`XX.XX%`）・`前回比`（`+X.XXpt` `.pos`・`-X.XXpt` `.neg`・`±0.00pt`・初回提出は `新規` `.b-init`）・`株数`（欠損は `–`）・`報告義務発生日`（`title` に `提出日 YYYY-MM-DD`、未来日または提出日より 30 日超後の異常値は `.odd-date` で `--warn` 色）の 5 列とする。保有割合 5% 以上の提出者を割合降順で先に並べ、最新報告が 5% 未満（5% 以下への減少変更報告）の提出者は区切り見出し行 `tr.below-h`（`5%未満`）の下に `tr.below` で淡色表示する |
| `#st-holders-chart` | 保有割合 5% 以上の提出者上位最大 6 社について、直近 5 年分の報告履歴 `history`（2 回以上の報告がある社が 1 社以上あるときのみ）を色分けした階段線 SVG で描く |
| `#st-holders-treasury` | 見出し `自己株` の下に最新の自己株券買付状況報告書から `発行済 X株 / 自己株 Y株（Z.ZZ%） YYYY-MM` を出し、進行中の取得枠決議ごとに進捗バー `.hd-bar`・進捗率 `XX.X%`・`決議 YYYY-MM-DD 〜 YYYY-MM-DD　累計 A株 / 枠 B株` を並べる |

### 操作

`#st-holders-large` の提出者リンクを押すと、大量保有報告書タブの保有者画面 `#holders/{edinet_code}` へ遷移する（パンくずで元の銘柄の `株主` へ戻れる）。

### 空とエラー

大量保有者が 0 件のときは `#st-holders-large` に `大量保有報告書はありません` を出して `#st-holders-chart` を隠す。自己株券買付状況報告書が無いときは `#st-holders-treasury` に `自己株券買付状況報告書はありません` を出す。`GET /api/stock/{code}/holders` が失敗したときは `#st-msg` に `読み込めませんでした。` を出す。

### スマホと PC

`#st-holders-large` は `.tbl-wrap` で横スクロールし、スマホ（`640px` 以下）では左端列の `sticky` を外す。`#st-holders-chart` の SVG は枠幅に合わせて伸縮する。

## 説明資料

### 目的

決算説明資料の原本 PDF を VPS に保持し続けずに、抽出済みのページ別要約・数値表・自動生成グラフで内容を素早く把握する（KAB-350）。

### 要素

`#st-deck-detail` 上部に書類見出し `.deck-head`（種類バッジ `説明資料`・開示日時・題名）と、資料全体の要約 `.deck-doc-summary`（`extract.summary` があるとき）を置く。

その下にページごとの `.deck-page`（`p.{page_number}` + スライド見出し + 要約文 + 自動グラフ `.deck-chart` + 数値表 `table.sheet.deck-tbl`）を並べる。表紙・目次・免責事項など見出し・要約・エラーがすべて空のページは省き、読み取り失敗ページには `.deck-page-err` で `このページは読めませんでした。` を出す。

数値表と自動グラフの描画規則は以下のとおりである。

| 対象 | 描画規則 |
|---|---|
| 数値表 `table.sheet.deck-tbl` | 列見出しの下段 `.under` に `col_kind` の日本語名（`実績`・`予想`・`計画`・`参考`）を出し、内訳の子行（`parent_item` あり）は `.deck-sub` で左インデント（`1.5em`）する。負値は `.neg`、先頭 `+` の増減表記は `.pos` で色分けする |
| 自動グラフ `.deck-chart`（1 表最大 3 個） | `actual`・`forecast`・`plan` の期間列で有効値が 2 期以上ある行だけを対象とし、増減・前期比・達成率列や 1 株指標（`EPS`・`BPS`・`DPS`・配当）はグラフ化しない。予想・計画の期は破線枠の棒または白抜き点で実績と区別し、凡例に `破線は予想・計画` を添える |
| グラフ種別の選択 | 割合（`%`・`pts`・`pt`・`ポイント`）と為替レートは折れ線グラフ（同一単位の単独行を最大 4 系列まで束ねる）、金額・数量は縦棒グラフ（単独行は同一単位を最大 3 系列まで束ね、親行に内訳子行が 2 行以上ある組は積み上げ縦棒 + 合計ラベルにする）で描く。`百万円`・`千円`・`円` などの金額単位は値の大きさに応じて `兆円`・`億円`・`万円` 等へ自動換算する |

### 操作

パンくず `#crumb` の `ニュース` またはサブタブの `ニュース` を押すと、`#stock/{code5}/news` の一覧へ戻る。

### 空とエラー

説明資料の状態に応じた表示文言は以下のとおりである。

| 状態 | 表示文言 |
|---|---|
| `GET /api/stock/{code}/decks/{key}` が `404` | `説明資料が見つかりません。` |
| `GET /api/stock/{code}/decks/{key}` が `404` 以外で失敗 | `読み込めませんでした。` |
| `document.status == "submitted"` | `読み取り中。` |
| `document.status == "failed"` | `読めなかった。` |
| `document.status == null` | `まだ読み取っていません。` |
| `document.status == "done"` で抽出本文が空 | `読み取り済み。` |

### スマホと PC

自動グラフの SVG は描画時のコンテナ実幅（`320px`〜`760px` にクランプ）を座標幅 `DECK_W` として描くため、スマホでも軸や値の文字が縮小して潰れない。数値表は `.tbl-wrap` で横スクロールし、スマホ（`640px` 以下）では左端列の `sticky` を解除する。

## API

エンドポイント共通の規約は [API 仕様](api.md)、JS と DB テーブルの対応図は [画面設計: 銘柄](gen/stock.md) を参照する。銘柄タブ固有の主要 API と応答構造は以下のとおりである（コード引数は 4 桁・5 桁どちらでも受け付け、存在しない銘柄は `404` を返す）。

| エンドポイント | 用途と主なクエリ・応答 |
|---|---|
| `GET /api/stocks/search?q=…` | 銘柄検索候補を `{results: [{code, name, market, sector33}]}` で最大 20 件返す。`q` が空文字なら空配列を返す |
| `GET /api/stock/{code}/overview` | 共通ヘッダーと概要の指標を `{code, name, market, sector33, quote, metrics, next_earnings}` で返す（任意の `today` 対応）。決算期未定時は `next_earnings` が `{"date": null, "fq": null}` になる |
| `GET /api/stock/{code}/holders` | 大量保有者一覧 `large_holders`（`filer_edinet_code`・`filer_name`・`holding_ratio`・`prev_ratio`・`shares_held`・`joint_count`・`obligation_date`・`file_date`・直近 5 年の `history`）と自己株状況 `treasury`（`report_month`・`filing_date`・`issued_shares`・`treasury_shares`・`treasury_ratio`・`resolutions`）を返す（任意の `today` 対応） |
| `GET /api/stock/{code}/financials` | 財務 3 表を `{code, statement, basis, has_consolidated, has_non_consolidated, accounting_standard, cumulative, periods, rows, earlier}` で返す。クエリは `statement`（`BS` 既定・`PL`・`CF`）、`periods`（`1`〜`20`、既定 `8`）、`consolidated`（`auto` 既定・`true`・`false`）を受け取る |
| `GET /api/stock/{code}/filings` | 短信・予想修正の一覧（最大 200 件）を `{code, name, market, sector33, filings}` で返す。各要素は `source`（`"xbrl"` または `"pdf"`）と `documents` を持つ |
| `GET /api/stock/filings/{filing_id}/documents/{seq}` | サニタイズ済み iXBRL 原文 HTML（`text/html`、CSP ヘッダー付き）を返す |
| `GET /api/stock/pdf/{disclosure_no}` | PDF 変換短信 HTML（`tdnet_pdf_documents.status == "ok"` のみ、CSP ヘッダー付き）を返す |
| `GET /api/stock/{code}/decks` | 決算説明資料の一覧（最大 200 件）を `{code, decks: [{key, disclosed_date, disclosed_time, title, status, summary}]}` で返す |
| `GET /api/stock/{code}/decks/{key}` | 説明資料 1 冊の `{document, extract, pages}` を返す（原本 PDF は返さない） |

上記のほか、概要サブタブは `GET /api/earnings/detail/{code}`（[決算速報](earnings.md)「API」）、株価サブタブは `GET /api/chart/{code}`・`GET /api/topix`・`GET /api/earnings-performance/{code}`（[API 仕様](api.md)「株価チャート・銘柄」）を併用する。

## 対象外

以下の項目は本画面の対象外とする。

1. 板情報・歩み値・日中足（分足・ティック）は扱わない。
2. 移動平均以外のテクニカル指標（RSI・MACD・ボリンジャーバンド等）は置かない。
3. アナリストのコンセンサス予想は扱わない。
4. 適時開示のうち、決算短信・業績予想修正・決算説明資料以外の一般リリースは扱わない。
5. 決算説明資料の原本 PDF ファイル配信およびスライド画像表示は行わない。
6. 有価証券報告書の「大株主の状況」（半期ごとの名簿）は扱わず、EDINET の大量保有報告書と自己株券買付状況報告書のみを対象とする。
