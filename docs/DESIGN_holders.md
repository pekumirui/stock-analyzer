# 保有者タブ

データは既存の `large_holding_reports` / `large_holdings` と日足。取込は `docs/DESIGN_edinet.md` §5。銘柄側の株主タブは `docs/DESIGN_stock.md`。共通見た目は `docs/SCREEN_SPEC.md`。

## 誰のための画面か

大量保有の提出者（運用会社・事業会社・個人）が今何を持っていて、最近増やしたか減らしたかを、保有者の名前から見たい自分。銘柄の株主タブから人をたどってもここに来る。

## 画面と遷移

ヘッダーの `保有者` タブ（`data-tab="holders"`）。ナビの末尾（ランキングの右）。PTS タブは動かさない。

| 画面 | ルート |
|---|---|
| 検索と最近の動き | `#holders` |
| 保有者 | `#holders/{edinet}`（`E` + 数字 5 桁） |

- 開いたときは検索と最近の動き。再読込は保有者まで戻す（`ui.route` にも同じパスを残す）
- 銘柄の株主タブの提出者名は `#holders/{edinet}` を開く（`gotoHolder`）
- 銘柄名は銘柄タブの株価へ（`gotoChart`）
- 形の違う EDINET コードは一覧へ戻す

## データ形

検索は `GET /api/holders/search?q=`。最近の動きは `GET /api/holders/activity`。保有者は `GET /api/holders/{edinet}`。銘柄の株主タブは `GET /api/stock/{code}/holders`。

共同保有・表記ゆれは `large_holdings.edinet_code` 単位。コードの無い行は保有者ページに出さない（検索もヒットしない）。銘柄の株主タブは提出者（書類の `filer_edinet_code`）でまとめ、共同保有は 1 行（書類の合計）。

最新の保有は `is_latest` かつ取下げでない `parsed` の報告を、発行体ごとに提出日（`file_date`、同時刻なら `submit_datetime`）が新しい 1 件。推移は同じ条件の報告を報告義務発生日の順に最大 5 年。

時価の目安は最新終値 × 保有株数。平均取得単価の目安は `total_funds` ÷ 保有株数、評価損益の目安は（終値 − 平均取得単価）× 株数。0・欠損・保有株数 0・取得資金が正でない・義務発生日以降に分割（`adj_factor` が最新と違う）は出さない。画面に「目安」と書く。

報告義務発生日が提出日より 1 か月を超えて先、または今日より先の行は消さない（元データの誤記があり得る）。最近の動きの並びは提出日。日付列は報告義務発生日のまま出し、提出日より 1 か月超先なら注意色。

動きの種類は保有者本人の割合（`large_holdings`）で決める。新規 5% 超え（直前が無い、または様式が大量保有報告書・特例報告）/ 買い増し / 売り / 5% 割れ（直前 5% 以上かつ今回 5% 未満）。割合が変わらない行（住所変更・担保契約だけなど）はフィードに出さない。

## 検索と最近の動き

**目的。** 保有者を名前か EDINET コードで探し、市場全体の直近の増減を見る。

**要素。** 上から:

1. 入力 `#hd-sym`（保有者名か EDINET コード。候補 `#hd-suggest` は検索 API の最大 20 件、`名前  EDINET`）
2. 最近の動き `#hd-feed`（`table.sheet`）。列は左から 日付（報告義務発生日 `YY/MM/DD`。提出日より 1 か月超先なら注意色。`title` に提出日）、種類（新規5%超え / 買い増し / 売り / 5%割れ）、保有者、銘柄（先頭 5 文字。下に 4 桁コード。未上場は発行者名だけ）、保有割合（下段に前回からの差 `+1.19pt`）

**操作。** 入力すると候補を出す。候補をクリックか Enter（先頭の候補）で保有者ページ。Esc か外のクリックで候補を閉じる。保有者名・銘柄名をクリックするとそれぞれのページ。

**空とエラー。** 動きが無ければ `最近の大量保有の動きはありません。` API 失敗は `読み込めませんでした。` 候補が無ければ箱を閉じる。

**スマホと PC。** 同じ構造。表は横スクロール。

## 保有者

**目的。** その人が今持つ銘柄と、選んだ銘柄の推移と、その人の最近の動きを見る。

**要素。** 上から:

1. `← 保有者` `#hd-back` と題 `#hd-title`（名前と EDINET コード）
2. 注記 `#hd-note`（`時価・平均取得単価・評価損益は目安。取得資金の書き方・分割・無償取得では出さない。`）
3. 銘柄一覧 `#hd-holdings`（`table.sheet`）。列は左から 銘柄、保有割合、前回からの差、株数、時価（目安）、平均取得単価（目安）、評価損益（目安）、報告義務発生日、保有目的（先頭の 1 行）。保有割合の大きい順。最新が 5% 未満の銘柄は下にまとめ、淡色にする。行を押すとその銘柄の推移
4. 保有割合の推移 `#hd-chart`。上の表と同じ並びで最大 6 銘柄の折れ線（横は報告義務発生日、縦は保有割合）
5. 選んだ銘柄の推移 `#hd-series`。報告のたびの日付・株数・保有割合（5 年）。表と、その銘柄だけの折れ線（株数と割合）
6. 最近の動き `#hd-activity`。一覧と同じ列から保有者を除いたもの。その人の分だけ

**操作。** 戻るで検索と最近の動き。銘柄名で銘柄タブの株価。表の行で推移の銘柄を切り替える（既定は 5% 以上の先頭、無ければ一覧の先頭）。ルートには銘柄を残さない。

**空とエラー。** その EDINET コードの報告が無ければ `保有者が見つかりません。` API 失敗は `読み込めませんでした。` 算出できない時価・単価・損益は `–`。

**スマホと PC。** 同じ構造。表は横スクロール。二段組にしない。

## API

`GET /api/holders/search?q=`

```json
{"q": "ブラックロック", "results": [{"edinet_code": "E09096", "name": "ブラックロック・ジャパン株式会社"}]}
```

`q` が空、または EDINET コード以外で 1 文字未満は `results: []`。名前の部分一致と EDINET コードの前方一致。最大 20 件。コードの無い保有者は出さない。

`GET /api/holders/activity?limit=80`（1〜200。省略 80）

```json
{"items": [
  {"kind": "buy", "edinet_code": "E09096", "holder_name": "ブラックロック・ジャパン株式会社",
   "code": "18020", "issuer_name": "株式会社大林組", "market": "プライム", "sector33": "建設業",
   "obligation_date": "2026-10-22", "file_date": "2026-10-28",
   "holding_ratio": 0.0202, "holding_ratio_prev": 0.0195, "shares_held": 14008800,
   "news_id": "lS100ABCD"}
]}
```

`kind` は `new` / `buy` / `sell` / `below`。提出日の新しい順。未上場は `code: null`。

`GET /api/holders/{edinet}`

```json
{
  "edinet_code": "E09096", "name": "ブラックロック・ジャパン株式会社",
  "holdings": [
    {"code": "18020", "name": "大林組", "market": "プライム", "sector33": "建設業",
     "shares_held": 14008800, "holding_ratio": 0.0202, "holding_ratio_prev": 0.0195,
     "obligation_date": "2026-10-22", "file_date": "2026-10-28", "purpose": "純投資",
     "news_id": "lS100ABCD", "price": 1850.0, "price_date": "2026-10-28",
     "market_value": 25916280000.0, "avg_cost": 1914.0, "unrealized": -896563200.0,
     "history": [{"date": "2026-03-02", "shares": 12000000, "ratio": 0.018,
                  "file_date": "2026-03-08"}]}
  ],
  "activity": []
}
```

`holdings` は 5% 以上が先（割合の大きい順）、5% 未満がその後ろ。時価・単価・損益が出せないときは null。履歴は報告義務発生日の古い順（最大 5 年）。無ければ 404。

銘柄の株主は `docs/DESIGN_stock.md` の `GET /api/stock/{code}/holders`。

## 対象外

- 日ごとの売買履歴・約定単価・5% に届かない保有
- 有報の大株主上位、所有者別の構成、信用残・空売り残
- コードの無い共同保有者、第3共同保有者の文章だけの名前
- 報告義務発生日の誤記を取込側で直すこと
- ニュース詳細（大量保有の原文カード）。株主タブの提出者名は保有者ページへ
