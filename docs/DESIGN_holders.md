# 大量保有報告書タブ

データは既存の `large_holding_reports` / `large_holdings` と日足。取込は `docs/DESIGN_edinet.md` §5。銘柄側の株主タブは `docs/DESIGN_stock.md`。共通見た目は `docs/SCREEN_SPEC.md`。

## 誰のための画面か

大量保有の提出者（運用会社・事業会社・個人）が今何を持っていて、増やしたか減らしたかを、提出日または名前から見たい自分。銘柄の株主タブから人をたどってもここに来る。

## 画面と遷移

ヘッダーの `大量保有報告書` タブ（`data-tab="holders"`）。ナビの末尾（ランキングの右）。PTS はランキングの中（KAB-265）。

| 画面 | ルート |
|---|---|
| 提出日の一覧と検索 | `#holders` |
| 保有者 | `#holders/{edinet}`（`E` + 数字 5 桁） |

- 開いたときは提出日の一覧。再読込は保有者まで戻す（`ui.route` にも同じパスを残す）
- 銘柄の株主タブの提出者名は `#holders/{edinet}` を開く（`gotoHolder`）
- 銘柄名は銘柄タブの株価へ（`gotoChart`）
- 形の違う EDINET コードは一覧へ戻す

## データ形

保有者候補は `GET /api/holders/search?q=`。一覧は `GET /api/holders/activity`（提出日または検索）。保有者は `GET /api/holders/{edinet}`。銘柄の株主タブは `GET /api/stock/{code}/holders`。

発行体が株でない報告（`stocks.product_category` が `011` / `021` 以外。ETF・ETN・REIT・出資証券）は、保有者候補・一覧・保有者ページのどれにも出さない。`stocks` に無い発行体（未上場など）は出す。ProdCat がまだ 1 件も入っていない DB では絞らない。銘柄の株主タブは絞らない。

共同保有・表記ゆれは `large_holdings.edinet_code` 単位。コードの無い行は保有者ページに出さない（検索もヒットしない）。銘柄の株主タブは提出者（書類の `filer_edinet_code`）でまとめ、共同保有は 1 行（書類の合計）。

最新の保有は `is_latest` かつ取下げでない `parsed` の報告を、発行体ごとに提出日（`file_date`、同時刻なら `submit_datetime`）が新しい 1 件。推移は同じ条件の報告を報告義務発生日の順に最大 5 年。

時価の目安は最新終値 × 保有株数。平均取得単価の目安は `total_funds` ÷ 保有株数、評価損益の目安は（終値 − 平均取得単価）× 株数。0・欠損・保有株数 0・取得資金が正でない・義務発生日以降に分割（`adj_factor` が最新と違う）は出さない。表の見出し `title` に「目安」と書く。

報告義務発生日が提出日より 1 か月を超えて先、または今日より先の行は消さない（元データの誤記があり得る）。既知の年ずれは取込で補正する（KAB-269、`config/large_holding_date_fixes.json`）。一覧の並びは提出日。日付列は提出日（`file_date`、`YY/MM/DD`）。報告義務発生日が提出日より 1 か月超先なら注意色（`title` に報告義務発生日）。

動きの種類は保有者本人の割合（`large_holdings`）で決める。新規 5% 超え（直前が無い、または様式が大量保有報告書・特例報告）/ 買い増し / 売り / 5% 割れ（直前 5% 以上かつ今回 5% 未満）。割合が変わらない行（住所変更・担保契約だけなど）は一覧に出さない。

## 提出日の一覧と検索

**目的。** 選んだ提出日の大量保有を見る。銘柄や保有者で探すときは日付を外して当たる報告を見る。

**要素。** 上から:

1. 提出日 `#hd-date`（`input type=date`。初期値は Asia/Tokyo の今日）
2. 入力 `#hd-sym`（銘柄名・保有者名・証券コード・EDINET コード。候補 `#hd-suggest` は保有者検索 API の最大 20 件、`名前  EDINET`）
3. 一覧 `#hd-feed`（`table.sheet`。決算速報・ランキングと同じ見出し 11px・縞・`td.num`）。列は左から 提出日（`file_date`、`YY/MM/DD`。報告義務発生日が提出日より 1 か月超先なら注意色。`title` に報告義務発生日）、種類（`.qb`。新規5%超え / 買い増し / 売り / 5%割れ）、保有者（先頭 5 文字。下に EDINET。`title` に正式名）、銘柄（先頭 5 文字。下に 4 桁コード。未上場は発行者名だけ）、保有割合（下段に前回からの差 `+1.19pt`）

**操作。** 日付を変えると、その `file_date` の提出分を出す。検索欄が空のときだけ日付が効く。銘柄・保有者などで検索すると日付では絞らず、提出日の新しい順に出す。検索欄を空にすると選んでいた日付の一覧に戻る。入力すると保有者の候補も出す。候補をクリックか Enter（先頭の候補）で保有者ページ。Esc か外のクリックで候補を閉じる。保有者名・銘柄名をクリックするとそれぞれのページ。検索中は日付入力を無効にする。

**空とエラー。** その日が無ければ `この日の大量保有報告書はありません。` 検索が無ければ `該当する大量保有報告書はありません。` API 失敗は `読み込めませんでした。` 候補が無ければ箱を閉じる。

**スマホと PC。** 同じ構造。表は横スクロール。提出日・種類・保有者は `pinCols` で左に残す。

## 保有者

**目的。** その人が今持つ銘柄と、選んだ銘柄の推移を見る。

**要素。** 上から:

1. `← 大量保有報告書` `#hd-back` と題 `#hd-title`（名前と EDINET コード）
2. 銘柄一覧 `#hd-holdings`（`table.sheet`）。列は左から 銘柄、保有割合、差、株数、時価、取得単価、評価損益、義務発生日、保有目的。時価・取得単価・評価損益の見出し `title` は目安。数字は右寄せ・桁区切り。保有目的は先頭の 1 行のまま折り返さない（`title` に全文）。保有割合の大きい順。最新が 5% 未満の銘柄は下にまとめ、淡色にする。行を押すとその銘柄の推移（表は作り直さない）
3. 保有割合の推移 `#hd-chart`。上の表と同じ並びで最大 6 銘柄の折れ線（横は報告義務発生日、縦は保有割合）
4. 選んだ銘柄の推移 `#hd-series`。報告のたびの日付・株数・保有割合（5 年）。表と、その銘柄だけの折れ線（株数と割合）

**操作。** 戻るで提出日の一覧（検索中なら検索結果）。銘柄名で銘柄タブの株価。表の行で推移の銘柄を切り替える（既定は 5% 以上の先頭、無ければ一覧の先頭）。ルートには銘柄を残さない。

**空とエラー。** その EDINET コードの報告が無ければ `保有者が見つかりません。` API 失敗は `読み込めませんでした。` 算出できない時価・単価・損益は `–`。

**スマホと PC。** 同じ構造。表は横スクロール。二段組にしない。銘柄列は `pinCols` で左に残す。

## API

`GET /api/holders/search?q=`

```json
{"q": "ブラックロック", "results": [{"edinet_code": "E09096", "name": "ブラックロック・ジャパン株式会社"}]}
```

`q` が空、または EDINET コード以外で 1 文字未満は `results: []`。名前の部分一致と EDINET コードの前方一致。最大 20 件。コードの無い保有者は出さない。

`GET /api/holders/activity?file_date=2026-10-29&limit=80&offset=0`

`q` が検索として足りるとき（2 文字以上、または EDINET / 証券コード）は `file_date` を無視する。足りないときは `file_date`（省略時は Asia/Tokyo の今日）で `large_holding_reports.file_date` を等号検索する（`ix_large_holding_reports_file_date`）。`limit` は 1〜1000（省略 80。検索は 200 まで）。`offset` は 0 以上。

```json
{"file_date": "2026-10-29", "q": "", "has_more": false, "items": [
  {"kind": "buy", "edinet_code": "E09096", "holder_name": "ブラックロック・ジャパン株式会社",
   "code": "18020", "issuer_name": "株式会社大林組", "market": "プライム", "sector33": "建設業",
   "obligation_date": "2026-10-22", "file_date": "2026-10-28",
   "holding_ratio": 0.0202, "holding_ratio_prev": 0.0195, "shares_held": 14008800,
   "news_id": "lS100ABCD"}
]}
```

検索時は `"file_date": null` と `"q": "ブラックロック"`。`kind` は `new` / `buy` / `sell` / `below`。提出日の新しい順。未上場は `code: null`。件数は `limit` で打ち切り、続きがあれば `has_more: true`。

`GET /api/holders/{edinet}`

```json
{
  "edinet_code": "E09096", "name": "ブラックロック・ジャパン株式会社",
  "holdings": [
    {"code": "18020", "name": "大林組", "market": "プライム", "sector33": "建設業",
     "shares_held": 14008800, "holding_ratio": 0.0202, "holding_ratio_prev": 0.0195,
     "obligation_date": "2026-10-22", "file_date": "2026-10-28", "purpose": "純投資",
     "news_id": "lS100ABCD", "price": 1850.0, "price_date": "2026-10-28",
     "market_value": 25916280000.0, "avg_cost": 1914.0, "unrealized": -896563200.0,
     "history": [{"date": "2026-03-02", "shares": 12000000, "ratio": 0.018,
                  "file_date": "2026-03-08"}]}
  ],
  "activity": []
}
```

`holdings` は 5% 以上が先（割合の大きい順）、5% 未満がその後ろ。時価・単価・損益が出せないときは null。履歴は報告義務発生日の古い順（最大 5 年）。無ければ 404。`activity` はその人の動き（一覧と同じ形。画面には出さない）。

銘柄の株主は `docs/DESIGN_stock.md` の `GET /api/stock/{code}/holders`。

## 対象外

- 日ごとの売買履歴・約定単価・5% に届かない保有
- 有報の大株主上位、所有者別の構成、信用残・空売り残
- コードの無い共同保有者、第3共同保有者の文章だけの名前
- ニュース詳細（大量保有の原文カード）。株主タブの提出者名は保有者ページへ
- 一覧の無限スクロール。続きは `offset` / `has_more`
