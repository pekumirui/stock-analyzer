# 月次の行名

月次 KPI の行名正規化、7 層の分解、表示単位、保存名の凍結、および発行体別の改名・親子木規則の正本である。書き込み時の保存名決定は `canonicalize_element_label`、読み取り時の表示名と層分解は `monthly_element_label` が担い、どちらも `app/monthly/ingest.py` に実装する。

年別取得 API（`GET /api/v1/tables/{code}/{year}`）の各行は、DB の保存名 `element` に加えて派生の `label` オブジェクト（`display`・`group`・`metric_kind`・`series_kind`・7 層の各文字列・`breakdown_depth`）を返すため、SPA 側で文字列の再パースは行わない。

共通語彙と銘柄別定義の配置先、および関連仕様書は以下のとおりである。新しい銘柄固有の例外を足すときは、`AGENTS.md`・`docs/jobs/monthly.md`・`docs/screen/monthly.md` に 1 行追記するのではなく、必ず本ファイルの銘柄別セクションに追記する。

| 対象 | 正本ファイル | 役割 |
|---|---|---|
| 全銘柄共通の語彙 | `config/monthly/monthly_vocab.json` | 前年比語・合成語の分割・国・チャネル・スコープ・除去語・出退店・内訳・指標と `metric_kind` を定義する。`split`・`yoy_words`・`metrics` は配列の先頭から順に当てるため、長い語を先に並べる |
| 正規化手順 | `app/monthly/ingest.py` | 保護語の退避と復元、`_stitch_*` の連結順、状態語付き店舗数の正規表現、領域ツリーの振り分けを保持する |
| 銘柄別の改名 | `config/monthly/issuer_aliases.json` | 期間条件（`until`）付きの保存名リネームを定義する |
| 銘柄別の件数・率指標 | `config/monthly/issuer_metrics.json` | 特定の 5 桁コードでのみ指標として扱う件数語・率語を定義する |
| 発行体別の親子木 | `config/monthly/monthly_row_order.json`, `app/monthly/tree.py` | 年表の親子階層と指標タブの並びを定義する |
| 取込と `unit`・画面表示 | [月次の取込規則](monthly.md)、[月次](../screen/monthly.md) | 暦年の列割り当て、`unit` 変換、画面側の描画規則を定義する |

共通語彙や銘柄別辞書を変更しても、DB 上の既存行の保存名は自動では書き換わらない（「同一行・保存名の凍結」を参照）。新しく入る行の名前だけが新しい規則に従い、既存行とのずれはデプロイ時のドリフトログに現れる。

## 層の構成と語彙

### 7 つの層

正規化後の行名は空白区切りで `[国] [セグメント] [時間軸] [チャネル] [スコープ] [指標] [内訳]` の順に並ぶ。値が存在しない層は保存名に出力せず、API の `label` オブジェクトでは空文字列 `""` として返す。

各層が取り得る値と正規化時の変換規則を下表に示す。

| 層 | 代表的な値 | 正規化・分類の規則 |
|---|---|---|
| 国 | `日本`・`海外`・`米国` | 単独の `国内` だけを `日本` に変換する。国の語が2つある行は最初の1語だけを国にし、2語目以降はセグメントに残す（`海外 米国 店舗数` は国 `海外`・セグメント `米国` のまま。保存名も 31930 のエイリアスも変えない）。`国内リテール` や `米国子会社` のような複合語、`中国` などの未登録の国名はセグメントに残す。自動の木では国の語を節の名前から外し、同じ業態の節へ載せる（46800 の `米国 ボウリング 売上高` は `全体` › `ボウリング`）。国だけの行（26950 の `米国 店舗数`）は `日本 店舗数` と同じく全体の直下 |
| セグメント | 事業名・ブランド名・店舗名 | 国・時間軸・チャネル・スコープ・指標・内訳のいずれにも当たらない残余トークン（leftover）を保持する |
| 時間軸 | `単月` | 指標語がある行やスコープ付きの前年比行では除去されるため、正規化後はほぼ空になる。残った場合は `label.time_axis` に出す |
| チャネル | `直営`・`FC`・`直営+FC` | チャネル語を行頭に引き上げずセグメントの後ろに置く（例: `焼肉 直営 店舗数`）。`直営店舗`・`直営店` は `直営` に、`FC店舗`・`FC店`・`ＦＣ店舗`・`ＦＣ店`・`フランチャイズ` は `FC` に揃える。`直営店` が先に部分一致して `舗` が残らないよう長い語から順に処理する |
| スコープ | `既存`・`全店`・`全社` | `既存店`・`既存店舗` は `既存`、`全店舗` は `全店` に短縮する。アルペンの全社計と全店計のように対象範囲が異なるため、`全社` は `全店` に畳まない。`既存` と `全店` の両方がある行（`既存店全店`）は `既存` にする |
| 指標 | `売上高`・`連結売上高`・`客数`・`客単価`・`購入お客様数`・`出店`・`退店`・`転換出店`・`店舗数`・`稼働店舗数`・`取扱高`・`仕入高`・`客室収入`・`売上収益(IFRS)`・`ヴィンテージ商品売上高`・`稼働日修正後`・`調理済み商品お届け数（千食）`・`調理済み商品お届け数`・`営業所数`・`売上総利益`・`売上総利益率`・`売上原価`・`売上個数`・銘柄別の件数と率 | `売上` は `売上高`、`来客数`・`来客` は `客数`、`単価` は `客単価`、`総店舗数`・`全店舗数`・`店数` は `店舗数` に揃える。`連結` はセグメントにせず指標の接頭辞（`連結売上高`・`連結営業利益` など）にする。スコープは原資料にあるときだけ残し、空なら補わない |
| 内訳 | `ドラッグ`・`調剤`・`物販`、領域の子、`稼働店舗数` の子 | 指標が `売上高` または `稼働店舗数` のときに設定する。`label.breakdown_depth` は親が `0`、内訳が `1`、小枝が `2` になる |

### 指標の分類と出退店・状態語

`label.metric_kind` が `sales`・`customers`・`spend` のいずれかになる行は、必ず `label.metric` が非空でなければならない（`tests/monthly/test_monthly_label_snapshot.py` で検証する）。新しい指標語を追加するときは `config/monthly/monthly_vocab.json` の `metrics` と `metric_kind` の両方に登録する。

指標ごとの個別規則は以下のとおりである。

- `取扱高`（`CPAソリューション事業 取扱高` の残余は `CPAソリューション事業`）、`仕入高`（`76850` の `出張訪問買取 仕入高` は残余 `出張訪問買取` で自動の木の節に入り、`metric_kind` は `other`、#581）、`客室収入`（`ホテル 客室収入` の残余は `ホテル`）、`売上収益(IFRS)`（`百貨店事業 売上収益(IFRS)` の残余は `百貨店事業`、`metric_kind` は `sales`）はいずれも独立した指標とし、原資料に無いスコープは補わない。
- `売上総利益`・`売上総利益率`・`売上原価` は `metric_kind` を `other`、`売上個数` は `count` とする（KAB-126）。辞書登録が無いと「売上」を含むだけで `sales` と判定されて売上高と混同するため、明示的に区別する。辞書で `other` または `count` と決めた指標の前年比は、既存店・全店の代表系列（`series_kind`）に入れない。また 1 つの行名に指標語が 2 つ並ぶ旧保存名（`売上総利益 既存 売上高(前年比)`）では後ろの語を指標とし、前の語はセグメントに残して `既存 売上高` への潰れを防ぐ。
- `ヴィンテージ商品売上高`（`31740` の `既存 ヴィンテージ商品売上高(前年比)`）は複合語として保護し、途中の `売上高` で分割しない。
- `調理済み商品お届け数（千食）`・`調理済み商品お届け数`・`営業所数`（ワタミ宅食など）は外食の `店舗数` に畳まず独立した指標とする。`稼働日修正後` と `購入お客様数`（アスクルなど）も独立した指標とし、`購入お客様数` は `客数` に畳まない。
- `開店`・`開店数`・`開設`・`開設数` は `出店` に、`閉店`・`閉店数`・`閉鎖`・`閉鎖数`・`撤退`・`撤退数` は `退店` に変換する。`転換出店`・`転換出店数` は `出店` に畳まず `転換出店` とする。出退店は店舗数にもセグメントにもせず独立した指標とし、スコープは原資料にある `全店`・`既存` だけを残す。
- 店舗関連の行（`出店`・`店舗数`・ダミーの `店舗` と並ぶ行）にある `新規` は `出店` に寄せるが、売上や会員数の行にある `新規`（`主要商品 合計新規`・`新規 会員数` など）はセグメントに残す（#661）。
- `閉店中店舗数`・`転換準備による一時閉店中の店舗数`・`改装閉店中店舗数`・`開店準備中店舗数`・`出店予定店舗数`・`休業中店舗数` のような「状態語＋店舗数」はストックの `店舗数` であり、途中の `閉店`・`開店`・`出店` をフロー指標へ切り出さない（助詞の `の` だけ落として `転換準備による一時閉店中 店舗数` の形にする）。空白区切りの `閉鎖 店舗数` は従来どおり `退店` にする一方、空白なしの `閉鎖店舗数` は再パースで退店に変わらないよう `閉鎖店舗数` のまま保つ。
- 店舗関連の行の並び順は `出店` → `退店` → `純増`・`新設`・`改装`・`業態転換` → `店舗数` とする。`純増` などの調整語は名称を変えずに指標位置へ置く。
- `実店舗` と `EC` はセグメントとして扱い、`実店舗数` は `実` と `店舗数` に割らず `実店舗 店舗数` にする。

### 修飾語・複合語・内訳・除去語の扱い

連結・保護・内訳移動・ノイズ除去の規則は以下のとおりである。

- 分割トークンの `客 数` と `売 上` は先に `客数` と `売上` へ連結する。`既存直営店舗`・`既存直営店` は `直営 既存` に展開し、`直営店舗数` は `店舗数` を先に剥がして `直営 店舗数` にする。
- `入店`（`大丸 心斎橋店 入店 客数`）と `総額`（`百貨店事業 総額 売上高`）は指標の修飾語として扱い、行名には残したまま `label.group` からは外す（前者の `group` は `大丸 心斎橋店` で葉が `入店 客数`、後者の `group` は `百貨店事業` で葉が `総額 売上高` になる。`総額 連結売上高` のように残余が `総額` だけなら `group` は空になる）。
- `百貨店事業合計` は複合語として保護し、汎用の `合計` 除去で切り離さない（J.フロントでは後述のエイリアスで表 1 の名前へ寄せる）。複合語でない `全社合計`・`合計 店舗数`・`日本 合計 売上高` は通常どおり `合計` を落とす。
- `連結` はセグメントに残さず指標へ結合する。`連結売上高`・`連結 売上高` は `連結売上高`、`連結 全店 売上高` は `全店 連結売上高`、前年比の `連結 全店` は `全店 連結売上高(前年比)`、`連結 営業収益` は `連結営業収益` になる。
- 前年比（`yoy`）で行名がスコープのみ（`全店`・`既存`・`全社`）または「セグメント＋スコープ」（アルペンの `既存店計 単月`・`全店計 単月`・`全社計 ※ 単月`、ゼビオの `ゼビオ 単月 既存店`・`ゼビオ 単月 全店` など）である場合は、指標として `売上高` を補う。ただし、チャネル付きの `直営 全店(前年比)`、既に指標語がある `既存 売上総利益(前年比)`、および残余に `会員数` がある `会員数 既存(前年比)`（実数の `会員数 既存` と対称にし、`metric_kind` を `sales` にも `series_kind` を `existing`・`all_store` にもしない）には `売上高` を補わない。なお `客数 既存(前年比)` は従来どおり `既存 客数(前年比)` になる。
- `売上高` 行の残余が `ドラッグ`・`調剤`・`物販`（`内)ドラッグ店舗`・`（内 調剤）` などの括弧・`うち`・末尾 `店舗` は剥がす）である場合は内訳層（`depth=1`）へ移す（例: `MKG ドラッグ 全店 売上高` は `MKG 全店 売上高 ドラッグ`）。`調剤事業` や `内アパレル` はセグメントに残し、出店の `（内 開店）` も内訳にしない。
- `売上高` 行の残余が `グロース領域` または `サステナブル領域` とその子カテゴリである場合も内訳層へ移す。中節（`depth=1`）は `プロパティ`・`専門通販`・`呉服関連`・`アパレル雑貨`（`アパレル・雑貨` から中黒を除去）・`その他` であり、小枝（`depth=2`）は `プロパティ` 配下の `ホテル`・`インカム太陽光`（`インカム、太陽光` から読点を除去）と、`専門通販` 配下の `化粧品健康食品`・`グルメ`・`ワイン`・`ナース関連` である。親領域を持たない単独の `ホテル`・`その他` はセグメントのまま保ち、`_BREAKDOWN_CANON` には追加しない。
- `稼働 店舗数`・`稼働店舗数` は指標 `稼働店舗数` に揃え、その子の `管理テナント数`・`取引店舗数`・`増加`・`減少` は内訳（`depth=1`）にする。
- ノイズとして除去する語は、`合計`・`総計`・`小計`・`計`、店舗数行の `月末`・`期末`、`うち`・`内数`（チャネルの `FC` は残す）・`部門`・`店`・`全`、`対`（対前年比の残り）・`前期比`・`同期比`・`増減率`・`昨対`・`昨対増減率`・`昨年比`・`昨年比増減率`、`累計`・`店舗状況`・`対象`・`当年`、`購入お客様`（`ASKUL事業 購入お客様 客単価` は `ASKUL事業 客単価`）、指標やスコープがある行の `単月`・`Monthly`、単位表記の `（％）`・`（%）`・`(％)`・`(%)`・`%`・`（百万円）`・`(百万円)`・`売上（％）`・`売上（%）`、注記記号の `※`、数字だけの括弧や丸数字（`(1)`・`（2）`・`①`・`②` など）、年度帯（`2026年度`・`2026年（令和8年）度` など）、および単独の括弧文字である。`［売上高］全店` のような角括弧の見出しはパーサ側で中身を取り出す。

### 銘柄別の件数・率指標（`issuer_metrics.json`）

`受託施設数`・`訪問介護事業所数`・`総レセプト数(鍼灸込み)`・`件数`・`台数`・`入居率` のような銘柄固有の件数・率指標は、`config/monthly/issuer_metrics.json` に `{"<5桁コード>": ["語", ...]}` の形式で登録する。全銘柄に効く「末尾が `数` または `率` なら指標」という汎用規則を置くと、1 銘柄の都合で他銘柄の保存名が変わって既存行が消失したり（#534 で `23050`・`31740`・`81980` に影響、#545）、`家賃ベース入居率` が `入居率` で割れたりするため、必ず銘柄限定で定義する。

この辞書の照合と保存名への作用規則は以下のとおりである。

- 登録語は当該銘柄の `code` を渡した層分解（`monthly_element_label(element, unit, code)` と自動の親子木）および `code` 付きの `canonicalize_element_label`・`normalize_element_tokens` でのみ指標になる。辞書に無い銘柄や語は残余（leftover）のまま残り、自動の木では会社直下の行名葉になるだけで DB は壊れない。新しい銘柄で件数・率の行を投入したときに随時追加する。
- `label.metric_kind` は、語が `率` で終わるときは `rate`、それ以外は `count` になる（KAB-39）。共通語彙に既にある `売上総利益率` は `other` のまま変わらない。
- 照合はトークンの完全一致のみで行い、前方一致や後方一致は行わない（`売上個数` は `個数` に当たらず、`家賃ベース入居率` は `入居率` に当たらない）。`_METRIC_PREFIX` が先に剥がす語（`…店舗数` など）や共通指標と完全一致する語は置けないが、`一品単価` のように共通の `単価` で割れる複合語は登録できる（KAB-121）。
- 銘柄別の指標語が取れた行では、前年比で指標が空のときに補う既定の `売上高` を足さない。また `拠点数` が別の指標の前に付く見出し（`拠点数 営業所数`）は保存名で `拠点数` を落とす。`業態転換数` は従来どおり `_peel_adj_metric` で処理する。
- 保存名の語順並べ替えは、共通語彙が分割するとき、既定の `売上高` を補うとき、および残余が銘柄別指標そのものでスコープがあるときに限定する（`31740` の `粗利率 既存` は残余が `粗利率`＋スコープなので `既存 粗利率` の指標位置へ並べ替える、KAB-127）。一方、`直営 タイムズパーキング 件数`、`14350` の `入居率 全体`・`入居率 自社施工`・`入居率 管理受託`・`管理戸数 全体`（KAB-11・#662・KAB-39）、`70620` の `マッサージ事業 総レセプト数(鍼灸込み) 直営`、および件数語の後ろに別指標がある `売上個数 既存 売上高(前年比)` は `code` を渡しても保存名の語順を変えない。
- 辞書に語を追加しても既存の DB 保存名は起動時に書き換えない（「同一行・保存名の凍結」を参照）。

## 前年比と実数の扱い

前年比（`yoy_index`・`yoy_pct`）と実数（`number`）の行名・並び順は以下の規則で扱う。

- 入力 `unit` が前年比（`yoy_index` または `yoy_pct`）の行は、`monthly_vocab.json` の `yoy_words`（`前年同期対比`・`前年同月比`・`前年対比`・`前期対比`・`前年同月`・`(前年比)`・`（前年比）`・`前年比`・`(前期比)`・`（前期比）`・`前期比` の 11 語）を変化しなくなるまで取り除いたうえで、末尾に半角括弧の `(前年比)` を 1 回だけ付ける。
- 入力 `unit` が `number` の行には `(前年比)` を付けない。`number` の `売上高` と `yoy_index` の `売上高(前年比)` は別行として保存する。
- 年表の行並びでは同じ指標の実数群を先に置き、前年比群を後ろに置く。内訳行もそれぞれの塊の中にまとめ（例: `売上高` → `プロパティ` → `ホテル` のあとに `売上高(前年比)` → `プロパティ(前年比)` → `ホテル(前年比)`）、実数と前年比を小グループ単位で交互に混ぜない。
- 保存名と API の基本正規化は同じ規則を使い、保存名は常に正規名とする。全角・半角を無差別に潰す NFKC 正規化は保存名に対して行わない。

## 同一行・保存名の凍結

DB に保存された `monthly_elements.element` は凍結データとして扱う（#545）。正規化と銘柄エイリアスは新しく入ってくる行名にだけ適用し、既存の行を最新の規則から自動的に作り直すことはしない。

- `ingest` および `POST .../elements` は、入力行名を正規化して銘柄エイリアス（`ingest` は `as_of` のあとに列の暦年、`POST` は指定 `year`）を掛け、DB の保存名と完全一致する行だけを更新対象とする。一致する行が無ければ新規行を作成し、既存の類似行を勝手に改名・統合しない。
- `PUT .../elements` で既存行の `unit` を変更したときだけは、その行を新しい `unit` に対応する正規名へ付け替える（例: `売上高` を前年比に変えると `売上高(前年比)` になる）。付け替え先の正規名が既に存在する場合は値をマージし、同じ月に両方とも非 `NULL` で異なる値が入っていれば `409 FOLD_CONFLICT` を返す。
- アプリ起動・定期バッチ・デプロイ処理は既存の保存名を書き換えない。デプロイ時に走る `jobs/migrate.py` は、現行の正規化規則とエイリアスを全行に当て直した場合に名前が変わる行数（ドリフト）を数え、1 件以上あれば `月次の保存名ドリフト: N 行 / M 銘柄 (...)` を 1 行ログに出力する。任意の時点で確認したいときは GitHub Actions の `Monthly names` ワークフローを既定の `plan` で実行する。
- 既存行の保存名を実際に付け替える作業は `jobs/monthly/monthly_names.py`（引数なしは書かずに計画表示、`--apply` で書き込み、`--code <code>` で銘柄限定、`--drop-cumulative` で累計行の削除、`--out <path>` で計画 JSON 保存）で行う。正規化規則や `config/monthly/issuer_aliases.json` を変更した PR は、デプロイ後に Actions の `Monthly names`（`workflow_dispatch`）を `plan` → `apply` の順で実行して既存行を揃える。`apply` を実行しないまま次の月次を取り込むと新旧 2 行に割れるが、値は消えないため後から `apply` を流せば統合される。
- `apply` で短い旧名を正規名へ統合するときは、正規名の行を残して非 `NULL` の値を優先マージし、同じ月で両方が非 `NULL` かつ不一致であれば正規名側の値を残して衝突リストに記録する。
- `GET` 系 API は DB の保存名を書き換えず、派生フィールド `label` だけを添えて返す。SPA の複数年比較表・系列選択・チャートは `label.display` を行キーとして束ねるため、年ごとに保存名が異なっていても表示名が一致すれば画面上では 1 行にまとまる。

## 行名スナップショット

正規化規則や辞書を 1 か所直した際に想定外の銘柄・行まで変化していないかを、本番データの全行スナップショットで検証する（KAB-10・KAB-17）。手書きの単体テストでは思いついた例しか守れないため、スナップショットテストを正本の回帰確認とする。

- `tests/monthly/golden/labels.tsv` には本番の全銘柄・全年・全行の入力（銘柄コード・年・並び順・経路 `via`・`unit`・送信時の元の行名）と、現行コードを通した期待出力（保存名・`unit`・`label` の主要項目・親子木の `path` と `metric`）を記録する。
- スナップショット検証は一時 SQLite を組み立てて本番 API と同じ `table_year_payload` を通す。名前の通し方は `POST .../elements` と同じ暦年エイリアスとし、`PUT .../doc` 由来の行（`via="doc"`）は名前を正規化せずそのまま投入する。
- CI の `tests/monthly/test_monthly_label_snapshot.py` は期待値とずれた行をすべて列挙して失敗する。意図した規則変更であれば `python tools/monthly/label_snapshot.py update` で TSV を更新し、PR 上の TSV 差分に想定外の行が混じっていないかを確認する。
- 本番からの入力取り直しには `python tools/monthly/label_snapshot.py collect` を使う。`--api https://kabukpi.com` は公開 API の保存名を `legacy` 経路として取り込み、`--db stock.db` は `monthly_element_sources` に残っている送信時の元の行名から取り込む。ソース記録が始まる前に API 経由で投入された行は `tests/monthly/golden/labels_known.tsv` に手作業で追記しておくと、`collect` が `known` として取り込む。

## 入力の拒否条件

`ingest` および行操作 API で入力時に拒否する行名の条件は以下のとおりである。

- 前期・前年同月・前年同期・前年の実数行（`前 年` や `前年店舗数` を含む）は、正規化の前に `400 PRIOR_PERIOD_ELEMENT` で拒否する。対象は `ingest` と `POST .../elements` であり、直後に `比`・`対比`・`差`・`増減` が続く今期の比率・差額行は通す。HTML パーサと PDF sidecar 投入ジョブは該当行を事前に落として残りの行だけを投入する。
- 行名の文字列長は、正規化前の生入力と正規化・エイリアス適用後の保存名のどちらも 1〜50 文字でなければならず、50 文字を超える場合は `400 INVALID_PARAM` で拒否する。

## 銘柄固有の改名・取込・親子木規則

### 銘柄別の改名規則（`issuer_aliases.json`）

`config/monthly/issuer_aliases.json` は銘柄ごとの保存名リネーム規則を保持する。辞書のキー自体も `canonicalize_element_label` を通した形で記述し、辞書に当たらない行名はそのまま通す。`tests/monthly/test_monthly_ingest.py` には銘柄ごとの個別テスト分岐を足さず、`plan_issuer_alias_cases` が JSON からテストケースを自動生成する。

- `ingest` では最初に `as_of < until` で照合し、各列の暦年が決まったあとにもう一度 `year <= until.year` で照合する。`POST`・`PUT`・`jobs/monthly/monthly_names.py` では `year <= until.year` で照合する。

2027 年 3 月期 8 月度（#473、`https://www.release.tdnet.info/inbs/140120260907532362.pdf`）に基づき、国内の全店・既存の売上高と客数、既存の客単価、`土日祝日前年差異` を根に置き、商品別の既存店前年比（`タイヤ`・`カーエレクトロニクス`・`オイル`・`バッテリー`・`アクセサリー`・`サービス`・`車販売`）を既存売上高の内訳とし、原資料の字下げに従って `車検・整備` を `サービス` の子に置く（店舗数は月次行に無いため入れない。指標順は `既存 売上高` → `日本 既存 客数` → `既存 客単価` → `日本 全店 売上高` → `日本 全店 客数` → `土日祝日前年差異` で先頭表示は `日本 既存 売上高(前年比)`）。

#### アークランズ（`98420`）

小売事業と外食事業（アークランドサービスHD）の表（#484）において、外食の国内総店舗数（保存名 `日本 外食事業 店舗数`、2026 年 7 月は `722 = かつや 513 + その他 209`）を `rows` 完全一致で `外食事業`（▸ `かつや`・`その他`）の `店舗数` に割り当てる。全店売上高は外食事業節、かつや既存店はかつや節に置き、指標順は `既存 売上高` → `既存 客数` → `既存 客単価` → `全店 売上高` → `店舗数` とする。

#### 王将フードサービス（`99360`）

売上・客数・客単価は直営店のみのため `直営 全店/既存 ...` を根に残し、店舗数推移（#818、2026 年 9 月は全店 `726 = 直営 549 + FC 177`、開店・閉店は未投入）は `prefix` を使うと直営売上が店舗節に混ざるため、`rows` 完全一致で `全店 店舗数` の下に `直営 店舗数`・`FC 店舗数` を束ねる（#592）。

#### 太洋物産（`99410`）

2026 年 9 月期 8 月度 PDF に基づき、会社合計（2026 年 1 月 `1,447 ≒ 930 + 118 + 374 + 23`）の下に `食料部`（`930 ≒ 牛肉 213 + 加工食品 330 + 輸入鶏肉 160 + その他鶏肉 23 + 国産鶏肉 203`、旧 `その他畜産` も含む）・見出し `農産部`（`118`、▸ `農産品`）・`中国開拓部`（`374 ≒ 中国関連 327 + 化学品 46`）・`生活産業部`（`23`、▸ `豚肉`）を置く（旧 `営業開拓部計` は木に入れない）。

#### バローHD（`99560`）

前年比 4 指標（全店売上高・既存売上高・既存客数・既存客単価）について、`SM`・`バロー`・`スーパーマーケット（SM）` を `スーパーマーケット`、`HC`・`ホームセンター（HC）` を `ホームセンター`、`DG`・`中部薬品` を `ドラッグストア` へエイリアスで寄せる（`until: "2099-12-31"`、HC 各社名であるダイユーエイト・ホームセンターバロー・タイム・アレンザと `グループ総 店舗数` は寄せず、中部薬品は将来単体と全社計が並んだ時点で見直す）。親子木（#474）は原資料の順に `スーパーマーケット`（2026 年 8 月全店 `104.4`＝資料 `4.4%`、店舗 `366` のうちバロー単体 `249`）・`ドラッグストア`（既存 `101.5`＝資料 `1.5%`）・`ホームセンター` を根の子に並べ、`グループ総 店舗数`（2025 年 3 月 `1,449`、2026 年 8 月末の `1,560` は行なし）を根の `店舗数` とする。指標順は `既存 売上高` → `既存 客数` → `既存 客単価` → `全店 売上高` → `店舗数` である。
