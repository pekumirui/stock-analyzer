# 取込と保存の規則: サプライ

サプライタブで使う素材の月次統計（`material_monthly`）と相手国別貿易統計（`material_trade_country`）の取得・正規化・保存規則を定める。ジョブの起動時刻・引数・読み書きするテーブルは [ジョブ設計: サプライ](gen/supply.md)（自動生成）を参照する。画面表示の仕様は [サプライタブ](../screen/supply.md) に置く。

## 素材の月次量と相手国別統計（`material_stats`）

対象ジョブは `jobs/supply/material_stats.py` であり、統計品目と素材 ID の対応表は `config/supply/material_stats.json`、共通の変換・書き込み処理は `app/supply/material_stats.py` に置く（定義は [ジョブ設計: サプライ](gen/supply.md) を参照する）。外部からのデータ取得は `app/supply/estat.py`（e-Stat API、`ESTAT_APP_ID` 未設定時はスキップ）と `app/supply/meti.py`（経済産業省の統計 Excel、API キー不要）が分担する。

全処理は冪等な UPSERT で動作する。初回投入時は `python jobs/supply/material_stats.py --years 2021-<今年>` で過去年を含めて取得し、定常実行では e-Stat の対象年を前年と今年に絞る。経済産業省サイトの WAF 制限を避けるため、生産動態統計と石油統計の cron 起動時刻は離して設定する。

### 統計の割り当てと不要行の削除

1 つの `(素材, 指標)` には 1 つの統計区分（`seidou`・`sekiyu`・`trade`）だけを割り当て、複数の統計区分に同じ `(素材, 指標)` を載せた場合は `validate_mapping` がエラーにする。素材ごとの統計の選び方は以下のとおりである。

| 対象素材 | 割り当てる統計区分 |
|---|---|
| 原油と石油製品 7 素材（ガソリン・ナフサ・灯油とジェット燃料・軽油・重油・アスファルト・LPG） | 需給一式が揃う資源・エネルギー統計の石油（`sekiyu`）から全指標を取り、生産動態統計と貿易統計（`trade.items`）には載せない（原油と LPG の相手国別輸入内訳のみ `trade.country_items` で `material_trade_country` に取る） |
| 天然ガス | 生産は資源・エネルギー統計の石油（`sekiyu`）、輸入・輸出は普通貿易統計（`trade`）から取る |
| 上記以外の素材 | 生産・出荷・月末在庫は経済産業省生産動態統計（`seidou`）、輸入・輸出は普通貿易統計（`trade`）から取る |

対応表から外した `(素材, 指標, 統計区分)` の `material_monthly` 行、および `trade.items`・`trade.country_items` から外した `(素材, 輸出入)` の `material_trade_country` 行は、ジョブ実行の先頭（`prune_unmapped`）で自動削除する。

### 生産動態統計（`seidou`）

生産・出荷・月末在庫は経済産業省生産動態統計から取り、`source` を `seidou:<4桁報告番号>` として保存する（アルミダイカスト `2560` と鋳物 `2550` のように 1 素材に複数報告番号がある場合は別行で保存し、API 応答時に合算する）。同じ `source` に対して経産省 Excel と e-Stat API の 2 経路から書き込み、保存済みの行より `revision` が下がる上書きは行わない（同じ `revision` なら後から書いた方を採用するため、ジョブ内では e-Stat の後に経産省 Excel を処理する）。

取り込む 5 種類のデータ源と `revision` は以下のとおりである。

| データ源 | `revision` | 公表時期・対象範囲 | 特徴と用途 |
|---|---|---|---|
| 経産省 Excel 速報 `sokuho/h2daaYYYYMMs.xlsx` | `1` | 翌月末（当月分） | 確報より収録品目・指標が少ない |
| 経産省 Excel 確報 `kakuho/YYYY/h2daaYYYYMM_jikei.xlsx` | `2` | 翌々月中旬（その年の 1 月から） | 当年の月次時系列を持つ |
| 経産省 Excel 年間補正号 `kakuho/YYYY/h2daaYYYY_hosei_jikei.xlsx` | `3` | 前年 1〜12 月 | 年間補正後の確定値を持つ |
| 過去年 12 月確報 `kakuho/YYYY12/h2daaYYYY12_jikei.xlsx` | `2` | 前年 12 月〜その年の 12 月 | 統計表一覧に載らず e-Stat 年報にも無い品目（2024 年の銑鉄計など）を `--december YYYY` で手動補完する（2022 年以前は非掲載） |
| e-Stat API（`00550200`）の「YYYY年 時系列表(<報告番号>_…)」 | `3` | 年報のみ（当年分は無し） | 2021 年以降の過去年を一括取得する |

経産省 Excel と e-Stat の読み取り規則は以下のとおりである。

- 経産省の速報・確報・年間補正号は「統計表一覧」ページからリンクを拾い、縦持ちのシート `実数表`（`項目名 == "製品"` の行）を読む。既定の User-Agent は HTTP `403` で弾かれるため、連絡先 URL を含めた `METI_USER_AGENT` を付与する。
- e-Stat の時系列表は年によって分類軸の ID が異なるため（2025 年は品目が `cat01`・月が `time`、2021〜2024 年は品目が `cat02`・月が `cat01` または `time`）、`製品_<4桁番号>_…` 形式のラベルを持つ軸を品目軸、`YYYYMM` または `YYYY年M月` を含む軸を月軸としてメタデータから動的に判定する（年計・年度・四半期の列は除外する）。
- 品目番号は年によって振り直されるため（2023 年の化学繊維、2024 年の AS・ABS 樹脂の統合など）、番号ではなく NFKC 正規化した品名で照合する。年や速報・確報で品目の分割単位が異なる素材は `products` に候補リストを複数並べ、表内に全品名が揃う最初の候補を採用する。どの候補も揃わない表（速報に載らない二輪自動車用タイヤや硫酸アンモニウムなど）ではその素材を書き込まない。

セル値と単位の変換規則は以下のとおりである。秘匿になる年がある品目（ポリスチレン発泡用、合成ゴムの NBR・EPDM、PET 樹脂の容器用とその他、銑鉄の内訳など）は最初から対応表の対象外とし、`note` に理由を記録する。

| セルの内容・単位 | 変換と保存の扱い |
|---|---|
| 加算対象の品目が 1 つでも秘匿（`X`）・不詳（`…`）・`***` の月 | 過小な合計で系列が跳ねるのを防ぐため、その月・指標の行自体を書かない |
| `-`・`(-)`・`*-`・`* -`・`―`・`－`・`‐` | `0` として扱う |
| 空欄（未公表） | 値なしとしてスキップする |
| 単位 `千本` | `1,000` 倍して `本` に揃える（タイヤで `本` と `千本` が混在するため） |
| 単位 `kg` | `0.001` 倍して `t` に揃える（アルミダイカストや飲料缶を貿易統計の単位と揃えるため） |

### 資源・エネルギー統計の石油（`sekiyu`）

原油・石油製品・天然ガスの生産は経済産業省「資源・エネルギー統計（石油）」の Excel から取り、`source` を `sekiyu` として保存する。対象素材と取得指標は以下のとおりであり、在庫はすべて月末在庫、単位は液化石油ガス（LPG）とアスファルトが `t`、それ以外が `kl` である。

| 対象素材 | 取得する指標 |
|---|---|
| 原油 | `production`・`import`・`processing`（原油処理）・`inventory` |
| 石油製品 7 素材（ガソリン・ナフサ・ジェット燃料油 + 灯油・軽油・A重油 + B・C重油・アスファルト・液化石油ガス） | `production`・`inventory`・`import`・`export`・`domestic_sales`（国内向販売） |
| 天然ガス | `production` |

取り込む 3 種類の Excel ファイルと読み取り構造は以下のとおりである。

| ファイル種別 | パスパターン | `revision` | 対象期間と読み取り規則 |
|---|---|---|---|
| 年報 | `sekiyuka/xls/h2dhhpeYYYYk.xlsx` | `3` | その年の 1 月から翌年 3 月までの横持ち表を読む（原油の国別輸入合計・原油処理・原油在庫、石油製品の月別国内向販売・月別輸入・月別輸出。2021 年のみ販売の表題が「国内向月別販売」）。最初の元号行より上の見出しから数値列を特定し、単位表記が `kl、アスファルト以降:t` の表ではアスファルト列から右を `t` とする。製品在庫は別形式のシート「石油製品月別業態別在庫」（月ごとに計・製油所・製造と輸入業者の 3 行）から `計` の行だけを取る。年報には原油・天然ガス・石油製品の月別生産が含まれない |
| 確報 | `sekiyuka/xls/seYYYYMMkakji.xlsx` | `2` | 前年 10 月から 15 か月分の時系列表を読む。一覧ページの最新 1 本に加え、年報が存在する各年の 12 月号（`seYYYY12kakji.xlsx`、一覧には当年分しか出ないが過去年分も同じ命名規則で置かれている）を取得し、年報に無い月別生産を埋める。品目ごとの左右ブロックを見出し行 `年・期・月` で切り出し、見出しの無い左ブロック（原油在庫など）は直上ブロックの品目名を引き継ぐ |
| 速報 | `sekiyuso/result/xls/h2j*j.xlsx` | `1` | 当月 1 か月分のみ読む。石油製品はシート「需給概要」（列が品目・行が指標）、原油は 1 行目に「原油受払」を含むシートから取得する（原油と天然ガスの生産は速報には無い） |

品目名と列見出しは空白を除いた NFKC で照合する。`ジェット燃料油 + 灯油` や `A重油 + B・C重油` のように複数ブロックを合算する素材は、1 つでも値が欠けた月を書き込まない。セル記号の `―` などは生産動態統計と同じく `0` として扱う。

### 経産省 Excel の取得・控え・失敗通知

生産動態統計と石油統計の Excel 取得には共通のクライアント（`MetiClient`）・控え管理（`MetiArchive`）・失敗台帳（`MetiLedger`）を使う。

経済産業省サイト（CloudFront）は同一 IP から連続アクセスすると AWS WAF の bot 確認（HTTP `202` または `x-amzn-waf-action` ヘッダー、本文空）を返すため、リクエストごとに `2` 秒の間隔を空ける。異常応答時の扱いは以下のとおりである。

| 応答の種類 | ジョブの動作 |
|---|---|
| HTTP 通信エラー | `10` 秒・`20` 秒待って最大 `3` 回試行する |
| AWS WAF の bot 確認（一覧ページ・個別 Excel 共通） | `60` 秒待って `1` 回だけ再試行する。再試行でも確認応答が返った場合は長引かせずその回の取得を打ち切り、次回の cron に回す |
| 空の本文、または先頭が `PK` でない不正な `.xlsx` | `fail meti <kind> <name>: …` を出力してその 1 本だけを飛ばし、残りのファイルに進む |

内容が確定して以後変わらないファイル（年報・年間補正号・過去年 12 月確報）には `final = true` を付け、落とした全 Excel を `data/stats/meti/{seidou,sekiyu}/<ファイル名>`（`SHARE_ROOT` 設定時はその配下）に保管する。再取得・控え利用の規則は以下のとおりである。

| 条件 | 動作 |
|---|---|
| `final` かつ DB に取り込み済みで、手元に控えがある | 経産省へはアクセスせずスキップする（石油統計の `final` は対応表の全対象項目がそのファイル名の `origin` で揃っているかで判定し、12 月確報では年報に無い生産項目だけを見るため、対応表に項目を追加した初回は自動で再処理される） |
| `final` で再処理が必要（未取込、項目追加後、または `--reread` 指定）かつ控えがある | 経産省へは行かず、手元の最新版の控えファイルから読み直す |
| DB に取り込み済みだが手元に控えが無い | 控えを残すために一度だけ経産省からダウンロードする |
| `--refetch` 指定 | 正誤訂正を取り込むため、`final` や控えの有無にかかわらず経産省からダウンロードし直す |
| ダウンロードした内容が既存の控えと SHA-256 で同一 | ファイルを書き直さない |
| 同じファイル名で内容が変化した（正誤訂正） | 既存の版を消さず、`<名前>_YYYYMMDD.xlsx` として別ファイルで保存する |
| 控えディレクトリが利用不可（マウント切断や書込不可） | `warn meti archive off` を出して控えなしで取り込みを続行する |

アラート通知と終了コードは以下の規則で制御する。

- 個別ファイルの `fail meti …` 行では Slack 通知（page）を発火させず、ジョブ末尾に必ず `material_stats done written=N failed=K` を 1 行出力し、この集計行の `failed=K`（および非ゼロ終了による `cron-run.sh` の `fail cron`）でのみ通知する。
- 打ち切りまたは失敗が 1 件以上（`K >= 1`）あれば、ジョブは終了コード `1` で終了する。
- cron 実行時は `--ledger /var/log/app/material_stats_ledger.json` を渡し、生産動態・石油統計ごとに「最後に全件取得できた日（`ok`）」を記録する。最後に成功した日（一度も成功していなければ最初の失敗日）から `METI_FAIL_PAGE_DAYS`（既定 `3` 日）以上連続して取得失敗が続いたときは、`material_stats meti <kind> not fetched for N days …` を診断行として出力する（二重通知を避けるためこの行には `failed=` を付けない）。

### 貿易統計（`trade`）

輸入・輸出は e-Stat の普通貿易統計（`00350300`）の「全国分 品別国別表 輸入」と「全国分 品別国別表 輸出」から取得する。統計品目番号（9 桁）に対して対応表の `4`〜`9` 桁コードを前方一致で当て（輸入と輸出で番号体系が異なる品目がある）、全相手国を合算して `material_monthly`（`source = 'trade'`）へ書き込む。あわせて同じ表から相手国ごとの合計を `material_trade_country`（3 桁国コード `137` と国名 `サウジアラビア` のような組）へ別保存する。

対象品目・`revision`・数量換算の規則は以下のとおりである。

| 項目 | 規則 |
|---|---|
| `trade.items` と `trade.country_items` | 国合計と国別の両方を取る素材は `trade.items` に載せる。国合計は石油統計を正とする素材のうち相手国別内訳だけ欲しい素材（原油 `2709`、LPG `271112`・`271113`）は `trade.country_items` に載せ、`material_trade_country` にのみ書き込む |
| `revision` の決定 | 表題の括弧書き（例: `(1-7月：確報、8月：輸入9桁速報)`）から最新年の速報月を抽出し、その月を `1`（速報）、それ以外の月を `2`（確報）とする。`material_trade_country` も同じ `revision` を使い、`revision` が下がる上書きは行わない |
| 未公表月の除外と過去年収録 | e-Stat の品別国別表は 1 つの表に複数年分（2021 年からの 5 年分など）を含み、最新年の未公表月には `0` が入っている。そのため最新年については表題に記された最終公表月より後の月を破棄する |
| 数量列の選択 | `単位1` がある品目は `数量1`、無い品目は `数量2`（化学品の多くは `数量2` の `KG` のみ）を採用する |
| 単位の正規化 | `KG` は `0.001` 倍して `t`、`MT` はそのまま `t`、`KL` は `kl`、`NO` は `本` に揃え、それ以外の単位はそのまま保存する |
| 数量 `0` の月 | DB には行を書かず、API 応答時に公表済み月を `0.0` で補完する（詳細は [サプライタブ](../screen/supply.md) を参照する） |

### DB 書き込みと見掛け消費

`write_rows` と `write_country_rows` は、`WRITE_CHUNK`（`500` 件）ごとに既存行の `revision` を照会した直後に一度 `commit` して読み取りトランザクションを閉じ、そのあと `500` 件ずつの短いトランザクション（`run_sqlite_write` 付き）で UPSERT する。`SELECT` のトランザクションを開いたまま 1 本の `executemany` で書き込むと、別プロセスが書き込みロックを保持していた際にロック昇格待ちとなって `busy_timeout`（`30` 秒）まで `database is locked` が発生するためである。

見掛け消費（`生産 + 輸入 - 輸出 - (当月在庫 - 前月在庫)`）は DB には保存せず、`GET /api/supply/monthly/{material_id}` の応答時に算出する。4 指標と前月在庫がすべて同じ単位で揃う月だけ出力し、`revision` はその月の構成 4 指標の最小値とする。
