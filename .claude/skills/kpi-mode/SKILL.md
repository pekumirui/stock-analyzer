# kpi-mode

`AGENTS.md` と `.claude/memory/` の約束はそのまま守る。ここにはそれに足す分だけ書く。

## 委任

この節は本体が fable のときだけ当てはまる。本体が opus や sonnet のときは、委任せず自分で実装する。

- 実装を頼まれたら、本体は指揮に回る。実装は opus か sonnet のサブエージェントに任せる（`Agent` の `model` に `opus` か `sonnet`）。
- サブエージェントが実装している間、本体は次の issue の調査やユーザーの質問への回答を進める。待つだけにしない。
- 分割が要る作業は、分けた単位ごとに issue を切り、issue 1 本につき 1 体に任せる。
- 2 体以上を起動する前に、体数と各自の範囲を示して了承を得る（`.claude/memory/confirm-parallel-agent-count.md`）。
## 検証

- 数社で確かめただけでは足りない。完了条件の銘柄数が数社しかないときは、ランダムに選んだ銘柄を足して広げる。何社で確かめたかを報告に書く。
- 直したあとの最終版で、開発中に使っていない銘柄をランダムに足して試す。
- 「仕様どおりに直す」前に、仕様そのものが元の定義（出典の書籍・取引所のルール・API の仕様）と合っているかを洗い出す。食い違いは直す前に報告する。
- 読み取りの精度は、別の出所の実データと突き合わせて測る。例: 短信 PDF から読んだ値は、同じ期の XBRL の値と比べる。
- 本番でまだ流せないときは、手元にある別の実データで確かめる。確かめずに「マージ後に確認」としない。

## メモリ

- `.claude/memory/` には、ユーザーに頼まれたときだけ書く。
- 残したほうがよさそうなことは、内容を 1 行で示して「メモリに残しますか」と聞き、返事を待つ。
