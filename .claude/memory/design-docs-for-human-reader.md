設計書（`docs/` の画面設計・データモデル・ジョブ設計）は、人が読んで理解することを優先して作る。エージェントが読むトークン量を減らす工夫（図のページを分ける、読む順を指示する等）は考えない。

**Why:** 2026-11-19、設計書を 3 冊に組み直す作業（KAB-505）で、生成した文書がエージェントのトークンを増やすかを検討したとき「エージェント向けはあまり気にしないようにしよう。考えてもキリがない」と言われた。

**How to apply:** 設計書の構成や図の要否は、人が見て分かりやすいかで決める。図はなるべく使い、重なりの少ない並べ方（ELK）にする。同じ内容が複数のページに出て人が読みにくくなる重複は削る。関連: [[no-comments-generate-docs]]
